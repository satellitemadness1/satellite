## 7. Method calls, indexing, slicing

### Methods are sugar — verified

```
my_list.append(x)   ===   satellite.container.list.append(my_list, x)
```

A prototype implementing exactly this over **one** table landed **16000/16000 concurrent
appends from 8 threads with no lost write**. Receiver methods and module functions share one
table, so methods cost almost nothing once module functions exist.

Three qualifications:

1. The module path is **not derivable** from the type name (`satellite.container.list` has
   two segments, `satellite.time` has one). Use an explicit variant-index → module-path
   table, not string derivation.
2. Constructors (`satellite.time.now`) live in the same table and must carry a
   "does the first parameter bind the receiver" tag, or `my_file.new()` degrades into a
   confusing arity error.
3. `nil` has no module, and there are **two** non-dispatchable states that need different
   messages: an undeclared variable (`Library::get()` returns `nullptr`, `library.cpp:65`)
   and a declared variable holding `std::monostate` (returns a live pointer).

### Mutation goes through `Library::update()`

For a mutating method on a shared variable, `Library::update()` is exactly the right
primitive and already exists. But one invariant must be written above it:

> **No satellite code runs inside `update()`.**

**Verified blocker otherwise.** `std::mutex` is not recursive, so re-entering `update()` on
the same variable **deadlocks** — and receiver syntax makes this reachable from ordinary
user code (`my_list.append(my_list.size())`). Fully reduce arguments to Values *before*
entering `update()`:

```cpp
std::vector<Value> argv = eval_args(call.args, err);   // all eval() happens HERE
if (!err.empty()) return;
lib.update(ns, name, [&](const Value *cur) { return apply_method(cur, argv); });
```

A mutating method also needs a receiver that names a storage slot. Reject
`foo().append(x)` — there is nowhere to write back.

**The invariant is what decides §8.6's key types.** A map's hash and equality run inside this
lock, so they must be native C++ and can never be satellite code. That is not a preference
about extensibility; it is the deadlock above, one level down.

**One read-modify-write, not three.** There are three storage kinds — a field under the
object's `write_lock` (§14), a frame slot with no lock at all because §6 makes it reachable
from one thread, and a global through `update()` — and each mutating method needs all three.
Written out per method they were three chances for the next mutator to differ subtly, which
matters more than it looks: `library_test` drives the Library directly from C++ and never
constructs an evaluator, so the *field* arm has no ThreadSanitizer coverage. They are now one
function taking the transform as a callback, and the transform is pure C++ over the current
value. §7's rule then holds by construction rather than by discipline, because the callback has
no way to call back into the evaluator.

**A selector belongs to one container, but only the receiver knows which container it is.**
`append` is the list's; `set` and `remove` are the map's. Deciding the receiver's container
from the *method name* is a mistake that looks like a shortcut, and it was made here: it
produced an out-of-bounds read, because `l.set(1, 2)` on a `satellite.container.list<T>` took
the map path and indexed the type's one-element generic argument vector at `[1]`. At `-O2`
there was no crash — just a diagnostic about storing a value into a list, generated by matching
against a `Type` whose `std::string` members were constructed from unallocated heap bytes.
AddressSanitizer found it; eleven green test binaries did not.

The rule that replaces it: the receiver's declared type decides, the selector is only *what is
being asked for*, and a selector the receiver's container does not own is refused the same way
any other missing method is. `args[1]` is read under a declared **map** and nowhere else —
which is what the resolver's "0 or 2" guarantee was ever about. It was never a claim about a
list, and the earlier code cited it as though it were.

Whether a call is a container mutation is still settled *before* the receiver is evaluated,
because the mutator path needs storage rather than a value. The test used to be "route to the
mutator unless the declared type
is a spacesuit", which sent every receiver of *unknown* type down the mutator path; a spacesuit
method named `set` then failed with a message about writing back through its receiver whenever
it was called on anything but a declared spacesuit-typed variable. The test is now positive — a
declared **container** routes to the mutator, a declared spacesuit does not, and when nothing
static settles it the receiver is evaluated and the *value* decides. Widening the mutator set
for the map is what made that latent defect reachable.

### Indexing and slicing

```
list_name[i]        single item
list_name[a:b]      half-open range
list_name[:b]  list_name[a:]  list_name[:]
```

- **Half-open (exclusive end).** `len(l[a:b]) == b - a` with no `+1`, and it maps directly
  onto `List(begin+a, begin+b)` — the half-open iterator pair C++ already gives you.
  `l[:k]` and `l[k:]` partition exactly, and an empty slice `l[3:3]` is expressible.
  Rename the docs from `some_number_start:some_number_end` to `start:stop` — "end" reads as
  inclusive and will set the wrong expectation for every reader.
- **Out-of-range index is an error; out-of-range slice clamps.** `hi < lo` yields empty.
- **`l[i] = x` assigns**, added by §19.4. It is a copy-and-replace through the same
  `update_through_slot` protocol `.append()` uses — a spelling, not a mechanism — and it
  takes the index rules in this list unchanged, so a negative index counts from the end and
  **out of range stays an error rather than growing the list**. A map still refuses and still
  says `.set(key, value)`.
- **Negative indices** Python-style.
- **Slicing copies pointers only.** **Verified**: a child's `use_count` goes 2 → 3 with
  pointer identity preserved. Indexing is O(1) with no copy at all. Skip a view/span type —
  it would force every `get_if<List>` site to handle two representations and would pin whole
  backing lists. Do take `if (lo == 0 && hi == len) return base_ptr;`.
- **Postfix `[` must be on the same line as what it subscripts.** With no statement
  terminators, `display(x)` followed by a line starting `[1,2,3]` parses as
  `display(x)[1,2,3]` — the JavaScript ASI bug. One comparison using the token's `line`
  field removes it permanently. Decide now; retrofitting is breaking.
- **String indexing selects satellite characters, not display characters.** **Verified**:
  `encode("hi\home!")` is 4 SatChars decoding to the 16-character `hi/home/madness!`, so
  `s[2:3]` is one unit that displays as `/home/madness`. `SAT_VOID` occupies an index and
  displays as nothing. This is the right rule — it is the only O(1), stable one — but it is
  unique to satellite and must be specified explicitly or it will be reported as a bug forever.
  Note honestly that string slicing *does* copy characters, unlike list slicing.
- **Every bullet above scopes to `list` and `string`.** A **map** subscripts by key, not by
  position: `m[k]` is `.get(k)`, a missing key is an error by the same rule that makes an
  out-of-range index one, and `m[a:b]` is refused because a slice of an unordered lookup means
  nothing. §8.6 carries the key contract. One ordering consequence is worth recording because
  it was a real defect: `eval_index` used to coerce the subscript to a whole number *before*
  consulting the receiver, so `m["bolt"]` failed with "index must be a whole
  satellite.variable.number" no matter what the receiver was. The map is consulted first now,
  and the coercion moved inside the list and string branches where it belongs.

### Generic element types are enforced at runtime

Check at **insertion and literal construction only** — not on every assignment, and skip it
for slices, which preserve element type by construction.

**"Literal construction" had nothing to construct when this was written; §19.2 gives
it the list literal, and the rule held with no new code.** A declaration checks its
initialiser against the declared type, and `matches` recurses into a container's
element type, so `satellite.container.list<satellite.variable.number> l = {1, "no"}`
is refused at the declaration — **verified** — the same way `l.append("no")` is. The
literal itself carries no element type, which is the point: the type belongs to the
binding, and this is the check that makes that safe. One recursive
`bool matches(const TypeNode&, const Value&)`, roughly 15 lines, no change to the Value
variant. Store the declared `TypeNode` alongside each binding, not inside the Value.

The argument is timing, not purity: once user code exists that relies on no checking, adding
checking is a breaking change. R2 is a gift here — every variable has an explicit declared
type, so no inference is needed.

A **map** has two type arguments, and `matches` checks both — `args[0]` against every key and
`args[1]` against every value. Reading `args[1]` is safe only because the resolver now
guarantees a container's argument count before anything runs: a map takes 0 or 2, a list takes
0 or 1, and an unknown container name is rejected outright. That check did not exist before the
map: `satellite.container.list<A, B, C>` and `satellite.container.zzz<T>` both ran clean, and a
one-argument map would have read past the end of the vector. The rule is deliberately "0 or N"
and never "exactly N", because an empty argument list means "matches anything" and a bare
`satellite.container.list` is legal.

Only a container is generic, and that half is checked too: `satellite.variable.number<A, B>`
parsed and resolved clean before, because the parser validates a type's *space* and never its
name. That was pre-existing laxness rather than anything the map introduced, and it is closed
here because a shape check that covers one half of the type space reads as an oversight.
