# POLYMORPH M4 — `polymorph` into a namespace, with no object

Written 2026-09-14. **Status: an idea. The author is still thinking about
it.**

## The author's spelling

```satellite
satellite.polymorph("name")
{
    // code just goes here, under the namespace of the quotes typed in ( and )
}
```

and the thought behind it: defining classes "in the namespace of whatever
thread it is running in."

## What already exists

- **Spaceships are namespaces.** `satellite.include(ship)` makes `ship.cap()`,
  `ship.suit b` and `satellite.library.ship.x` (M25). Anything declared inside
  a spaceship is already reached through a name.
- **A thread has no namespace of its own** today. It runs a capsule and sees
  what that capsule sees.
- **Namespaces were proposed once before**, as
  `satellite.capsule.ns name(args)`, and not decided.

## Why it is its own milestone and not M2

- **It adds to no object**, so it is a different feature.
- **One word would do two jobs.** satellite numbers a word once per number of
  arguments (the `seeded` tier found this in M21), so `polymorph(local_object)`
  and `polymorph("name")` would share one row. They would be told apart only
  by what is inside the brackets.
- **A quoted name is only known when its line runs.** Every other namespace
  in satellite is known before the program starts.

## Decisions for the author

- **D1. Is this a namespace, or a thread's own storage?** They are different:
  a namespace is reached by name from anywhere; a thread's storage is seen
  only by that thread.
- **D2. Its own word, or `polymorph`?** Recommended: its own word, perhaps
  growing from spaceships, which are already namespaces.
- **D3. May the name be a string the program computes** (M5), or only one
  written in the file?
