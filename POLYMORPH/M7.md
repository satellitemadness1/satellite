# POLYMORPH M7 — every language number as its own file

Written 2026-09-14. **Status: an idea, measured. Recommended AGAINST for the
language's own words, and FOR as the layout of M6's user commands.** The
author's decision.

## The author's idea

"We can build satellite to run these numbers, but compile every single number
as a separate C++ executable." The whole language becomes a folder tree, one
file per numbered path:

```
./1/5/1/string.satellite.cxx      satellite.console.display
```

The interpreter reaches a number, finds that file, and runs it with the
arguments. (The author wrote `1 2 1` for display; its number is `1 5 1`.
`1 2` is `satellite.capsule`.)

## Measured 2026-09-14

The same table as M6. For a program that displays 1,000,000 lines:

| design | 1,000,000 displays |
|---|---|
| `satl` today (the whole loop, `for` and string included) | 5.2 s |
| each number a separate executable, `posix_spawn` | 5.5 minutes |
| each number a separate executable, `std::system` | 32 minutes |
| each number a compiled library, loaded once | about today's speed |

**Executables are out of the question for the language's own words:** a loop
QUAD runs millions of times would be 60 to 370 times slower. Libraries are
fast enough.

## What a library per number would still cost

- **Loading.** `words.def` has 342 rows; opening hundreds of `.so` files at
  start-up adds to the 0.9 ms `satl` takes to start today (M17).
- **The static build.** `satl` is one self-contained 3.8 MB file since
  2026-09-06, the author's call: "why build something without everything
  needed to run it included in it?" A folder of libraries is the opposite
  choice, and every copy of satellite would have to carry that folder intact.
- **Values.** Today a built-in handler receives satellite's own `Value`.
  Across a library boundary every value needs a stable C++ shape, and every
  library must be rebuilt if that shape changes.

## Recommendation

- **The language's own words stay compiled into `satl`.**
- **The folder-per-number layout is how M6's user commands are stored**:
  `~/.satl/commands/<root>/<numbers>/command.so`. The author's picture of "the
  number is the name of the file" is kept exactly where it pays.

## Decisions for the author

- **D1. Accept the recommendation**, or build the language itself as a folder
  of libraries despite the start-up and static-build costs above?
- **D2. Where user commands live on disk** if the recommendation holds.

## Done when

This is a decision, not a build. It is done when D1 is answered and M6 records
where commands are stored.
