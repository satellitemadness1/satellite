# POLYMORPH M1 — a spacesuit declared inside a capsule

Written 2026-09-14 at `01d2756`. **Status: proposed. Nothing built.**

The foundation for everything else in this folder: **a class that comes into
being when the line declaring it runs**, and objects made from it later by a
different capsule.

## The author's program

```satellite
satellite.include(satellite)

satellite.spacesuit some_test()
{
    satellite.capsule test()
    {
        satellite.spacesuit test_name()
        {
            satellite.protected
            {
                satellite.capsule test_again()
                {
                    satellite.variable.string something = "void"
                }
            }
        }
    }
}
```

5 left-brackets, all balanced (counted by script on 2026-09-14).

## What runs today

`satl` refuses it before anything runs, once per nested declaration:

```
error S0213: satellite.spacesuit is a declaration and goes at the top of a file, not inside a block
   7 |         satellite.spacesuit test_name()
```

The same S0213 appears for the `satellite.protected` and `satellite.capsule`
inside it. **S0213's rule, "declarations go at the top of a file", is what
this milestone changes.**

A capsule written directly inside a spacesuit with no section around it —
`satellite.capsule test()` above — is already accepted.

## What C++ and Python do, measured 2026-09-14

- **C++ builds every class before the program starts.** A class written
  inside a function could be instantiated by another function even when the
  defining function NEVER ran (`the_test_no_call.cpp`). So C++ does not do
  this.
- **Python makes the class when its line runs.** In the author's
  `py_poly.py`, the class did not exist until `create_class()` ran, and it
  vanished again unless it was stored somewhere (a `NameError` from another
  function). **Every run made a separate class with the same name**, and an
  object of the first was not an object of the second.

## What building it means

1. **Parser.** A `satellite.spacesuit` inside a capsule body parses as a
   statement instead of S0213.
2. **Resolve.** The names inside it are resolved before the program runs, as
   they are today, so its capsules still get slot numbers. What waits for
   run time is only the MOMENT the spacesuit becomes usable.
3. **Run.** Reaching the line registers the spacesuit. Declaring an object of
   it before that line has run is an error that names the line to reach first.
4. **`satellite.access`** (ACCESS_PLAN A5) shows an object of it like any
   other.

## Decisions for the author

- **D1. Where does `test_name` exist once `test()` has run?** Python's answer
  is "only inside the function unless you store it", and its `NameError` is
  the trap.
  - (a) inside `test()` only;
  - (b) on the object `test()` ran on, reached as `object.test_name`;
  - (c) everywhere in the program from then on.

  **Recommended: (b).** It keeps two objects from fighting over one name, and
  it is what M2's `polymorph` needs anyway.
- **D2. What happens when `test()` runs a second time?** Python silently
  makes a second class with the same name.
  - (a) replace: new objects use the new version and old objects keep theirs;
  - (b) refuse, with the line of the first declaration;
  - (c) keep both as numbered versions that `access` can tell apart.

  **Recommended: (a).**
- **D3. The number.** None is needed: `satellite.spacesuit` is already `1 10`.

## Done when

The author's program above runs; a second capsule makes two `test_name`
objects after `test()` has run; making one BEFORE `test()` runs gives an error
naming the line; D2's rule holds when `test()` runs twice; and `make test` is
