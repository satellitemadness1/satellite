# M4 — the arena AST and the parser

**Landed 2026-08-30**, which also corrected DESIGN §6 twice and added §6.6 —
see §4. Written against [PLAN.md](../PLAN.md) §8's M4 entry,
[PLAN.md](../PLAN.md) §2.2's arena and [DESIGN.md](../DESIGN.md) §6, with the
prototype in `prototype/M4/` **read as a draft and not as a source** — §3 says
what it got wrong, and the headline is the same class of error M3 found in its
own prototype one milestone earlier.

**Verdict: done.** Every clause of M4's done-when has code behind it,
`make test` passes all three suites under clang and g++, and
`satl --unparse` round-trips **the four programs LAYOUT.md calls the acceptance
programs**. §6 lists what is left open, including the two files in `example/`
that do *not* parse and why that is a statement about them.

## 1. What the milestone was

- **`uint32_t` node indices into a contiguous arena, no `shared_ptr` anywhere in
  the tree** — PLAN §2.2, which is a measurement and not a preference.
- **`satl --unparse file.satl` round-trips**, *"which is how we know the parser
  is right before anything can run"*.
- **The first caller of M2's name allocator.** `words::Words::intern` was built,
  tested and called by nothing until here; PLAN §8.1 says the parser is what
  meets a name for the first time.
- **All eleven of DESIGN §6.1's segment-1 words** — `variable`, `container`,
  `library`, `statement`, `include`, `capsule`, `spacesuit`, `return`,
  `returns`, `protected`, `public`. PLAN records that naming them was *a fix
  rather than an addition*: eight had appeared in the backlog as work with no
  milestone when a milestone owned them and did not say so.
- **`satellite.returns(TYPE)`**, which DESIGN §13 records as decided and §6's
  grammar already has — *"not new work; work that had no name in this list."*

## 3. The prototype, and the one thing it got wrong that mattered most

`prototype/M4/` is 2,286 lines and was read rather than run. Four findings, and
the first is the milestone:

**1. It compared strings to decide everything.** `at_language_path("capsule")`
is `is_word(0, "satellite") && is_punct(1, ".") && is_word(2, sub)`, where
`is_word` is `t.text == text` — so every statement in every program costs a
string compare against `"satellite"`, and the §6.1 dispatch costs one more per
candidate word. **This is PLAN §1.1's finding, reproduced.** That section is the
one the whole plan hangs off: the first satellite *"already built the number
table, and the evaluator never read it"*, then flattened every member chain into
a `vector<string>`, joined it, and ran seven arms of `full == "satellite…"`.
DESIGN §6.1 states the correction in one clause — dispatch on segment 1, *"which
under §4 is no longer a string compare but a child index"* — and M3 built the
half that makes it free, `Token::spelling`. The prototype has that field
available and never reads it.

**2. It copies the token stream.** `Parser(const std::vector<Token> &toks, ...)`
stores `std::vector<Token> toks_` **by value**, and a `Token` owns a
`std::string` and a `SatString`. Parsing therefore duplicates every token in the
file before reading one.

**3. Its node is a `std::variant` of twenty-six alternatives**, several holding
`std::vector` and `std::string`, inside a `std::vector<AstNode>`. That is the
obvious C++ answer and it is the exact shape PLAN §2.2 exists to refuse: every
node is as wide as the widest alternative, which is what made the first
satellite's node 96 bytes. It also cannot be trivially copyable, so M4.5's
`.satc` writer would need a visitor per kind.

**4. It numbers a user capsule under `satellite.capsule` `1 2`.**
WORD_NUMBERS §3's worked example is `satellite.library.main` — a capsule's number
lives under **`library`**, which is the node that owns it, and `satellite.capsule`
is the keyword that declares one. It also invents `DurationLit`, `ListLit` and
`NamedArg`, none of which DESIGN §6 can produce, and accepts `f(x = 1)` as a
named argument that is in no grammar.

**What was taken from it: nothing but the shape of the file split**, and even
that came out differently — six files here against five, cut at DESIGN §6's own
production boundaries.

## 4. Three things the specification did not settle, decided here

**A milestone that finds a gap in DESIGN has two honest moves — leave it and say
so, or decide it and say who decided.** All three below are the second, and
**all three are now in DESIGN itself**, written there the same day: a decision
that lives only in a milestone review is a decision the next reader of the
specification will make again, differently.

**1. There was no precedence table in DESIGN.** §6 wrote the whole expression
rule as `expression := ... precedence climbing ...` and stopped. The table chosen
is C's, minus every operator satellite does not have — `* / %` above `+ -` above
`< > <= >=` above `== !=`, all left-associative — and it is now **DESIGN §6.6**,
marked as decided at M4 and listed under §13's *Decided*. In the code it lives in
[ast.hpp](../src/abstract_syntax_tree/ast.hpp) rather than in the parser
**because it has two readers**: the printer reads it to decide whether a bracket
the program wrote has to come back. Unary `-` is not a choice — DESIGN §5.6
refuses to fold a sign into a Number precisely so that it is an expression rule.

**`&` and `!` did not get decided, and DESIGN §13 now says so as one question
rather than two.** `&` gets precedence 0, so it ends an expression and is
reported. `!` is parsed as a unary and given no meaning, which is the smallest
guess available and is still a guess. What the write-up found is that the real
gap is larger than either: **satellite has `==` and `!=` and no `and`, no `or`
and no `not`**, so a program that wants to test two conditions cannot, and one
answer settles all four.

**2. A newline inside brackets.** §6 says statements are newline-terminated and
says nothing about an argument list that spans lines. Newlines are skipped while
a bracket is open and nowhere else. This **cannot** weaken §6.2, because the
postfix loop runs at bracket depth 0 where nothing is skipped —
`tests/parser_test/expressions.cpp` checks both halves.

**3. `suit_section` cites the wrong production, and the grammar as written
cannot parse its own example.** DESIGN §6 has

    suit_section := "satellite" "." ( "protected" | "public" ) block
    block        := "{" { statement } "}"

so a section's body held *statements* — while every section in
`example/class_test.satl` holds capsule declarations, and a declaration is not a
statement. A section holds what a suit block holds, so the parser reads them with
one function. **DESIGN §6 was corrected on 2026-08-30**: `suit_section` cites
`suit_block`, and the old line stays visible beside it, which is how M3 corrected
§5.6 and for the same reason.

## 5. What being M2's first caller found

**PLAN asks for a consumer in the milestone that writes a thing** — because the
first satellite shipped three commits where its registry had none and four
defects accumulated behind a guarantee nothing checked. M2 could not keep that
rule for `words::Words`: PLAN M4 is named in `words_runtime.hpp` as the caller
that would arrive. It arrived, and it found two things.

**1. `intern()` is not the function PLAN M4 asks for.** `Words::intern` is
find-then-define, so `intern(LIBRARY, "main")` hands back **1 14 1** — the
language's own node — for a user capsule called `main`. PLAN M4's sentence is
that a name the language already owns is *"refused rather than renumbered"*, and
`intern()` does neither: it silently answers with somebody else's number. So
`define_name()` calls `find()` first and reports. `Words::intern`'s own comment
calls itself *"what a parser wants"*; what a parser wants turns out to be
`find()` and `define()`, which that comment gives to a diagnostic.

**2. A user's spacesuit cannot be a parent, and no compiler can see it.**
`words::Words` seeds one counter per node of the **frozen** table
(`uint32_t next_free_[kNodeCount + 1]`) and walks the frozen child lists
(`std::array<PathId, kNodeCount + 1>`). A user's `PathId` starts *above*
`kNodeCount`, so handing one to `find()` or `define()` indexes past the end of
both. **A capsule declared inside a spacesuit has exactly such a parent.** So a
method gets no number at M4, its node carries `kNoPath`, and
`tests/parser_test/declarations.cpp` asserts that rather than leaving it to be
discovered. Fixing it is a growable counter vector and a user-side child list —
small, and M22's rather than this milestone's, because M22 is where a spacesuit's
members have to resolve.

**What did work, first time and exactly as written:** a user capsule takes
**1 14 3**, because `main` is 1 14 1 and `system` is 1 14 2. That is PLAN §8.1's
worked example, checked.

## 6. What is left open

1. **The two `example/` programs that do not parse, and both are the files.**
   `class_test.satl` line 4 is `satellite.spacesuit my_superclass():` — DESIGN §6
   writes the superclass as `[ "(" IDENT ")" ]`, so an empty pair is not the form
   for *no superclass* (leaving them out is) and the colon is in no rule at all.
   **With that one line corrected the whole file parses and round-trips**,
   verified 2026-08-30, so it is one line and not a shape.
   `gui_example.satl` line 7 is `satellite.console.new("my window title", 800x600)`
   — which the lexer reads, correctly, as `Number(800)` then `Bits(x600)`, because
   DESIGN §8.5 gives `x` literals to hex and no document here has a dimensions
   literal. **Neither is the parser's to fix**: either the files are corrected or
   DESIGN gains the forms, and that is the author's call. LAYOUT.md lists four
   acceptance programs and these are not among them.
2. **Of §4's three, two are now written into DESIGN and one is open there.**
   `suit_section` cites `suit_block` (§6), the precedence table is §6.6 and is
   listed under §13's *Decided*, and **what `&`, `!` and the missing `and`/`or`/
   `not` mean is now §13's first open item** — one question, not three. The
   parser gives `&` no precedence and reports it, and parses `!` as a unary with
   no meaning; both follow DESIGN the day DESIGN speaks.
3. **`satl --unparse` exits `EXIT_USAGE` on a malformed program**, which is M3's
   open item 2 with a second arm behind it now. Non-zero is right; `EXIT_USAGE`'s
   own definition is *"the command line did not name something satl can do"* and
   a bad program is not a bad command line. **M5 owns it**, and now has two
   callers wanting the missing code rather than one.
4. **CLOSED 2026-08-30 BY M5, and the type is GONE rather than wrapped.**
   `Parse::errors` is a `std::vector<errors::Diagnostic>` -- code, span, notes,
   frames -- and a second error type would have been a second place a message
   can be composed. **And this item's second sentence is what made it cheap**:
   every error already carried a token index into the stream the tree kept, so
   the whole conversion is `span_of(token)` in one function. That is the most
   useful thing a milestone can do for its successor without building any of it.
5. **STILL OPEN, AND M5 ANSWERED THE PREDICTION RATHER THAN THE ITEM.** This
   said "M5 will want to underline a whole expression"; **M5 did not**. The
   anchor token is the token the message is about at all 24 sites -- `a + `
   points at the `+`, which is the choice `ast.hpp` made for exactly this reason
   -- so nothing in the reporter asked for an extent. Left open with the answer
   attached: whoever wants it should bring a message that reads worse without
   it. *(Original: "M5 will want to underline a whole expression, and a
   first-to-last token pair would give it. Not stored, because the reporter that
   would use it does not exist and its shape would be guessed; the extent is
   recoverable by walking a node's children. Same call M3 made.")*
6. **`unparse.cpp` is 341 lines and is now the largest file in the tree**, past
   `lexer.cpp`'s 304, which M3 recorded as *the number to watch* after M2 said the
   same of `authority.cpp` at 299. The seam is real and is named here rather than
   taken: the printer does two things — emits **lines** with an indent
   (declarations and statements) and returns **strings** (expressions and types)
   — and the second half is what M5 will call to quote an expression. It is not
   split now for the reason M3 gave: the class is one object in an anonymous
   namespace, splitting it needs a private header, and 41 lines is an arithmetic
   rather than a subject. `parser_declarations.cpp` at 309 is the same answer with
   a smaller number.
7. **`words::intern()`'s 254-row scan is now measured and still unchanged**, which
   is M3's open item 5 answered but not acted on. §7 has the number: **18.4 ms of
   a 32.1 ms lex**, 57%, against 6.1 ms to parse the same stream. Replacing it
   with a hash *"changes one function and no caller"*, and the milestone to do it
   is whichever first has a reason to care about a large file — **M4.5 reads one
   by definition**.
8. **HALF CLOSED 2026-08-30 BY M5.** Both numbers are still `parser.cpp`'s and
   neither is in a permanent document -- M5 did not move them, because how much
   a parser says before it is lost is the parser's decision and not the
   reporter's. What changed is that **reaching the cap is said out loud**:
   `S0208`, a note rather than an error, pushed after the run so `ok()` still
   asks whether anything is an error rather than counting. Before it, the
   twenty-first problem was invisible and the file looked understood.

## 7. What was measured

**Startup, 2026-08-30, load 0.8–1.0**, best of five runs of 200 invocations,
`STATIC=full` on both sides — the floor M1 established and M3 re-took:

| | |
|---|---:|
| bare `int main(){return 0;}`, static | 0.614 ms |
| `satl` (opening information) | 0.655 ms |
| `satl --version` | 0.655 ms |
| `satl --tokens example/hello_world.satl` | 0.725 ms |
| `satl --unparse example/hello_world.satl` | 0.722 ms |
| `satl --unparse example/class_test.satl` | 0.858 ms |

**Parsing hello world costs nothing measurable over lexing it** — the two arms
are 3 µs apart and the noise is larger than that. satl's own share of starting up
has gone from M3's 0.012 ms to about **0.041 ms**, and the honest attribution is
the binary: `STATIC=full` grew from 1,111,528 to **1,200,312** bytes, 88,784 for
the milestone, which is 2.7× what M3 cost and is eight new translation units.
Nothing here reaches `<iostream>`; the test suite is where `<fstream>` lives.

**And the measurement M3 asked for, which needed a whole program to take.**
A generated source of 11,001 lines / 321,259 bytes / **81,008 tokens**,
clang -O3, best of 20:

| | |
|---|---:|
| lex | 32.088 ms |
| **lex with `words::intern`'s 254-row scan removed** | **13.717 ms** |
| parse the same stream (37,004 nodes) | 6.131 ms |
| print the tree back | 1.767 ms |

**The interner is 18.4 ms — 57% of lexing, and three times what parsing costs.**
The scan was free at the 255 tokens of the largest program in `example/` and is
the dominant cost of reading a real one, which is the shape M3 predicted and
could not yet see. The second row is an experiment, not an estimate: the call was
removed and the lex re-timed. `words_spellings.hpp` carries the table beside the
function.

**The arena, against what PLAN §2.2 measures it against**: a `Node` is
**24 bytes**, trivially copyable, and both are `static_assert`s rather than
claims. `example/hello_world.satl` is 17 nodes; `class_test.satl` is 78; the
11,001-line source is 37,004, which is **888 KB of tree** where the first
satellite's 96-byte `shared_ptr` node would have been 3.5 MB in 37,004 separate
allocations.

## 8. What the test proves, and the mutations that prove the test

`tests/parser_test/` is six files and **127 check sites in five sections**. It
links five module sources, which is more than any test before it — a property of
the subject: a parser runs over a token stream, the lexer needs its alphabet, and
the tree has a printer.

- **`arena.cpp`** — what the `static_assert`s in `ast.hpp` cannot reach: that
  every node's token index is inside the arena, that node 0 and list handle 0 are
  real sentinels, and that **the empty list is always handle 0** — two encodings
  of empty is how a comparison of two equal trees starts answering *different*.
- **`expressions.cpp`** — §6.2's loop, with `foo().bar()` named as the defect it
  exists for; precedence, including **`a - (b - c)` keeping its brackets**, which
  is the one case that silently changes an answer; and the same-line rule, checked
  as `x` then `(f(y))` coming out as two statements and not as `x(f(y))`.
- **`statements.cpp`** — **§6.1's collision, and it is the milestone's most
  important check**: `satellite.control.return my_time` must declare nothing while
  `satellite.variable.time my_time` declares a variable. Same four tokens. A test
  that checked only the second would pass against a parser with the defect.
- **`declarations.cpp`** — the name allocator: **1 14 3**, the refusal of a
  language-owned name, the reserved `satellite.main` looked up rather than
  defined, and §5's limit asserted rather than described.
- **`roundtrip.cpp`** — the done-when. Four programs parsed, printed, parsed and
  printed again, identical; hello world checked **character for character**
  against DESIGN §3 less the comments; and the two files that do not parse checked
  as not parsing, with the reason pinned to a line number. **It fails loudly
  rather than skipping** when it cannot read a file — words_test's rule for
  WORD_NUMBERS.md, in a third place.

**Verified by mutation on 2026-08-30**, which is the standard M2 set:

| mutation | caught by |
|---|---|
| §6.1 dispatch made structural — *a dotted path then a bare word is a declaration* | **3 checks**, and see below |
| a `Call` ends the postfix chain instead of continuing it | 3 checks, all three naming §6.2 |
| the postfix loop allowed to cross a newline to find an opener | 2 checks — precisely the same-line pair |
| `expression(precedence)` instead of `precedence + 1` — right-associative | 2 checks — `a - b - c` and the mixed chain |
| `define_name` reduced to `words_.intern()` | 2 checks — `main` accepted, and a duplicate accepted |

**The first mutation had to be made twice, and the reason is a finding.** Written
as the structural rule alone it changed nothing: `type()` refuses a path whose
segment 1 is not `variable` or `container`, so the bad declaration failed at its
type instead of being built. **§6.1's rule is enforced in two places**, and only
disabling both reproduces the defect. That is defence worth knowing about, and it
was invisible until a mutation went looking for it.
