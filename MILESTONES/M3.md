## 1. What the milestone was

- **`src/lexical_analyzer/`** — tokens, spans, and the five rules DESIGN §5 says
  were *"inherited as rules, not rediscovered"*, each of which fixed a verified
  defect in the first satellite.
- **Known words carry their node identity out of the lexer; user-owned bare
  words carry their text.** §3 is about what "node identity" turned out to mean.
- **The reservation rule** (DESIGN §2), or rather the lexer's half of it: one
  integer compare for *"is this bare word `satellite`"*.
- **`satellite.variable.binary` `1 6 5` and `.hex` `1 6 11`** — DESIGN §8.5
  makes them real types with literals, and a literal is lexed, so the lexer
  decides them whether or not a milestone says so. **The width is part of the
  value**: `x0009` is not `x9`.
- **The lexer's half of the spelling table**, which is what M2's nine aliases
  were owed.
- **`satl --tokens <file>`** — the consumer, in the milestone that wrote it.

**It also had a dependency no milestone had scheduled**, and §4 is that.

## 3. What "node identity" turned out to mean, and the draft that got it wrong

PLAN M3 says *"known words carry their node identity out of the lexer"*, and the
prototype read that as a `PathId`. **It compiles**, because
`words_spellings.hpp` says `using SpellingId = PathId` — the two are the same 32
bits — and it is wrong, because the two are not the same fact:

| | answers | comes from |
|---|---|---|
| `SpellingId` | *is this bare word one the language uses, and which one* | `intern()`, at lex time |
| `PathId` | *which node is this* | a **walk**, once a whole path has been read — DESIGN §4.5 |

**DESIGN §5.6 has been corrected**, because the sentence is the defect's cause
and leaving it would have cost the next reader the same day: it now says a known
word carries its **spelling**, names §4.4's interner id, and carries the account.
§4.4 and §4.5 each gained a line pointing at the other, and PLAN §8's M3 sentence
was reworded to match. PLAN_ONE.md's copy is annotated rather than edited — a
superseded draft that gets quietly corrected stops being a record of what was
thought at the time.

DESIGN §4.4 is the sentence that always settled it: the interner is
**"deduplication, not identity"**, because `list` under `container` and `list` under `directory`
are *"two nodes sharing one piece of text"*. A lexer sees `display` and cannot
know whether it is `satellite.console.display` or a user's variable, because the
answer is a property of the path being built around it — and the parser is what
builds one. So the token carries the spelling, and M4's walk turns a run of them
into a path.

**The prototype's `lookup_word` also returned `kAliases[i].of` — a `NodeId` —
as a `PathId`,** and scanned the dotted aliases it could never match.

**What catches this class of error is a word the language spells twice**, which
is why `console` is `spellings.cpp`'s fixture: `satellite.console` and
`satellite.window.console` are two nodes with two numbers, and one spelling id
must answer for both while being neither.

## 4. The dependency no milestone had scheduled

DESIGN §5 opens: *"The lexer walks `SatString`, so the code table in
`satellite_string.hpp` **is** the language's alphabet."* PLAN §6.1 surveys that
module and **PLAN M7 owns it** — four milestones later. A lexer cannot wait for
an alphabet, so something had to give, and the choice was made explicitly rather
than by whoever noticed last:

- **The character half came forward to M3.** The table, both encoders, and a
  `decode()` for everything that is a character.
- **The live half did not.** Codes 95–100 resolve at decode time to the user's
  home directory, their name, the thread count, two memory figures and the
  working directory — readers in `system_facts/` that **M14** ports. `decode()`
  emits `<threads>` and its five siblings until then.

**The stub is safe rather than merely cheap, and the reason is checkable**:
`encode_raw` maps every source byte to a letter, a digit, a punctuation code or
the raw area, so **no code in 95..100 can occur in a program's text at all**.
They are reachable only through `encode()`'s backslash names inside a string
literal body — a value, which does not exist until M7 builds one. Finishing it
is replacing six lines with six calls.

**One thing the port gained rather than carried.** DESIGN §5.4 requires escape
names to be matched longest-first so a short name cannot shadow a longer one,
and v1 held that **by hand-ordering the table**: `"t"` sits four rows below
`"threads"` and nothing but care kept it there. An alphabetised edit would have
made `\threads` lex as a tab followed by `hreads` — silently, in every string in
every program. It is now a `static_assert` over the table, which is
FORMAT/CXX.md §1's third rule applied to a fact that had been left in prose.

## 5. What the test proves

`tests/lexer_test/` is five files and **105 check sites** (more assertions than that actually run — several sit inside loops). Unlike `words_test` it
**links objects** — the registry is constexpr data, a lexer is a function that
has to run — and 065-tests.mk names exactly two: the lexer and its alphabet.

- **`characters.cpp`** — the extent rules. §5.1's own worked example is checked
  as a **count**, because that is the form DESIGN states it in: *6 tokens with
  the rule and 16 without*. Its `shape()` helper deliberately does **not** print
  spelling ids, so a word gaining a sibling in `words.def` cannot fail a test
  about underscores.
- **`literals.cpp`** — numbers, the five escapes in both directions, and §8.5.
  `x0009` against `x9` is checked directly. So is the longest-first rule, by
  asserting `"\threads"` is **one** code and not a tab plus `hreads`.
- **`spellings.cpp`** — §3's distinction, the six spellings of `arguments`, and
  the assertion that `range` resolves to nothing, which is how the dot filter is
  known to have held.
- **`spans.cpp`** — **every span sliced back out of the source and compared**,
  which is the only way to check the one field of a Token that cannot be
  verified by reading the program. Also `example/hello_world.satl` end to end,
  and it **fails loudly rather than skipping** when it cannot read that file —
  `words_test` records the same rule for `WORD_NUMBERS.md`.

**Verified by mutation on 2026-08-29**, which is the standard M2 set:

| mutation | caught by |
|---|---|
| underscore removed from `word_start`/`word_cont` | 6 checks, including §5.1's 6-vs-16 count |
| the escape skip allowed to swallow a newline | 2 checks — and the failure it prevents is a **line counter** one, not a string one: `line` stays one short for the rest of the file and every error span after it points a line too high |
| `intern_word` reduced to `words::intern` | 6 checks — all five `arg*` spellings and `hexadecimal` |

## 6. Five things left open

1. **`lexer.cpp` is 304 lines and is now the largest file under `src/`.** PLAN §3
   is a target rather than a ceiling and FORMAT/CXX.md §1 says going over is not
   wrong — but M2's review named `authority.cpp` at 299 as *"the number to
   watch"*, and this passes it. The seam if one is wanted is real: `lex()` is a
   dispatch over five token shapes, and the string literal arm is the one with
   its own control flow. **Not split now**, because a seam chosen to satisfy an
   arithmetic is what §3 warns against.
2. **CLOSED 2026-08-30 BY M5, after three milestones and three arms.**
   `EXIT_MALFORMED = 1` is in `programs/opening.hpp`, `--tokens`, `--unparse`,
   `--satc` and the new `--check` all return it, and the enum carries why it is
   1 rather than 4 -- it is what every compiler returns for a source it could
   not compile, and this is the one place that enum defers to convention rather
   than to its own order. **Three arms wanted it and none of them invented it**,
   which is the enum working: it exists so that two arms cannot disagree about
   what a failure is worth, and an arm that guessed would have been that
   disagreement. *(Original text below.)*
   **`satl --tokens` exits `EXIT_USAGE` on a malformed program, and that is the
   wrong code.** Non-zero is right — a script has to be able to tell — but
   `EXIT_USAGE`'s own definition in `opening.hpp` is *"the command line did not
   name something satl can do"*, and a bad program is not a bad command line.
   **What is missing is a status for "the program you gave me is malformed"**,
   and adding one is a change to a contract that exists so *"two arms cannot
   disagree about what a given failure is worth"* — so it belongs to **M5**, with
   every code it needs in view, rather than to this arm guessing. *(The related
   defect was found the same way and IS fixed: the dump went to **stderr** on a
   malformed file, so `satl --tokens bad.satl > out` wrote an empty file. The
   answer goes to stdout now, error token and all.)*
3. **CLOSED 2026-08-30 BY M5, exactly as this item predicted.** A `Token` now
   carries an `errors::Code`, `text` goes back to meaning the bytes as written
   the way it does for every other kind, and `lexer.cpp`'s `diagnostics_of()`
   turns the Error token into the block a person sees -- with the caret under
   the opening quote and a **note** where the line ran out, both spans out of
   that one token because the string arm had already set both ends.
   `describe()` prints `Error(S0101)`, so a stopped stream can be looked up from
   the `--tokens` dump it appears in. *(Original: "`TokenKind::Error` carries a
   reason and no code. M5 builds the reporter with codes, spans and 'did you
   mean'; the one error this lexer can emit says `unterminated string literal`
   as a bare string. That is the right shape for M3 and the wrong shape for M5,
   and M5 is where it changes.")*
4. **CLOSED 2026-08-30 BY M4, WITH AN ANSWER AND A SECOND REASON.** `split_punct`
   still has no caller and now **says so beside itself**, which is what this item
   asked for. M4 reads every generic argument list the grammar has and closes
   them all with a plain `>`: §5.5's argument holds, because nothing that can
   follow a complete type begins with `=`. **And M4 found a reason not to call it
   even if that changes** — it *inserts* into the token vector, and the parser
   stores token indices in every node it has already built, so a split partway
   through a parse renumbers the anchor of the whole tree behind it, silently.
   The fix would belong at lex time. *(Original text: "`split_punct` has no
   caller. It is tested and exists for M4's `parse_type`, which is the milestone
   that will want a `>` out of a `>=`. DESIGN §5.5 notes no such collision is
   actually reachable in §6's grammar — so this may stay uncalled, and if M4
   confirms that, the honest move is to say so beside it rather than to keep it
   looking pending.")*
5. **MEASURED 2026-08-30 BY M4, AND THE ANSWER IS THAT IT MATTERS.** The number
   this item asked for -- throughput on a large generated source -- is
   **18.4 ms of a 32.1 ms lex, 57%**, on a 321 KB source of 81,008 tokens; the
   parse over the same stream costs 6.1 ms, so the scan is nearly three times
   what parsing is. `words_spellings.hpp` carries the table beside the function
   and MILESTONES/M4.md §7 carries how it was taken. **Still not changed**, and
   that is now a scheduling decision with a number behind it rather than an
   absence of one. *(Original text follows.)*
   **`words::intern()` is still a 254-row linear scan per word, and §7's
   measurement is not yet a reason to change it.** That function's own comment
   predicted this milestone — *"there is nothing to measure until M3 runs it
   over a real source"* — and §7 is that measurement: 0.22 ms to lex the largest
   program in the tree, 255 tokens. **What it does not tell us is the shape.**
   The biggest file here is a quarter of a kilobyte of tokens, and a scan that
   is free at 255 is not free at 250,000; the comment's own claim is that
   replacing it with a hash *"changes one function and no caller"*, which this
   milestone is the first to be in a position to test and did not. The number to
   take is lexing throughput on a large generated source, and the milestone to
   care is whichever one first reads a real program.

## 7. Two things measured, and one thing not done

**Startup, 2026-08-29, load 0.34**, best of five runs of 200 invocations, both
sides linked the same way:

| | |
|---|---:|
| bare `int main(){return 0;}`, static | 0.606 ms |
| `satl` (opening information) | 0.618 ms |
| `satl --version` | 0.624 ms |
| `satl --words` (271 lines) | 0.766 ms |
| `satl --tokens example/hello_world.satl` | 0.678 ms |
| `satl --tokens example/class_test.satl` | 0.840 ms |

**satl's own share of starting up is about 0.012 ms, which reproduces M1's
0.01 ms** rather than merely resembling it — three milestones and three objects
later. Lexing a 273-byte program costs about 0.06 ms on top of that; the largest
example in the tree, at 255 tokens, costs 0.22 ms.

**The first attempt at this measurement was wrong and is worth recording.** satl
ships static, and a static binary skips the dynamic loader — so timing it
against a *dynamic* `int main(){return 0;}` made satl come out 0.9 ms **faster
than an empty program**. A linking difference wearing a performance result's
clothes, and the giveaway was a number that could not be true.

**And the milestone nearly cost 1.4 MB.** `read_file` was written with
`std::ifstream` and `std::ostringstream`, which is the obvious way and drags in
the iostreams machinery — locales, facets, the static init behind them — that
this binary otherwise never touches, because it prints with `fputs` and
`fprintf`:

| | with `<fstream>` | with `fread` |
|---|---:|---:|
| `STATIC=full` satl | 2,596,120 | **1,111,528** |
| `STATIC=1` satl | 1,657,808 | **367,568** |

For scale: **the whole of M3 cost 32,696 bytes** (STATIC=full went from
1,078,832 to 1,111,528). One convenient header would have cost forty-five times
the milestone, on every installed copy, to read a file into a string.

**And a second measurement pointed the other way**, which is why both are kept.
The first `fread` version grew the string with an append loop and was **2.5x
slower** than the `ifstream` idiom it had just beaten on size — 5,929 us against
2,325 on an 8.1 MB file. But sizing the buffer up front with `fseek`/`ftell`
gets 2,329, so the win was never `fstream`'s: it was **sizing the buffer once**.
Had only the first two rows been measured the conclusion would have been "fread
is faster", which is true of the idiom and false of the library.
`programs/source_file.cpp` carries the full table.
048-static.mk now carries the figure beside the decision that makes it matter.

**`satl` and `satl.haswell` produce byte-identical `--tokens` output** over
`example/class_test.satl`, the largest of the six at 255 tokens.

**What was not done: the prototype was read as a draft and not audited.**
`prototype/M3/test.cpp` was never run. What §3 records are defects found by
reading its lexer against DESIGN §4.4 and §4.5 — not a full review of it.
