## 1. What the milestone was

**Three things, and the smallest is the one the plan said mattered.**

1. **The answer.** *Is "nothing" a state every type has, or a value only a
   `variant` can hold?* Two later milestones ask the same question in the same
   words — `satellite.console.typed()` *a line, or nothing* (M14);
   `read_line` *one line, or nothing at end* (M19) — and PLAN §8 required it
   answered once, in front of both. It is answered: **a state every type
   has.** DESIGN §8.7 is the language's statement; §2.1 below is the argument.
2. **The representation.** DESIGN §8's table carried a dash for the variant
   until this milestone. The row now reads **the `Value` itself** — M9's
   discriminated union, no arm of its own, no handle, no bytes, §8.2's
   forty-byte `static_assert` untouched. A `variant`-declared slot holds
   whatever `Value` it holds; the declared type does the one thing declared
   types do in this language — it numbers the selectors.
3. **The vocabulary.** Four rows behind `handlers[path_id]`, the numbering's
   first appended children: `holding` `1 6 14 1`, `holds(x)` `1 6 14 2`,
   `held` `1 6 14 3`, `clear` `1 6 14 4`.

## 2. What was decided on the way

### 2.1 The blocker: nothing is a state every type has

**The code had already taken the decision three times, and the milestone's job
was to notice.** The argument, in the order it convinced:

1. **The state was already universal in the built machine.** `Nothing` is arm
   zero of every `Value`, and `op_store` writes it into every
   declared-without-initialiser slot of every declared type, on every loop
   iteration, deliberately (`operations_control.cpp`'s own comment defends
   exactly that). Under reading two, the evaluator was already committing a
   type error on every uninitialised declaration in the language.
2. **S0714's sentence was already reading one, verbatim** — *"a declared
   variable holds nothing until a value is assigned to it"* — declared, any
   type, firing since M11 for string- and number-declared receivers. And
   `value.cpp` said it outright: *"'nothing' is §6.4 q3's word for the state
   and is not a type at all."*
3. **Reading two's error had nowhere to fire from.** *"A type error at end of
   file"* needs an assignment type-check, and there is none anywhere:
   `op_store` is checkless, and resolve never compares an initialiser against
   a declaration — the declared type is a **dispatch key**, not an enforced
   invariant. Building that check meant either a test on the hottest store in
   the machine or static return-type inference `names.cpp` explicitly refuses
   to build.
4. **M11 had already spent the decision.** Its refusals were chosen *because*
   "a refusal can loosen into an answer once §8's nil is askable" — `find`
   answering nothing one day. Under reading two, `find` could never answer
   nothing; the recorded rationale of a landed milestone leaned on reading one.
5. **The asymmetry argument cuts the other way here.** "Refuse now, loosen
   later" is about sentinels wedged into answer types. Nothing-in-a-string-slot
   is not a sentinel — it is the honest absence, refused by name at every use —
   and reading two's "tight" position is itself forever: a `read_line` that
   returns a `variant` is an interface every program writes extraction
   ceremony against, which is §1.1's exact enemy.

**What reading two offered survives as `held`** — the refusal at the moment
nothing arrives somewhere unexpected, opt-in and by name — and DESIGN §8.7
keeps the declined reading beside the taken one, so the day it looks wrong the
losing argument is findable.

### 2.2 The vocabulary, each row overrulable in one place

1. **`holding` answers a word, and the words are the arms.** `"nothing"`,
   `"bool"`, `"number"`, `"string"`, `"satellite"` — one word per arm of
   value.hpp's variant, the READING of each type (the way display prints
   `true`, not the way a diagnostic says "the satellite runtime"), and
   `word_of()` in variant_methods.cpp is the one place the list grows when
   M15's float or M19's file handle appends an arm. It never refuses: the
   nothing state is an *answer* here, which is the milestone's whole reason.
2. **`holds(x)` refuses a word off the list, never answers false.**
   `box.holds("strng")` answering false forever is a condition no program can
   satisfy wearing a working test's clothes; the S0713 sentence names the five
   words and the caret names the line, and the refusal loosens the day a new
   arm makes a word real. `box.holding() == "strng"` still answers false —
   equality is not a question about the vocabulary.
3. **`held` is the checked extraction.** Plain assignment already copies a
   variant's value out, nothing included — satellite checks values, not
   annotations — so `held` exists for the program that means *"there is
   something in here, and stop me at this line if not."* On nothing it is
   S0714 by name, which is the done-when's second clause satisfied by a row
   whose receiver cannot be of a wrong type.
4. **`clear` is the string's `clear` again** — same word, same
   one-value-two-destinations mutating contract, `1 6 1 15`'s twin at
   `1 6 14 4`. Clearing an empty variant answers nothing rather than
   refusing: the method promises a state, not a transition.
5. **The four rows are the only rows in the table with no receiver check**,
   and that is §2.1 made executable: any value at all is a legal thing for a
   variant slot to hold, so there is nothing for a `string_at`-shaped helper
   to refuse.
6. **The numbers came from the acceptance walk**, WORD_NUMBERS §1.1 applied
   exactly as the thread's children were: `example/variant.satl` asks
   `holding` first, `holds` second, takes with `held` third, erases with
   `clear` last, and §2.5 of the numbering records the delegation. `1 6 14`
   gained its `(0)` with its children, the notation edit `1 6 13` already
   modelled.

## 3. What building it found

1. **Every method refusal in the language named a `(`, and the done-when is
   what caught it.** `Machine::text_of` answered an op's node's anchor token,
   and a Call node's anchor IS its paren (ast.hpp's table) — so S0714 printed
   *"`(` was asked of a variable that holds nothing"*, at M11 as well as here,
   and nobody had read one aloud until a done-when demanded the refusal be
   **by name**. The fix is in `text_of` itself — a call answers its target's
   text — so M11's S0713/S0714/S0722 sentences healed with it, and
   `tests/eval_test/variant.cpp` asserts the name lands in the sentence.
2. **S0720 gave wrong advice for a receiver that IS a name, and M12 made that
   case easy to hit.** `box.upper()` on a variant fell into *"name the
   receiver first"* — advice that cannot help, since `box` is a name; the
   fold failed because the TYPE has no such word. The compiler knows the
   declared type at that arm, so **S0723 EVAL_NO_SUCH_QUESTION** now says
   what is true — *"`upper` is not a question a `satellite.variable.variant`
   answers"* — with per-type advice in its third slot (the variant's row
   names its four words and `held()`; every other type gets the general
   sentence, and a type's own milestone can bring it a better one). It stays
   a run-time refusal for S0720's own reason: a wrong question in a branch
   that never runs is a program that runs. `f().trim()` still gets the
   one-hop sentence, which is still true and still the fix a person can make.
3. **The install count is one seam shared by two milestones' test sections.**
   `install_handlers()` is one summed install, so `scalars.cpp`'s assertion
   moved from 33 to 37 the moment the variant half was added — the count
   caught the join exactly as designed, and the message now names both
   owners.
4. **The startup guess was wrong and the table kept it honest.** The
   prediction written before measuring put `variant.satl` "near
   `console.satl`"; the measurement put it at share 0.612, above `--call
   factorial`'s 0.562 — nine lines through the printer's queue against
   console.satl's one. `make_support/startup.rows` records the misjudgment
   beside the number, because a registry a person can quietly re-guess is the
   shape this project keeps refusing.

## 5. What it left open

1. **`satellite.variable.expression` `1 6 9` stays numbered and unbuilt**, and
   saying so was work the PLAN entry itself already did. Nothing here changed
   its standing; WORD_NUMBERS §1.2 still means it keeps its number whatever
   becomes of it.
2. **The `(0)` definition is still unwritten and still the author's.**
   WORD_NUMBERS §2.5 repeats §2.4's note; `1 6 14 (0)` was added by copying
   what the table already does, again.
3. **S0723's general advice sentence is generic on purpose** — *"its methods
   are the words numbered under that path"* — and the compile arm that picks
   it is where a type's own milestone (M13's time, M16's containers) can hand
   its type a better one, the way the variant got its own here.
4. **`word_of()` must grow with the value variant's arms**, and nothing but
   its comment enforces that. The day M15 boxes a float or M19 lands the file
   handle, `holding` answers a new word and `holds` loosens; a forgotten edit
   there would make `holding` answer `"satellite"` for an arm that is not the
   runtime — variant_methods.cpp's file note is the tripwire, and a words.def
   -style consumer check may be worth it when the arms start arriving.
5. **Method-on-literal** (M11 §6.3) is unchanged and slightly more tempting
   now — `"x".holding()` reads naturally — and still costless to a program
   today: name the receiver.
