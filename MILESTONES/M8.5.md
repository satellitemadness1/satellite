# M8.5 — the walkers keep their own stacks

**Landed 2026-09-01** (`PENDING`).

DESIGN §7.5 is the rule, [PLAN.md](../PLAN.md) §2.5 and §2.6 are the decision and
its place in the order, [SCRATCH.md/NO_LIMITS.md](../SCRATCH.md/NO_LIMITS.md) §5
is the plan file by file, and §7 is the acceptance test. This is a **review and
not a plan** — what was decided on the way, what building it found, what it left
open, and which measurements prove its test.

**Seven walkers over four cycles**, in four files of `src/parser/`, one of
`src/name_resolver/` and three of `src/abstract_syntax_tree/` — one of which is
three because this milestone split it. Two new test files of 260 lines, and
**one thousand and one hundred lines of C++ that behave identically to the
thousand they replace**, which is the whole claim and §5 is how it was checked.

---

## 1. What the milestone was

**A rule the tree had already agreed to and did not keep.** DESIGN §7.5 was
rewritten on 2026-08-31 to say the language has no depth limit and that no walker
may use the C++ stack for a depth the user's program controls. On the same day
§7.5.1 was written to say, in the specification itself, that the tree did not
meet it — *"four walkers recurse on the C++ stack with no bound at all, so each
has a depth at which it dies with signal 11 and says nothing."*

Measured 2026-08-31 at `ulimit -s 8192`, one expression nested N deep:

| N | `--check` | `--unparse` | `--satc` | `--resolve` |
|---|---|---|---|---|
| 19,000 | ok | **SEGFAULT** | ok | ok |
| 20,000 | ok | SEGFAULT | **SEGFAULT** | **SEGFAULT** |
| 32,000 | **SEGFAULT** | SEGFAULT | SEGFAULT | SEGFAULT |
| 100,000 | SEGFAULT | SEGFAULT | SEGFAULT | SEGFAULT |

**Reproduced on 2026-09-01 against the binary this milestone replaces**, which is
the table above with a fourth column filled in and a fifth that is all zeros.
Every cell after the rewrite is exit 0.

**It is M9's precondition and that is why it is here rather than later.** PLAN
§2.6: the four static passes walk the arena and must stop using the C++ stack to
do it, and *"closure compilation then emits onto a stack that already exists
rather than growing one afterwards. Doing them in the other order means doing the
evaluator twice."*

## 3. What was decided on the way

### 3.1 Four cycles, not one, and the fourth had never been named

NO_LIMITS §3 lists every recursive walker in the tree and it is a list of
FUNCTIONS. What the rewrite needed was the list of **cycles**, which is shorter
and is the thing a machine is one of:

| cycle | how it closes |
|---|---|
| expressions | `expression → unary → postfix → primary → '(' expression`, and back in again through an argument list and through a subscript |
| statements | `statement → block → statement`, and the three compound forms whose body is a block |
| types | `type → generic_arguments → type` |
| **suit bodies** | `suit_body → section → suit_body` |

**The fourth is not in NO_LIMITS §3's table.** That table has a row for
`parser_declarations.cpp` and the recursion it names is `suit_body → suit_member →
capsule_decl → block`, which is real and is a one-way edge into the statement
cycle. `section()` calling `suit_body()` back is a cycle and was missed, because
nothing in `example/` nests a section inside a section and the function is four
lines long. **A cycle is invisible in a list of functions and obvious in a list of
edges**, and drawing the edges is what found it.

### 3.2 The cycles are not nested in each other, which is what made four machines enough

Every edge BETWEEN the cycles runs one way: a suit body holds a capsule, a capsule
holds a block, a statement holds an expression, an expression holds no statement,
and a type holds only types. So the machines can call each other directly — the
statement machine calls `expression()`, which is one C++ frame and not one per
level — and the deepest a satellite program can drive the parser's C++ stack is
**one frame per machine**, four, whatever it is nested inside.

**Had one edge run both ways, this would have been one machine and a much larger
one**, because an expression that could contain a statement would have to be
suspendable from inside the statement's own suspension. It is worth writing down
that the grammar does not do that, because it is a property M9 inherits: DESIGN
§6 has no statement-expression, and the day it gets one this decomposition is what
has to be revisited.

### 3.3 The pieces read forwards, which is the only way the printers stayed reviewable

An explicit stack pops in reverse, so the naive translation of a printer writes
every case backwards — push the closing bracket, then the children in reverse,
then the prefix. That is correct and unreadable, and a printer is the one thing in
this tree whose source ought to look like its output.

**So a case NAMES its pieces in source order and one function reverses them.**

    case NodeKind::Index:
        expr(n.a); say("["); expr(n.b); say("]");

`flush()` is the only place the order is inverted, and it is four lines. Both
printers and the resolver's walk use the same shape.

### 3.4 The `.satc` writer lost a rule rather than gaining one

`write.cpp`'s header carried a paragraph — reproduced here because deleting it is
the finding — requiring every subexpression to go into a named local before being
joined:

> note() appends to the line's comment as a side effect, and C++17 leaves the
> operands of `a + b` INDETERMINATELY SEQUENCED — so
> `expression(n.a) + " = " + expression(n.b)` may run the right side first and
> emit a comment column whose paths are in the wrong order, on one compiler and
> not another.

**A piece is expanded when its output position is reached.** So the comment column
is in the order of the output by construction, and the discipline is gone rather
than restated. That is the one place this rewrite made the module smaller in
rules as well as different in shape.

**What it cost to keep that true was three more Step kinds.** `Fixed`,
`GlobalName` and `CapsuleName` are pieces rather than strings computed early, and
the reason is exactly the hazard above one level up: `satellite.returns` is
printed AFTER a capsule's parameter types, so computing it eagerly would have put
its name in the comment column before theirs. The general rule is that anything
which notes must be a piece unless nothing lazy precedes it, and making all three
pieces is cheaper than checking that at each site.

### 3.5 The comment column can still be measured, which is why the line has two ends

The writer pads its comment to column 41, counted from the start of the line —
which the recursive version knew because it built the line as a string before
printing it. A streaming printer has no such string. **It has `out_` and the
index the line started at**, which is the same number and needs no buffer:
`LineStart` records `out_.size()`, `LineEnd` measures against it.

### 3.6 `unparse.cpp` was split, and the seam was already chosen

Making the printer keep its own stack took it from 341 lines to **565, of which
452 are code** — the widest file in the tree by a distance, against PLAN §3's
target of 300. The seam is not an arithmetic: `satellite_cache/write_*.cpp` is the
same printer with the paths substituted and has been three files since M4.5, on
DESIGN §6's own three levels. The printer now has the same three, plus the
internal header the writer already had.

**So the two printers are twins in shape as well as in walk**, which is what
`write.cpp`'s header has claimed since M4.5 and could not previously be checked by
looking.

### 3.7 The resolver's actions are the sentences the recursion was saying silently

`walk.cpp`'s stack carries six actions and four of them are not "visit a node":
`CloseScope`, `Declare`, `MemberDone` and `CallTargetDone`. Each is a rule the
recursive version expressed by WHERE a call sat:

- a `Block` and a `For` close their scope after their children, not before;
- a `VarDecl`'s name enters scope **after** its initialiser, which is what decides
  `satellite.variable.number x = x`;
- `member()` and `call()` read their receiver's `Info` back, so the rest of each
  has to wait for the whole subtree under it.

**Every one of those was already a comment in the file** saying why the call was
where it was. The rewrite turns three comments into three enum values, which is
the same fact in a place the compiler can see.

## 4. What building it found

### 4.1 The old test for the resolver's depth was measuring the wrong stack

`tests/resolve_test/frames.cpp` gained a 20,000-deep fixture on 2026-08-31, with a
note saying it *"costs about 60 MiB of the stack machine_limits/limits.hpp asks
the kernel for at startup."* **Both halves of that are wrong.** `065-tests.mk`
names resolve_test's sources and `machine_limits` is not among them, so the test
binary never had the raised stack and has always run on the 8 MiB a login shell
hands out — the fixture passed because 20,000 frames of the resolver fit in 8 MiB,
not because of a raise it never got.

**That is the accident that makes the new fixtures worth something.** None of the
test binaries links the raise, so `tests/parser_test/depth.cpp` at 100,000 levels
is a check against 8 MiB — and a walker that still recursed would fail it rather
than pass. A test run against the 1.9 GiB `satl` asks for would have proved
nothing at all.

### 4.2 A test that reads the arena has to know which end it is built from

The first version of the associativity check took `first_of(ast, NodeKind::Binary)`
as the root of `1 - 1 - 1 - …` and found a chain of length one. **The arena is
built bottom up** — a node is added when its children are finished — so `first_of`
answers with the DEEPEST node of a nest and the root is the one added LAST. The
check now uses a `last_of` written beside it, with the reason on it, because a
check that walks from the wrong end passes on every tree.

### 4.3 The printers meet the size of their own answer, and that is not a limit

At 100,000 nested BLOCKS the walk is fine and the output is not: the printers
indent four spaces per level, so the answer is quadratic in the depth — 600 MB at
10,000 levels, 2.4 GB at 20,000, 5.4 GB at 30,000, measured. At 100,000 it is
about sixty gigabytes, and on this 61.9 GiB machine `--satc` ends with
`std::bad_alloc` and exit 134.

**That is the machine running out of room to hold an ANSWER, not a walker running
off its stack**, and NO_LIMITS §2.4 drew the distinction before this milestone
started. It is why the block fixtures in `tests/satc_test/depth.cpp` are 2,000
deep and the expression fixtures are 100,000: an expression's printout is linear.

**And with a ceiling set it refuses in words, which is what §7 asked for.**
Measured with `MEMORY_MAX=2GiB` in a `satellite_config.ini` beside the binary:

    satl: stopping -- this run is using 3.5 GiB and MEMORY_MAX is 2.0 GiB (the file)

and exit 4. **Without one, `MEMORY_MAX` is the whole machine and the allocator
fails first** — which is NO_LIMITS §8's first open question and is untouched by
this milestone.

### 4.4 The one behaviour that changed shape is a message that did not

`section()` used to be a function of its own, so a section's braces were opened
and closed by a `suit_body()` call that said *"to open the spacesuit"* and *"to
close the spacesuit"* — the outer body's wording, applied to an inner section.
The rewrite opens both in one loop and **keeps both sentences exactly as they
were**. Improving them here would have been two changes wearing one commit, and
`tests/reporter_test` pins the wording of every diagnostic in the tree.

## 5. How it was checked, which is the whole of the argument

**A rewrite of eleven hundred lines is worth nothing without a way to say the
output did not move.** Three, in increasing strength:

1. **All eight suites green**, including `roundtrip.cpp`'s character-for-character
   comparison over the acceptance programs and `satc_test`'s check of every
   number in every written line against the numbering.
2. **The new depth fixtures**, which the old code fails: `tests/parser_test/`
   checks nested brackets, calls, subscripts, unary chains, blocks, `if` blocks,
   an `else if` chain, generic arguments and nested sections, plus
   left-associativity at 100,000 terms and a round trip at 100,000 levels.
3. **The binary before and the binary after, compared byte for byte.** A worktree
   at `1f70002` was built and both were run over `--unparse`, `--satc`,
   `--resolve`, `--check`, `--tokens` and `--words` on all seven programs in
   `example/`, with `HOME` pointed at a scratch directory so each started cold:
   **42 outputs identical, 0 differing, and all five written `.satc` files
   identical byte for byte.**

**The third is the one that matters**, because the first two check what the tests
were written to check and the third checks everything else — the comment column's
order, the spacing, the two programs in `example/` that must NOT parse and the
error each of them gets.

## 6. What it cost, measured rather than quoted

PLAN §2.5 has carried a 2–3× figure for the explicit control stack since the plan
was written, with its own sentence saying the figure *"is borrowed rather than
measured, which by §9's own rule means it decides nothing here until this project
measures it."* **It is measured now, for the static passes.**

Over 32,000 lines of ordinary satellite — 2,000 capsules with parameters, a
conditional, a loop and arithmetic, which is a program shaped like a program
rather than like a fixture — best of nine runs of ten, 2026-09-01:

| step | before | after | |
|---|---:|---:|---|
| parse (`--check`) | 147.4 ms | 145.4 ms | unchanged, inside the noise |
| the unparser's own step | 6.7 ms | 16.6 ms | **2.5×** |
| the `.satc` writer's own step | 48.0 ms | 60.1 ms | 1.25× |
| `--unparse` end to end | 154.1 ms | 162.1 ms | +5.2% |
| `--satc` end to end | 195.3 ms | 205.5 ms | +5.2% |

**The borrowed figure was right about a printer and wrong about a parser.** The
parse is unchanged because recursive descent's C++ frames were replaced by frames
in a vector, one per nesting level, and there were never many; the printers pay
because every piece of output is now a `Piece` pushed and popped rather than a
substring returned. The writer pays less than the printer in RATIO because it does
more work per node — a path match — so the walk is a smaller share of it.

**What is still unmeasured is the evaluator's**, which is the half §2.5 was
actually arguing about, and it is M9's to take.

**Startup did not move.** `make startup`, 2026-09-01: every row inside ±0.05 ms of
its previous share, which is the noise floor §4.3 established.

**And `make test` went from about 0.2 s to 1.4 s**, nearly all of it
`parser_test`, which now parses about ten megabytes of generated source on every
build. That is the price of the fixtures being in the binary rather than in a
scratch file, and §7's rule is that a test binary is where a claim gets checked on
every build.

## 7. What it left open

**Nothing of its own, and three things it inherited — one of which was answered
the same afternoon.**
`SCRATCH.md/NO_LIMITS.md` §8 carries all three and each is the author's:

1. **What happens when memory really does run out.** §4.3 above measures both
   halves of it — the watchdog refuses in words with exit 4 when `MEMORY_MAX` is
   set, and the allocator aborts first when it is not — but whether an exhausted
   heap should be the same sentence as a ceiling is a decision.
2. ~~**What `satellite.library.system.max_depth` `1 14 2 2` means now.**~~
   **ANSWERED THE SAME DAY, 2026-09-01, ON THE AUTHOR'S DECISION**, which is what
   happened to M8's four as well and is recorded here rather than quietly removed.
   It is **a memory ceiling on the control stack, in bytes, and unset means the
   machine** — the reading that keeps the name honest, costs a check when the
   stack grows rather than on every push, and lets a runaway recursion be told
   about recursion instead of about memory. The alternative put first was a number
   large enough never to fire, and it was refused by two things already written
   down: NO_LIMITS §4.1.1's *"a bigger number and not the absence of one"*, and
   DESIGN §7.5's kept v1 measurement, where a guard that could never fire let the
   segfault it existed to prevent happen anyway. PLAN §8's M9 entry carries the
   whole argument; **nothing was built for it here** — the reader and the range
   land at M9 with the stack that reads them.
3. **The evaluator's cost figure**, above.

**And one thing this milestone deliberately did not do.** The parser's error
recovery is unchanged and untouched — `synchronise()`, `panic_`, `fresh_` and the
one-error-per-synchronisation rule are the same lines in the same places, because
NO_LIMITS §5.4 names them as the thing to watch and `tests/reporter_test` is what
would have caught a change. It did not have to.
