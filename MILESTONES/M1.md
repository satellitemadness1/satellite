# M1 — `satl` exists and says how to use it

**Landed 2026-08-26** (`eef1fbb`). **Verified 2026-08-29** against the binary in
the tree, one clause at a time.

**Verdict: done.** Every clause of the milestone's own done-when holds, and the
two decisions it took against the first satellite still hold. What has changed is
that **three facts M1 measured and wrote down are no longer true of the binary**
— none of them because M1 was wrong, all of them because later work moved what
they measured. §5 is that list, and it is the only thing in this file that asks
for an edit anywhere.

---

## 1. What the milestone was

Two documents specify it and they do not disagree.
[PLAN_ONE.md](../PLAN_ONE.md) §7 holds the checklist; [PLAN.md](../PLAN.md) §8
holds one line — *"`satl` exists and says how to use it"* — and points at §1,
which is where the tree's current state is kept rather than the milestone's.

**The binary, the build, and the way in. No language at all.** In full, from
PLAN_ONE §7:

- `Makefile` as an **index**, with the build in `make_support/` — the first
  satellite's *final* restructure, adopted as this one's first commit rather
  than arrived at.
- `src/system_facts/version.hpp`, carried over: VERSION and REVISION as two
  numbers moving at different rates, arriving as `-D` on the recipes that need
  them and **deliberately not in `CXXFLAGS`**.
- `satl` with no arguments prints the opening information: what this is, the
  version, and **`satl filename.satl`** as the way to run a file.
- `satl --version` / `-V`, `satl --help` / `-h`.
- `satl <file>` recognises the argument and **reports honestly** that the reader
  lands in a later milestone. It does not pretend.
- exit codes: 0 for `--version` and `--help`, non-zero for a usage error.
- **the startup budget is measured here**, with `satl` doing nothing, and the
  numbers go in `make_support/040-sources.mk` beside the decision they justify —
  not in a commit message, where nobody looks for them again.

**Done when:** `satl` prints its opening information, `satl --version` prints a
version, and startup is measured and recorded.

## 2. The done-when, checked one clause at a time

Run 2026-08-29 against `./satl` as built in the tree. One invocation per row.

| clause | command | result | |
|---|---|---|---|
| opening information | `satl` | names the version, says `satl filename.satl`, says running a file lands at M8 | **0** |
| a version | `satl --version` | version, build stamp, compiler, invoked path, flags | **0** |
| its short form | `satl -V` | same | **0** |
| every way to start it | `satl --help` | eleven forms, milestones in brackets | **0** |
| its short form | `satl -h` | same | **0** |
| a file that exists | `satl example/hello_world.satl` | *"running a file is not built yet — it lands at M8. example/hello_world.satl **was found and nothing was done with it**"* | **3** |
| a file that does not | `satl nosuchfile.satl` | *"… **could not be read either**, so check the path before M8 arrives"* | **3** |
| spelled out | `satl --run example/hello_world.satl` | same as the file arm | **3** |
| `--run` with nothing after it | `satl --run` | usage error | **2** |
| an option that is not one | `satl --bogus` | `unknown option --bogus`, then the usage | **2** |

**The file arm is the one worth reading twice, and it is the clause the
milestone argued for rather than merely listed.** A misspelled path answered
with *"not built yet"* is a bug report waiting to be filed against M8 by
somebody who typed the name wrong. So the two cases print different second
lines, and they print them **now**, at the milestone that cannot run either.
Both exit 3, which is correct: `EXIT_NOT_YET` says *a correct request this
milestone cannot serve*, and neither request was malformed.

**Exit codes live in one place**, [src/programs/opening.hpp](../src/programs/opening.hpp)
— `EXIT_FINE = 0`, `EXIT_USAGE = 2`, `EXIT_NOT_YET = 3` — *"so that two arms
cannot disagree about what a given failure is worth."*

**The banner returns a string rather than printing one**, and that is also an
argument rather than a style: M11.B's prompt needs the same text, and the first
satellite wrote its REPL banner as a second literal, which then drifted and said
`0.1` for months while `--version` said `002`.

## 4. Two things came out different from the first satellite

Both were right, and **neither was a change against `PLAN_ONE.md`, which had
already called both.**

1. **`--help` exits 0, against the first satellite's 2.** A request correctly
   made is not an error; a packaging script that greps `--version` is entitled
   to a zero. An exit status says whether what was asked for happened, not
   whether the program did any work.
2. **"119 shared objects" is not this machine's number.** The first satellite's
   source says gtk4 and vte pull 119; here `satl-term` resolves **79** and maps
   **78**. The shape of the argument holds — a windowing toolkit is dozens of
   objects and satl links none of them — and the count is not repeated anywhere.

## 5. Three facts M1 recorded that are no longer true

M1's discipline was to write measured numbers next to the decisions they justify.
That is the right discipline and it has the failure mode every measured number
has: **the thing measured moves and the number stays.** All three below are
consequences of work that landed *after* M1 and none of them is an M1 defect —
they are recorded here because a stale number in a build fragment reads exactly
like a current one.

- **`ldd satl` no longer lists 6 shared objects. It lists none.** `satl` is
  statically linked as of `088f8e6` (*static is the default in both layouts*),
  so `ldd` answers *"not a dynamic executable."* Three places still say 6:
  [make_support/040-sources.mk:14](../make_support/040-sources.mk#L14) (*"78
  against satl's 6"*), [PLAN_ONE.md:521](../PLAN_ONE.md#L521), and
  [PLAN.md:2578](../PLAN.md#L2578). The comparison the number was making —
  78 against 6 — is now **78 against 0**, which makes the argument stronger and
  the sentence wrong.
- **The startup numbers in `040-sources.mk` are M1's machine on 2026-08-26**:
  bare `int main(){return 0;}` at 1.74 ms, `satl` at 1.75 ms, `satl --version`
  at 1.75 ms. PLAN.md §1 records a *different* set taken 2026-08-28 for M2 —
  1.59 / 1.60 / 1.61 ms — on the same machine, two days later. Neither set says
  it supersedes the other, which leaves a reader to guess which is the floor.
- **"The largest C++ file is `src/programs/main.cpp` at 137 lines"** was true of
  M1 alone and stopped being true the next day. PLAN.md §1 already carries the
  correction and says so in its own parenthesis; it is listed here so the three
  are in one place.

## 7. The startup time is unknown

M1's done-when is *"startup is measured and recorded"*, and **the recording is
intact** — `make_support/040-sources.mk` lines 17-25 hold the numbers beside the
decision they justify, which is the clause's real requirement.

**The numbers themselves are stale and this review did not replace them.** They
describe a dynamically linked `satl` on 2026-08-26; the binary is statically
linked now. An attempt to re-take them on 2026-08-29 was abandoned: the machine
was compiling under a load average of 29, which makes any launch time measured
there a measurement of the compile, not of `satl`.

**So the current startup time is UNKNOWN.** It should be re-taken on an idle
machine — 50 launches, wall time summed and divided by 50 — and when it is, the
three sets of numbers in the tree (M1's 2026-08-26, M2's 2026-08-28, and that
one) should be reduced to one that says which machine and which build it is of.

Everything in §2 was run and is current.
