**Landed 2026-08-28** (`d9ff549`). **Reviewed 2026-08-29** by reading the module,
running `make test` and running the consumer.

**Verdict: done.** Every clause of M2's done-when has code behind it, the test

## 1. What the milestone was

- **`src/satellite_words/words.def`, written as a tree**: each entry names its
  parent, and **its position among that parent's children *is* its number.** A
  transcription of [WORD_NUMBERS.md](../WORD_NUMBERS.md) and nothing else — that
  file is the authority, this one is the copy a compiler can check.
- the trie, the spelling interner, and `PathId`.
- `words.hpp` as the consumer, with the static_asserts **in the header** so every
  future consumer inherits them.
- **the four properties**, restated once the three real aliases were found (§3).
- **a digest over `words.def`**, so a `.satc` can name the numbering it was
  written against ([SATC.md](../SATC.md) §2; used at M4.5).
- **a live child counter on every node**, so any node can be asked for the next
  number free under it (PLAN §8.1).
- **`satl --words` dumps the tree with each node's number** — *the registry gets
  a consumer in the same milestone it gets written*, which is the one thing the
  first satellite did not do.
- a test proving `satellite.console.display` walks to `1 5 1`,
  `satellite.random.normal` to `1 7 2`, and that both intern to stable `PathId`s.

**[PLAN_ONE.md](../PLAN_ONE.md) §7's M2 still carries the pre-2026-08-27
numbers** — it asks for `satellite.console.display` at `1 1 1` and
`satellite.random.normal` at `1 5 2`. Those moved when settling QUAD §3 took
§2.2 from 144 entries to 215. [PLAN.md](../PLAN.md) §8 is the current spelling
and is what the test checks; PLAN_ONE's copy is a stale citation, not a second
requirement.

## 3. The four properties, and why only one is a `static_assert`

M2 opened with *"every parent's children are dense from 1 with no holes and no
duplicates"* — **and that check failed on the numbering it was checking.** §2.2
holds three deliberate duplicates: `random.fast.range`, `.normal.range` and
`.ultra.range` are **aliases** of the call shapes above them. So "no duplicates"
is false as stated, and the milestone restated it as four properties with an
escape clause — *an alias is one node with a second spelling, not a second node.*

**Only one of the four is asserted, and that is the encoding paying off rather
than three being forgotten.** `words_invariants.hpp` says which is which:

| | property | how it holds |
|---|---|---|
| 1 | no holes — every parent's children dense from 1 | **by construction** — a number is a *position*, computed `++counter`, so the file cannot express a hole |
| 2 | no duplicates among non-aliases | **by construction** — two rows cannot share a position |
| 3 | no orphans, no node is its own ancestor | **`static_assert`** — the one the encoding does not give |
| 4 | no alias points at a number that does not exist | **by the compiler** — an alias names an *identifier*, so a bad one is an unknown enumerator |

**And eight more the encoding needs that PLAN could not have known to ask for**:
the enum and the table are the same length; the kinds are distinct; one root;
parents declared before children; one bare shape per parent; `SAT_BARE` and the
text `"()"` never disagree; a row has a spelling exactly when its text does not
begin with `(`; two siblings never share a whole text; an alias never shadows a
sibling or repeats another alias.

**What no assert can reach is the transcription**, and the module says so in
three places. A row *left out* of `words.def` does not leave a hole — it
silently renumbers every sibling after it, **and both files stay internally
consistent.** That is why the test opens the markdown.

## 4. §8.1 — the half no compiler can see

PLAN §8.1 splits M2 in two, and all eleven asserts are about the frozen half.

|  | the language's words | the user's names |
|---|---|---|
| numbered | ahead of time, in `words.def` | at parse time, as met |
| frozen | forever, across every program | for one run |
| checked by | `static_assert` in the header | nothing a compiler can see |
| a `PathId` is | stable and quotable | valid inside one run only |

Its three consequences, and where each landed:

- *"The header's static_asserts cover the frozen half only — that has to be said
  in the header itself."* → `words_invariants.hpp` closes with **WHAT THESE DO
  NOT COVER**, naming the runtime half and pointing at `words_runtime.hpp`.
- *"Anything that persists a `PathId` must record the name instead."* →
  `is_language_word()` in `words_nodes.hpp` is the predicate, with the rule
  written above it, and `runtime.cpp` asserts it of a user's id.
- *"Decide whether M2 owns a real allocator or a stub."* → **a real allocator.**
  `words_runtime.hpp`'s `class Words` is the record: `next_free`, `find`,
  `define`, `intern`. Not a singleton — a run's names end with the run, which
  M22 needs. **Its caller arrives at M4**, and PLAN M4's entry now says so.

**Three defects in that class were found by review on 2026-08-28 and are fixed
and tested**: an empty name matched a bare row and came back as a language word;
`find()` scanned only the numbered children, so `args` — one of DESIGN §7.7's six
spellings of `arguments` — was handed a *user* number while `walk()` answered the
language's node for the same spelling under the same parent; and the same empty-
spelling hole in `match_shape`, which was reachable from the command line —
`satl --words satellite.console.` answered `1 5 0` and exited 0.

## 5. What the test actually proves

`tests/words_test/` is four files and links no objects — everything under
`satellite_words/` except `dump.cpp` is constexpr data and pure functions.

- **`authority.cpp`** opens `WORD_NUMBERS.md`, parses §2.2 and **walks all 222
  paths**, checking each against its number. It checks the counts *first* (222
  rows, 219 distinct numbers, 3 aliases, 35 `(0)` markers) — a suite that reports
  PASS over half a table is a green line, not a result. It **refuses to pass when
  it cannot find the file**. And it checks the converse, added 2026-08-28: a row
  `words.def` has and the authority does not takes no number from anybody and
  renumbers nothing, so `kNodeCount == rows − aliases + markers` is the only
  thing that can see it.
- **`walking.cpp`** checks M2's two worked examples **by name**, so the
  milestone's acceptance condition is findable by grep; then the interner in both
  directions, the `(0)` rule at both depths, six-segment depth, `sizeof(PathId)
  == 4`, and what a *failed* walk says — because M5 does not exist yet and what
  M2 owes it is a signature M5 can be built against without changing.
- **`runtime.cpp`** is the only check the user's half gets.
- The make rule depends on `words.def`, the headers, **`WORD_NUMBERS.md`** and
  `.cxxflags-stamp` — the authority is an input to this test exactly as a source
  file is.

**Verified by mutation on 2026-08-28** (recorded in PLAN, not re-run here):
deleting `satellite.console.typed()` `1 5 5` compiles clean with every assert
passing, and the test names the missing row and the four siblings it shifted.

## 6. Four things left open — three of them since closed

None blocked the milestone. **Rechecked 2026-08-30 while M3 was being reviewed:
1, 2 and 4 are closed and are left below with their answers rather than deleted,
because what a review got wrong is worth as much as what it got right. 3 is
still open.**

1. ~~**The digest has no consumer.**~~ **CLOSED — it had one, and this review
   missed it.** `dump.cpp:88` prints `digest 5d2cb10461e38766` in the header of
   `satl --words`, and `./satl --words | grep digest` answers. The item below is
   left as written because it is a good argument that was aimed at nothing: the
   review inferred the absence from the four places it thought to look and never
   ran the one command that would have settled it. *(Checked 2026-08-30.)* `kDigest` and `digest_text()` exist and are correct as far as the test
   reaches — it checks the digest is non-zero and sixteen fixed-width hex digits.
   But nothing *prints* it: it is not in `satl --version`, not in `satl --words`,
   and its first real caller is M4.5's `.satc` header. M2's whole argument is
   that the first satellite's registry made a guarantee **with no consumer for
   three commits** and four defects accumulated behind it. The node table got its
   consumer. The digest did not. *A line in `satl --version`, or a
   `satl --words --digest`, would close it for the cost of one line.*
2. ~~**Whether `satl --words` shows the aliases at all.**~~ **CLOSED — it does.**
   `hexadecimal`, `arg`, `args`, `argz`, `argument` and `argumentz` each appear
   in the dump. The worry below was sound and the answer is simply yes; it went
   unresolved for one reason, stated at the end of the item — the body of
   `dump_text()` was not read. *(Checked 2026-08-30.)* The dump is described as
   "every node, one line each, in the order `words.def` declares them" — and an
   alias **is not a node**. If it is not printed, then nine of the language's
   spellings, including all six of `arguments`, are invisible in the only
   human-readable view of the registry, reachable only by asking for one by path.
   *Not confirmed — `dump_text()`'s body was not read in this review.*
3. **`WalkError::TRAILING` is defined and never tested.** `walking.cpp` exercises
   `NOT_ROOTED`, `NO_SUCH_WORD` and `NO_SUCH_SHAPE` — the fourth value has no
   check. Reading `walk()`, it is reachable (a path that matches and then does not
   end, e.g. text after a closing paren), so this is a coverage gap rather than
   dead code.
4. ~~**PLAN §1's counts have drifted from the files.**~~ **CLOSED — recounted and
   dated 2026-08-30**, at M3, and PLAN §1 now carries a note saying the previous
   figures were already stale when this review recorded the drift and did not fix
   it. The table below is the drift as it stood. Measured 2026-08-29 with
   `wc -l`:

   | PLAN §1 says | actually |
   |---|---|
   | `words.def` at **542** | **548** |
   | largest C++ file `authority.cpp` at **261** | **299** |
   | `src/satellite_words/` is **nine files** plus `words.def` | **ten** files plus `words.def` |

   The largest-under-`src/` claim is right: `words_invariants.hpp` at **244**.
   Every file in the module is inside PLAN §3's 300, and `words.def` is the
   declared permanent exception. **`authority.cpp` at 299 is now the largest file
   in the tree and is one line under the target** — the number to watch.

## 7. What this review did not do

- **No independent re-parse of `WORD_NUMBERS.md`.** The transcription is taken as
  proven by `words_test` passing, not verified a second way. The test's own
  design is the reason that is reasonable — it reads the authority and checks the
  converse — but it is one check, not two.
- **No mutation testing.** The 2026-08-28 mutation result is quoted from PLAN, not
  reproduced.
- **No startup measurement.** PLAN §1's *"M2 cost nothing measurable at startup"*
  is quoted, not re-taken; the machine was under heavy load and the number would
  have been meaningless.
- **`dump_text()`'s body was not read** — see open item 2.
