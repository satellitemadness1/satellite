# M26 — spacesuits

**Landed 2026-09-12**, across eight commits (§6). **`.pointer()` is still owed**,
and §4 says why that is a decision rather than an omission.

[PLAN.md](../PLAN.md) §8's M26 entry is the specification. DESIGN §13 has the
feature under **Decided**, and §12 holds the leak this milestone creates.

This is a **review and not a plan**: what was decided on the way, what building
it found, and what it left open.

    $ satl example/spacesuits.satl
    two counters, built by declaring them:
      first is at 1
      second is at 5

    one of them handed to a capsule that adds 10:
      first is at 11
      second is at 5
    ...

    $ satl /home/madness/code/satl/infinity_data/infinity_data_main.satl
    (1433 lines, 11 spacesuits -- it runs)

---

## 1. What the milestone was

Three numbered paths — `satellite.spacesuit` `1 10`, `satellite.protected` `1 11`
and `satellite.public` `1 12` — that M4 had parsed and M7 had resolved, and that
nothing could run. The grammar was written. The machine was not.

**The target was the author's own program**, `infinity_data_main.satl`: 1433
lines, eleven spacesuits, inheritance, nested globals, and a memory-filler built
entirely from objects. It runs. What stops it from reaching its 8.2 billion
entities is capacity, not the language — §3.4 has the measurements.

PLAN's done-when has two halves, and both are fixtures in
`tests/eval_test/suits.cpp`:

- a capsule handed a spacesuit mutates it, and **the caller sees the mutation**,
  while a second object of the same suit is untouched;
- a protected member reached from outside is **refused by name**, with a caret.

## 2. The decisions

### 2.1 The author's three, settled before anything was built

Recorded in `e2a129c`'s message, because a decision that lives only in a review
is one the next reader thinks is open.

1. **The cycle leak DESIGN §12 conceded.** Refcount now, `.pointer()` as the weak
   reference, and a cycle collector as **its own milestone**. The collector is to
   be trial deletion over only the objects refcounting already flagged, not a
   tracing pass, because a stop-the-world collector is what DESIGN §1.1 objects to.
2. **A pointer is spelled `object_name.pointer()`** — a method, not a keyword —
   and it answers a **weak** reference.
3. **Nested globals get built**, not worked around. `infinity_data_main.satl`
   line 1118 needs `satellite.library.<capsule>.<variable>`.

### 2.2 Declaring one builds one

`counter c` with no `=` constructs a counter with its field initialisers run.
Every other type holds nothing until assigned (DESIGN §6.4 q3). A spacesuit
cannot work that way, because there is no expression that makes one: DESIGN §12
defers a constructor call. So the declaration is the construction, which is the
shape the author's files already assumed.

**With an `=` nothing is built.** `infinity_subject s = build(...)` takes the
object the capsule answered. Building one first and discarding it would make
`a = b` ambiguous about which object a name holds.

### 2.3 A method is a capsule with the receiver at slot 0

DESIGN §6.4's "methods are sugar", made structural. A capsule declared inside a
suit is numbered **under the suit** — `1 14 3 1` — the first names in the
language whose parent is a user's name. That was M4.md §6's deferred fix, "a
growable counter vector and a user-side child list, small, and M26's".

The receiver's name is unspellable on purpose. A reachable slot 0 would have been
a back door onto the bare field access DESIGN §12 defers.

### 2.4 A spacesuit holds a copy of its superclass

Inheritance was on no list. `example/class_test.satl`, in the tree since M4,
parsed `my_suit(my_superclass)` and inherited nothing. Asked, the author chose to
build it: *"a spacesuit can hold a copy of it's superclass, and it has all of
those attributes as well."*

**That sentence is a memory layout.** A child's fields are its parent's followed
by its own, so a parent's indices never move and every op a parent's method
compiled reads the right slot of a child. It cost no new op.

**Lookup runs backwards**, so the most-derived match wins. All eleven suits in
the author's file declare `spacesuit_name`, and a forwards search would have
handed a child its parent's name silently.

### 2.5 `+` converts, and every scalar has four conversion names

Found by inheritance: `class_test.satl` next failed on `"TEXT: " + my_binary`.
The author: *"if we can do it for the user, then we do it for them."* The left
operand decides what is tried, and `4 + "abc"` is `"4abc"`.

Twenty-four rows: `string(x)`, `number(x)`, `binary(x)`, `hex(x)`, and
`.string()`, `.number()`, `.binary()`, `.hex()` on each of the five scalar kinds.
WORD_NUMBERS §2.8 records who minted them and when.

### 2.6 `binary.clear()` is string's `clear` on the other type

`1 6 5 12`. The author: *"The words are supposed to all do the same thing."* It
answers the run of width 0 and writes back through the receiver, so it is
binary's **first mutating row**. Empty means width 0, not zeroed bits, because
DESIGN §8.5 makes the width part of the value. It was the last thing stopping
`example/class_test.satl`.

### 2.7 A constructor cannot declare a return type — S0525

DESIGN §13: *"A constructor is the one member forbidden to declare one, since
what a constructor produces is the object."* PLAN §8 says M26 enforces it.

**The constructor is the capsule in a suit that carries the suit's own name**,
v1's spelling. The caret lands on the return type, because that is the part to
delete.

**This build does not run that capsule at construction**, so S0525 decides
nothing about what a constructor does. §4 carries that as open.

## 3. What building it found

### 3.1 The receiver was never evaluated, and the named bug was not the cause

`e2a129c` shipped naming a bug: the receiver built by a separate `take()`. That
defect was real, and fixing it alone would have changed nothing.
`method_receiver()` only admitted **language** selectors, and a suit method's
path is a **user** path, so the receiver was never compiled. The call then read
as a sibling call and took slot 0 of the caller's frame. Fixed in `6e9e088`.

### 3.2 An over-broad arm made every ordinary call take a receiver

`b233f7a`. The spacesuit arm matched any capsule the file declared, so
`helper()` at the top level got an extra argument. **Found by `section_calls`**,
a fixture eight milestones older than spacesuits that asserts a frame's size.

### 3.3 Three holes that only running the author's program could find

All in `5d9907b`, and all invisible to fixtures whose fields were literals.

- **Field initialisers were never resolved at all.** `gather_members` recorded
  `field.init` and nothing walked it.
- **A mutating method on a field** had no op. `class_dna.append(x)` inside a
  suit's own capsule is what a spacesuit is for. `op_method_field` is DESIGN
  §6.4's storage-slot rule's fourth answer.
- **Nested globals** were mostly built already. A capsule's variables were never
  interned as its children, so the walk stopped one hop short. Only literal
  initialisers are allowed, because the value runs once at startup with no frame,
  and anything else compiled to `op_local` against nothing and segfaulted.

### 3.4 Containers were quadratic, and the fix needed two halves

`19526c9`, outside M26's list and found by its target. Every append copied the
whole body. DESIGN §12's condition for mutating in place, `use_count() == 1`,
**could never be true**, because the value stack always holds a second handle.
`dispatch()` now takes the receiver out of its storage before a mutating method
runs.

| appends | before | after |
| --- | --- | --- |
| 40,000 | 14.44 s | |
| 200,000 | | 0.13 s |
| 1,000,000 | | 0.67 s |

**What `infinity_data_main.satl` still cannot do** is build 8.2 billion
entities. It is about 300 bytes per entity from RSS growth, which is ~2.5 TB
against this machine's 61 GB.

### 3.5 `make nodes` had stopped linking since the gzip reader

`cc19306` linked the vendored zlib into `satl` beside `SATL_OBJS`, and the
enumerator's list never followed. It failed on `gzclose` the first time a new row
needed measuring. Fixed in `065-tests.mk`.

### 3.6 v1's spacesuit benchmark, re-measured

PLAN §8 asks for DESIGN §8.1's figure to be re-measured, not quoted. v1's
`class_bench.satl` needs two changes to run here. It passes a constructor
argument, so this version declares the object and then calls `set`. And it timed
itself from inside, which a satellite program still cannot do (M23 §3.5). So each
phase is its own program, timed from outside, best of three, output to a file,
with a do-nothing program subtracted for startup.

| one million | v1 | now |
| --- | --- | --- |
| constructions | 1.145 s | 0.677 s |
| prints | 0.795 s | 1.703 s |
| string transfers into one object | 0.853 s | 0.505 s |
| total | 2.794 s | 2.885 s |

**Construction and transfer are faster than v1. Printing is twice as slow**, and
it is not a spacesuit cost: printing a constant string costs the same. `strace`
counts about 722,000 `write` calls and 2.2 million futex calls for a million
lines. The printer thread drains faster than a tight loop fills its queue, so the
queue runs dry after most lines, and `console.cpp` flushes whenever it does. Its
comment assumes *"under load the queue is never empty"*, and a display loop is the
load where that is false. v1 was measured when display appended to one string and
wrote once at the end.

## 4. What it left open

- **`.pointer()`.** The author asked for it last. It already works as a user
  capsule, because a spacesuit is a reference and plain assignment shares.
  Measured on the author's shape, one store of 20,000 numbers handed to 1,000
  entities left maxrss at 7208 kB, exactly where it started. What is missing is the numbered word and the **weak** part. Today a
  self-reference is strong, so an object that names itself is never freed.
- **The cycle collector**, its own milestone per §2.1. `src/program_diagnostics/`
  already warns about a ring through declared field types as S1501. A ring
  through a variant or a container element is invisible to it.
- **Constructors do not run.** A capsule named after its suit is callable like
  any other. Constructor arguments, `super(...)` and a capsule that runs at the
  declaration are all unbuilt, and S0525 is the only rule enforced about them.
  **A v1 program with a constructor compiles and silently skips it**, which is the
  sharpest edge this milestone leaves.
- **Display flushes per line under a tight loop** (§3.6).
- **`binary.hex()` pads and `binary.to_hex()` refuses.** `b101.hex()` answers
  `x5`, and `b101.to_hex()` is refused. WORD_NUMBERS §2.2 describes `1 6 5 11` as
  "the same answer as `to_hex`", and the help entry says it pads. One of the two
  documents is wrong, and which one is the author's call.
- **`satellite.system.memory.this.used(unit)` measures the thread's stack**, not
  the process. That is why `infinity_data_main.satl` prints 0.0066 mb beside a
  9 MB RSS.

## 5. What proves it

- **`tests/eval_test/suits.cpp`** — the first test that constructs a spacesuit.
  Construction, two independent objects, reference semantics through a capsule
  and through assignment, inheritance, a mutating method on a list field, and
  seven refusals by code: S0515 to S0520 and S0525. S0516 and S0517 had been
  raised by resolve and exercised by nothing.
- **`example/spacesuits.satl`** — the same story for a person. The S0516 and
  S0517 lines are left commented out, and both were uncommented and checked.
- **`example/class_test.satl`** — the author's, in the tree since M4. It runs to
  the end.
- **`infinity_data_main.satl`** — the target. It runs.
- **`help_lines/verify.py`** — 300 worked lines run and pass, including
  `binary.clear()`'s.
- **`make nodes`** — re-measured: **230 `H` rows at M23 to 255**.
- **`tests/reporter_test`** — **134 codes**, which includes S1501 from the
  diagnostics work that landed alongside.
- **The whole suite** — 14 binaries, all green at every commit in §6.

`kNodeCount` went from **342 to 367**, so the words digest moved from M23's
`ca4810a483e0d61c` and **every `.satc` written before M26 is stale**. SATC.md §2
accepts that cost for an append.
