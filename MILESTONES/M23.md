**Landed 2026-09-12** (`PENDING`).

[PLAN.md](../PLAN.md) §8's M23 entry is the specification and
[DESIGN.md](../DESIGN.md) §10.5 is the design — three sentences of it, written

## 1. What the milestone was

- **`satellite.thread.new`, `start()` and `join()` — six numbered paths, three
  handler rows**, and the header says why the other three are right to have
  none. §2.1.
- **The language's first DEFERRED argument**: `satellite.thread.new(f(x))`
  evaluates `x` and does not enter `f`. `words.def` grows a seventh list and the
  evaluator an op. §2.2, §2.3.
- **Two `Value` arms**, the tenth and eleventh, and the second ever to come off
  the `const`. §2.1.
- **`satellite.library` becomes the one thing two walks share.** §2.6.
- **Five error codes**, S1401–S1405, in a block the index said was free and
  was not. §3.7.
- **Three decisions the author took that no document had**, all on 2026-09-12:
  where the OS thread comes from, what `join()` answers, and what happens at
  `satellite.return(satellite)`. §2.4, §2.5, §2.7.

**AND THE HEADLINE IS THAT NOTHING IN THE EVALUATOR CHANGED TO MAKE IT WORK.**
DESIGN §10.5 is *"§7's frames are what make a capsule call safe to run on one;
PLAN §2.2's arena is what makes walking the program atomic-free rather than
merely safe"*, and both held with not a line altered. §7.2's frame per call has
been the shape since M9; the op arena has been immutable since M4 with its one
mutable part — the inline cache — in a side table since M9, where
`evaluator/closure.hpp` put it *"so the op arena stays immutable and shareable
across threads (DESIGN §10.5)"*, naming this milestone four milestones early.

**M23 IS THE FIRST MILESTONE TO ADD NO NUMBERED PATH.** All six existed: `1 23`
and `1 23 1` from M2, `1 6 13 1` and `1 6 13 2` assigned out of
`example/thread_test.satl` on 2026-08-28, `1 6 16` from the same reading.
`kNodeCount` is still 342 and the words digest is still `ca4810a483e0d61c`, so
**this is also the first milestone that invalidates no `.satc` on the machine** —
which is correct rather than lucky: `.satc` caches resolve's numbering, and
everything M23 changed happens after it.

## 2. The decisions

### 2.1 Three rows for six paths, and two arms for two types

| | | |
|---|---|---|
| `satellite.thread` | `1 23` | a namespace — derived, no row |
| `satellite.thread()` | `1 23 0` | the bare shape, reserved |
| `satellite.thread.new(f(x))` | `1 23 1` | **installed** |
| `satellite.variable.thread` | `1 6 13` | a type — derived, no row |
| `satellite.variable.thread()` | `1 6 13 0` | the bare shape, reserved |
| `satellite.variable.thread.start()` | `1 6 13 1` | **installed** |
| `satellite.variable.thread.join()` | `1 6 13 2` | **installed** |
| `satellite.variable.capsule` | `1 6 16` | a type with no children — **one `SAT_BUILT` row** |

**`Thr` COMES OFF THE `const` AND `Cap` DOES NOT**, which is the one distinction
the module exists to keep. A thread is a reference type for the file's reason
exactly: two names for one are one thread, there is a `pthread_t` underneath, and
the kernel has never heard of our slots. A deferred call is a VALUE — nothing can
write it, and handing the same one to two threads is two runs of one capsule
rather than one run seen twice. `Fil` had been the only arm off the `const` since
M19; `satellite_file/file_handle.hpp` says *"M23 is when it first gets EXERCISED,
not when it gets written"*, and this is that.

**NEITHER METHOD MUTATES, WHICH IS THE FIRST TIME DESIGN §6.4's LAST LINE HAS
BEEN LOAD-BEARING IN THE NEGATIVE.** Every mutating row in the language so far
has been a container, where the body is frozen and a change IS a new value
written back to the receiver's slot. `start()` changes what the handle points
AT; the slot still holds the same handle, so there is nothing to write back.

### 2.2 The deferred call, and DESIGN §13 had one sentence wrong

DESIGN §13 settled the form on 2026-08-27 and describes it exactly right except
for who does it:

> The handler evaluates the arguments and stores `(capsule number, argument
> values)` for the thread to run later.

**The handler cannot.** By the time any handler runs, §6's evaluation rule has
already been applied to everything below it — so `f(x)` would have been
PERFORMED before `new` was entered, and `satellite.thread.new(my_capsule())`
would have run the capsule on the calling thread and then been handed its answer.
**The only place a call can be stopped from being performed is where it is
compiled.**

So the hole is in the compiler and the shape is `words.def`'s:

    SAT_DEFER(THREAD_NEW, 0)   // 1 23 1 -- `f(x)` is packaged, x is evaluated

**A SEVENTH LIST, AND IT IS THE THIRD ONE-ROW LIST THAT SAYS IT INTENDS TO STAY
ONE ROW.** `SAT_PLACE` and `SAT_TOPIC` both carry that policy and both give the
same argument, which survives a third telling: a general facility for deferring
calls is *a bare name can be a value*, which DESIGN §12 has deferred since the
language was designed. §12's own note says this form does not reopen it, and
that is still true — `capsule_test(word)` is a CALL, which §6.2's postfix loop
already produces.

**AND IT IS NEITHER OF THE TWO LISTS ABOVE IT, WHICH IS WHY IT IS A THIRD.** A
place is an argument compiled as a SLOT. A topic is an argument the compiler does
not visit at all, folding a path in its place. A deferred call is visited in
full, its own arguments are compiled and run exactly as any call's are, and only
the last act — the entering — is replaced. `op_package` is `op_call` with the
`enter()` removed, which is the relationship `op_enter` already has to `op_call`
one direction along.

**THE MARK IS A SET AND NOT A FIELD, and that is worth the four extra bytes.**
The parent marks its deferred argument on the way down and `call()` reads the
mark on the way up; because the walk is a task stack, one `NodeIndex` would work
today and would break SILENTLY the first time a deferred call appeared inside
another one's arguments — by compiling a real call as a package or the reverse.
A set cannot: each node is marked at most once, by the one parent that defers it,
and membership is a fact rather than a state.

### 2.3 Only a capsule of your own, and the refusal is at COMPILE time

`satellite.thread.new(satellite.console.display("x"))` is S1401, raised by the
compiler. **Letting it fall through to `op_dispatch` would have PRINTED**, at the
moment `new` ran — which is the one outcome worse than a refusal, and is why the
boundary is enforced rather than documented.

The reason it is a boundary at all: a handler is a C++ function with no frame, no
slots, and nothing for DESIGN §7's isolation argument to protect, so *run this on
a thread* would mean something different for `display` than for a capsule. And
DESIGN §10.1 already put the console on a thread of its own.

**S1401 HAS TWO SITES AND ONE SENTENCE.** The compiler raises it for a call it
will not package; the handler raises it for a value that is not a deferred call —
which is the arm `satellite.thread.new(x)` takes, because the seventh list says
which argument IS deferred rather than which argument MUST be. If `x` ever holds
a deferred call it simply works, which is the property that makes `1 6 16` a type
rather than a compiler internal.

**AND op_misuse GREW A HOLE COUNT FOR IT.** That op carried the contract *"every
code this op carries has exactly one `{1}`"* as a comment, because M14's two rows
did; S1401 has two holes, so the contract that was a comment is now an operand.
A `c != 0` sentinel was written first and thrown away: `Compiled::add_text`
returns the position, so text 0 is real, and the bug would have appeared only in
the first program of a run to raise one of these.

### 2.4 The OS thread is a fresh one, and PLAN's tenant list was wrong

**`machine_limits/pool.hpp` names M23 as a tenant of the M6 pool, and the test it
names is the right test asked only half way.** The rule is *"this pool takes work
that finishes"*, arrived at by ruling out the console's two threads, which do not
finish. A satellite thread's capsule DOES finish — so it passes, and passing is
not enough.

**The half the test is missing is AND DOES THE CALLER WAIT FOR IT.** `run_over()`
is a range, a split and a join: it returns when the last chunk lands. `start()`
must return before the work starts. The two are opposites.

**And underneath that is the objection that settles it.** A pool has
`THREAD_COUNT` workers, so a program starting `THREAD_COUNT + 1` threads that
join each other would wait forever — **a ceiling on the language, arrived at by
accident, wearing an optimisation's clothes**. SCRATCH.md/NO_LIMITS.md is what
that is against.

**The author settled it on 2026-09-12: a fresh `std::thread` each time**, and no
ceiling of satellite's own on how many. Measured on this machine, 10,000 threads
created, run and joined: **0.27–0.29 s, so about 28 µs each**, against 10,000
plain calls to the same capsule at under 1 ms. When the machine will not make one
— `ulimit -u`, a cgroup pids limit, no memory — S1405 reports the **machine's**
reason, because that is a fact about this computer rather than a number satellite
chose.

**The correction is written in three places and the code is one of them**, which
is this tree's habit: PLAN §4.5.1 where the tenant list lives, PLAN §8's M23
entry, and `pool.hpp` itself beside the rule that was half a test. **The test for
the next candidate is now two questions.**

### 2.5 `join()` answers what the capsule returned

DESIGN gives it no return value and `example/thread_test.satl` discards it. The
author asked which of the three verbs should carry the answer, and the argument
that settled it is that **at the other two the answer does not exist**: `new`
hands back the handle before anything has run, `start()` returns the instant the
thread is launched. To answer at `start()` you would need a thing the program
asks later — a promise — which is a second type and a second word the language
does not have. `join()` already means *wait until it is done*, so it is the exact
moment the answer becomes true, and it costs no new machinery.

**A CAPSULE THAT REFUSES ON A THREAD RAISES ITS OWN DIAGNOSTIC AND NOT ONE ABOUT
THREADS.** A division by zero inside a threaded capsule comes back through
`join()` as S0601, with S0601's caret on the line that did it. A wrapper would
put the word "thread" in front of every error a program can make and bury the one
that matters; **the thread is HOW the capsule ran, not WHAT went wrong with it**.
The span still points into the one source file because both walks compiled the
same program — M25's second file is where that stops being free.

### 2.6 `satellite.library` is the one thing two walks share

DESIGN §7.2 asked for this by name, and it is the half of that section nothing
could build before there was a second thread:

> The global registry needs **zero logic changes**. It is not demoted; it is
> pointed at the data it was designed for. Permanent identity, **cross-thread
> sharing**, lock-free reads and atomic read-modify-write are exactly what
> globals need and exactly the opposite of what locals need.

Until M23 the Machine held globals in a plain vector of its own, so a thread's
Machine would have got its own empty copy. **That is not a race, it is worse**: a
program whose threads silently do nothing to the variable they were written to
change.

**LOCK-FREE READS ARE WHAT §7.2 ASKS FOR AND ARE NOT WHAT THIS BUILT**, and the
reason is `satellite_value/value.hpp`'s first line. A `Value` is a 40-byte
variant whose widest arm is a 32-byte `Number` and whose handle arms carry a
refcount; there is no machine this tree targets on which reading one is a single
atomic operation. §7.2's sentence was written about v1's registry of `SatValue`s
and is a description of what globals WANT. So there is a mutex — and **what is
lock-free is deciding whether to take it**. `shared_` goes true exactly once per
run, on the parent thread, inside `start()`, before `std::thread`'s constructor
returns; that constructor is the synchronisation point C++ requires to publish
it, so there is no window in which one walk thinks the globals are private while
another is reading them.

**MEASURED, BECAUSE THE COST FALLS ON EVERY PROGRAM EVER WRITTEN AND NOT ON
THREADED ONES.** 3,000,000 global reads: 1.19, 1.22, 1.25 s. 3,000,000 local
reads of the same shape: 1.25, 1.20, 1.24 s. **Indistinguishable.** `make
startup` says *nothing regressed* across all 17 rows.

**AND `read, add, write` IS STILL THREE OPERATIONS.** A shared global gives two
threads one variable; it does not make `satellite.library.n = satellite.library.n
+ 1` atomic, and satellite does not pretend otherwise. `example/threads.satl` §4
asserts only that every thread saw the same variable — provable without a total,
because a thread with its own copy would leave it at exactly 0 — and says at the
line why the total is not asserted.

### 2.7 What a thread does NOT share, and what "close everything" means

**The dials are copied and not shared.** A thread inherits its parent's `1 14 2`
dials as they stood at `start()`, and a retune on either side afterwards is that
side's own. Sharing them would make a dial a fourth piece of cross-thread state
with none of §7.2's argument behind it: **a global is shared because a program
SAID `satellite.library`, and nobody says that about a dial.** The inline caches,
the four stacks, the problems and the search threshold are the thread's own for
free — `satellite_containers/search.hpp` predicted the last of those, saying M23
*"inherits a per-machine dial it can split per-thread"*, and splitting it took no
code at all.

**The author's decision on the end of a run, in their own words: "whenever the
program reaches `satellite.return(satellite)`, close everything."** So
`close_all()` raises `stop` on every thread nobody joined — seen at the thread's
next statement boundary, through the same hook M11's Ctrl-C uses — and then joins
each one.

**IT IS STOP-AND-JOIN AND NOT WAIT, AND NOT ABANDON, AND BOTH ALTERNATIVES ARE
WRONG IN A DIFFERENT DIRECTION.** Waiting hangs a program whose thread loops
forever. Abandoning is a use-after-free: a thread walks the op arena by pointer
and the arena is a local of whatever built the program.

**STOPPING IS NOT FAILING**, which is where the return value comes in: a thread
`close_all()` stopped ends `Interrupted` and its diagnostics are discarded,
because the program was over and it was doing nothing wrong. A thread that
REFUSED on its own and was never joined has its diagnostic reported and turns the
run's exit status to `EXIT_MALFORMED` — a program losing an error silently is
what DESIGN §1.1 will not have.

## 3. What building it found

### 3.1 `1 23 1` is a WORD and `1 19 1` is a SHAPE, and the first version read only one

The topic list's reader asks the CALL node, because `satellite.help(x)` `1 19 1`
is a number that counts the parentheses — resolve's question one walks the whole
shape onto the call node and leaves the target member with no path. The deferred
reader was written beside it and copied that.

**`satellite.thread.new` is not that kind of row.** `new` is numbered on its own,
so `1 23 1` lands on the MEMBER and the call node carries nothing. The first
build therefore compiled `satellite.thread.new(capsule_test(arg))` as an ordinary
call, and the failure is on the record because it printed:

    HELLO, WORLD!
    satl: error S1401: `new` runs a capsule of your own on a thread ... and
          nothing is not one

The capsule ran at `new`, returned nothing, and the handler refused the nothing.
**Legible, which is the only good thing about it** — a row whose deferred
argument happened to be a bool would have threaded the wrong thing in silence.
`defer_parameter` asks both, in order, so a future row of either kind needs
nobody to know which kind it is.

### 3.2 A thread asleep cannot hear the stop flag, and `satl` hung

`close_all()` raises `stop` and the thread sees it at its next **statement
boundary** — which is the right mechanism, and which reaches a walk that is
walking. A walk inside `satellite.time.sleep(3600)` is not walking.

**FOUND BY RUNNING IT, AND THE SHAPE OF THE FINDING IS THE INTERESTING PART.**
The first test exited in 3 ms and looked like a pass; the second, identical
except that `main` slept 0.3 s before returning, hung. The difference is whether
the child got as far as the sleep before the parent finished — **a bug whose
appearance depends on a race between the child starting and the parent ending**,
which is exactly the kind that ships.

The fix is `system_facts/interrupt.cpp`'s own shape, one mechanism over: **the
flag is the message and a signal is the alarm clock.** SIGUSR2, a handler that
does nothing, delivered with `pthread_kill` to the thread that is asleep, and no
`SA_RESTART` — so `clock_nanosleep` returns EINTR, `sleep_nanoseconds` asks the
interrupted hook, the hook reads `stop`, and the ordinary path takes over.

**SIGINT WAS THE FIRST IDEA AND IS WRONG THREE WAYS.** It would print
"SATELLITE: CTRL+C RECEIVED" to somebody who pressed nothing, set the
process-wide interrupt count, and — on the second thread closed — **escalate
inside the handler to `_exit`**, because `interrupt.cpp` treats a second arrival
as *"the first one did not land"*.

**AND IT IS A RETRY RATHER THAN A TIMEOUT, which is the distinction that makes it
allowed.** One signal is not enough: `stop` is set, then the signal is sent, and
the thread may be between those two instants — past its last statement boundary,
not yet inside the syscall — so the wake reaches a thread that is not blocked and
does nothing. So it asks again every millisecond **until the thread says it has
ended**. That puts no ceiling on anything; a thread that never comes back is in
an uninterruptible syscall, which nothing in user space can reach and which a
timeout would only let us lie about.

### 3.3 Every entry point that runs a program must close its threads, and a segfault said so

`tests/eval_test` crashed. The clause was S1402 — `t.start()` twice — and the
sequence is: the first `start()` makes a thread over `run.program`, the second is
refused, the fixture returns, the `Run` is destroyed, and **the thread is still
walking the arena.**

**THIS IS NOT A TEST BUG AND FIXING IT IN THE TEST WOULD HAVE BEEN THE WRONG
FIX.** It is the same shape `programs/run_command.cpp` already handled by
accident of being written last: a thread holds `Compiled` and `Ast` by pointer,
and both are locals of whatever built the program. So `close_all()` became a
stated rule with the sites named — `run_command.cpp`, `evaluate_commands.cpp`,
`satellite_prompt/session.cpp`'s **two**, and `tests/eval_test`'s `call` — which
is `system_facts/interrupt.hpp`'s rule one module over, *"call it from every
entry point that can run a program"*.

**THE PROMPT IS THE SITE WHERE IT BITES HARDEST AND IT IS THE ONE NOBODY WOULD
HAVE THOUGHT OF.** `satl file.satl` destroys its arena once, on the way out of
the process. A session destroys one **per line typed**, so a thread left running
by line 4 would be walking freed memory while line 5 was being parsed.

**And putting it in the test HELPER rather than in the one section that starts
threads is the half worth keeping**: every section that ever starts a thread is
now safe by construction instead of by remembering.

### 3.4 The first `close_all` threw away the error of a thread about to fail

It asked `finished` BEFORE raising `stop`, to tell *ran to its own end* from *we
stopped it*. **That is a sample and not a fact**: a thread one microsecond from
refusing was recorded as stopped and had its diagnostic discarded.

The handle now records how the walk **ended**, and `close_all()` asks after the
join, where `Interrupted` means *this function caused it* and anything else does
not. Same question, asked where it has an answer.

**AND THE TEST THAT FOUND IT WAS ITSELF RACY IN THE SAME PLACE**, which is worth
recording because the correct behaviour looks like a bug. A program that starts a
thread on its last line and returns closes it before it reaches its first
statement — so it never divides anything by zero and there is nothing to report.
**That is "close everything" working**, not a defect, and the fixture sleeps 50 ms
so the clause is about reporting rather than about scheduling.

### 3.5 A satellite program cannot measure how long anything took

`example/threads.satl` §2 wanted to prove `start()` does not wait by reading the
clock either side of it. `satellite.time.now() - began` is **S0711**: DESIGN §12
defers durations — *"time is an absolute instant only; subtraction yields a
number of nanoseconds"* — and that subtraction is not built.

**So the section uses a global as its clock**: the threaded capsule sleeps a
quarter second and only then adds one to `satellite.library.arrived`, and the
state of that global on the line after `start()` is a statement about time with
no clock in it. Recorded because the milestone wanted the feature and the
workaround is better — a quarter of a second of margin against a few
microseconds, and a failure that would be a false alarm rather than a false pass.

### 3.6 A list of threads cannot be driven without naming each element

`crew[t].start()` is **S0720** — a selector folds only through a declared name,
WORD_NUMBERS §1.5's one hop. Every element has to be named first.

**For a list of anything else that would be a COPY and the loop would do nothing;
for threads it is free**, because a thread is a reference type, so
`satellite.variable.thread member = crew[t]` is a second name for the same
thread. §6's property arriving as a convenience three sections early — and the
first case in the language where the one-hop rule costs nothing.

### 3.7 errors.def's block index stopped at S11xx, and it is the index M23 read to pick a block

The header lists the S-blocks *"so that a milestone that adds codes takes a block
instead of taking the next free number and interleaving itself with everybody
else."* It ended at **S11xx**, M18's — while **S12xx (M19) and S13xx (M20) had
been sitting three screens below it**. So the one list whose entire job is to stop
two milestones reaching for the same block told M23 that S12xx was free.

**This is MILESTONES/README.md's own sentence failing for the third time in this
tree**: *an index holds no fact of its own and therefore has nothing to check it.*
M21 found it in a check's own message (§3.7) and in `words.def`'s tallies (§3.8),
on the same day, and here it is a third shape. **Found by doing exactly what the
list asks a milestone to do**, which is the one use that catches it. Backfilled,
and S14xx is written down.

### 3.8 `words.def` said FIVE SMALL LISTS and listed four — and M23 nearly healed it silently

The block tallying the small lists over the nodes has said **five** since M19
added `SAT_OPTIONS` and the prose did not move. It listed four.

**M23 added `SAT_DEFER` and made the sentence true by accident**, which is the
funniest version of this file's standing problem yet: a count that would have
SILENTLY HEALED, leaving a correct number nobody had ever checked. The four
counts beside the names are now counted rather than typed, and the paragraph says
which failure it is.

*(The node tallies one block up — 342 / 295 / 47 / 12 — did not move, because M23
adds no `SAT_NODE` row. That is the first time since they were written.)*

### 3.9 `satellite.variable.file` never got the `SAT_BUILT` row its own comment asked for

The block's rule said *"a row joins this list beside it"* the day a type gains a
`Value` arm, and named M19's file handle in the parenthesis. M19 landed `1 6 2`
with eleven children and no row; M20's arguments object is the same story.

**Nothing was broken by it, and that is the finding.**
`satellite_help/built.cpp` derives a fourth kind in one backward pass — **a
parent of a built row is built** — so a type with a method is already answered
for. The instruction was simply wrong, and a milestone that had obeyed it would
have written a redundant line.

**So M23 adds one row and not two.** `satellite.variable.thread` has `start()`
and `join()` under it and is derived like the file. `satellite.variable.capsule`
has **no children at all** — a deferred call is made by `new` and asked nothing —
so there is nothing to derive from and the row is load-bearing. That is
`satellite.variable.float`'s position at M15 exactly, and M21 gave the float its
first method and made its row derivable without removing it.

## 4. What it left open

- **A program cannot declare a `satellite.variable.capsule` and fill it in.**
  `1 6 16` is reachable only as `new`'s argument, because the deferred list fires
  on a CALL's argument and a declaration's initialiser is a different shape.
  `satellite.variable.capsule c = f(x)` would need the list read in a second
  place, which is a decision about how far the hole in §6's evaluation rule goes
  and is not one to take in passing. **What works today is everything a thread
  needs**, and a handler that is handed a capsule value from a variable already
  answers, which is what makes it a type rather than a compiler internal.
- **A thread started on the last line of a program may never run at all.** That
  is what "close everything" costs, it is the author's decision rather than a
  defect, and §3.4 records the fixture that mistook it for one. `join()` is the
  answer for a program that needs the work done.
- **A thread blocked in `satellite.console.input` is not reachable by the stop
  flag.** §3.2's wake reaches a sleep because `sleep_nanoseconds` asks the
  interrupted hook after EINTR; the console's reader parks on its own two
  descriptors and answers its own question. **Reasoned and not exercised** —
  reading from two threads at once is a shape M14's *"stdin has exactly one
  consumer"* has not been asked about.
- **`read, add, write` on a global is three operations and two threads can lose
  an increment.** §2.6 — a race in the program, not in the language, and the
  language's answer to shared mutable state is the frame. Whether satellite
  should offer an atomic add is a question nothing has asked yet.
- **`parallel_for` is still in no numbering, no document and no milestone**, and
  M23 removing the pool's one named language tenant makes that gap wider rather
  than narrower. PLAN §4.5.1.2's decision to start the pool at startup rests on
  it.
- **A thread's diagnostics are rendered against the joining run's source, which
  is free only while there is one file.** M25's `satellite.include` of a second
  file is where that stops being true.
- **Durations are still deferred** (§3.5), and this is the second milestone to
  want them.

## 5. What proves it

- **`example/thread_test.satl`** — the file that has defined this syntax since
  M2 and that nothing could execute. It runs.
- **`example/threads.satl`** — six sections, and §3 is **DESIGN §7.1's receipt
  run backwards**: eight threads, all started before any is joined, 200
  activations each, and **1600 of 1600 right** where the first satellite
  produced 1585 wrong out of 1600. §1 proves the packaging is deferred in both
  directions, §2 that `start()` does not wait and `join()` does, §4 that
  sixteen threads share one `satellite.library`, §5 the answer, §6 that two
  names are one thread.
- **`tests/eval_test`** — **eighteen clauses** in `threads.cpp`, and the file
  exists for the refusals: each of S1401–S1405 stops a run, so a program can
  demonstrate at most one and `example/threads.satl` demonstrates none. Two of
  its clauses would fail **by never finishing** if the stop flag did not work,
  which is said out loud in the file.
- **`help_lines/verify.py`** — **275 worked lines run and passed**, up from
  M21's 271: six entries rewritten from *"Not built — M23"* to what the words
  do, four of them with examples that run.
- **`make nodes`** — the table re-measured rather than typed, and it confirms
  the three rows at the arity and receiver binding they were installed with:
