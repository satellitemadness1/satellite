# M11 — scalars and control flow

**Landed 2026-09-03** (`dff2b4d`).

[PLAN.md](../PLAN.md) §8's M11 entry is the specification: the 26 numbered
paths — the five `satellite.statement` rows, the seventeen
`satellite.variable.string` rows, `satellite.variable.bool` and the three
`satellite.bool` rows — plus the `satellite.variable.number` method rows M8's
ledger line owns, the SIGINT half of DESIGN §10.2's Ctrl-C, and the fourth
`Ending`. This is a **review and not a plan** — what was decided on the way,
what building it found, and which decisions wait on the author.

**THIS FILENAME USED TO HOLD A REVIEW OF `prototype/M9`**, renamed here by the
2026-08-30 renumber, and this landing supersedes it — §9 below is what survives
of it. PLAN §8's warning about that file ("landed in `prototype/M9` and NOT in
this tree") is now moot the right way round: M11 is in this tree.

**One new module, ten new files.** `satellite_scalars/` is the join between
the value types and the dispatch table — handlers, sixteen string methods,
fifteen number methods — on `satellite_console/handlers.cpp`'s model exactly;
`system_facts/interrupt.{hpp,cpp}` is v1's SIGINT machinery ported whole;
`evaluator/operations_dispatch.cpp` is the three dispatching arms over one
core; `tests/eval_test/{scalars,interrupted}.cpp` are the sections that prove
them. **And the language has an if, a while and a for that run, a Ctrl-C that
stops them, and a string a program can build:**

    $ satl example/scalars.satl
    Hello, World!
    ...fourteen lines...
    $ echo $?
    0

## 1. What the milestone was

**Four things, and the first was already built.**

1. **Running `if`, `for`, `while`, `else`.** M9's machine compiled and ran all
   four — `op_if`, `op_while`, `op_for` have been in `operations_control.cpp`
   since the closure tree existed, because a machine that could not branch
   could not have run `factorial`. What M11 adds INSIDE them is the statement
   boundary that makes them stoppable, which is the part PLAN §8 said only
   this milestone could demonstrate: *"the first walk long enough to be
   stopped is `while`."*
2. **The scalar rows.** `handlers[path_id]` held one row after M10 —
   `satellite.console.display`. It holds 34 after M11: two module constants,
   sixteen string methods, fifteen number methods, and the one M10 row.
3. **Methods on values.** DESIGN §6.4's sugar, compiled down: the receiver
   rides as argument 0, the selector's PathId was folded through the declared
   type at resolve, and the mutating rows write back to the slot the method
   was called on.
4. **The SIGINT half of Ctrl-C, and the fourth `Ending`.** v1's handler — no
   `SA_RESTART`, the flag, the escalation — with the machine stopping itself
   at the next statement boundary, reporting the line it was on (S0730), and
   exiting 130 through an `Ending::Interrupted` that is neither `Refused` nor
   `Stopped`.

## 2. What was decided on the way

**Every decision below is the milestone's own, because the sixteen string
methods came from QUAD and not from v1** — v1's string surface is six methods
and only `contains`, `starts_with` and `ends_with` are among the sixteen; the
rest were numbered on 2026-08-27 with signatures and no semantics. **Each is
overrulable in one place, named here.**

1. **Positions count from 0, and `substring(start, end)` is end-exclusive.**
   The counting every reader of a C-family language already has — §6.6's
   tie-breaker — and the counting DESIGN §6.2's own example `my_list[0]`
   uses. WORD_NUMBERS counts its *paths* from 1; that is a fact about the
   numbering, not about strings. (`satellite_scalars/methods_internal.hpp`,
   `position_at`.)
2. **Where another language hands back a sentinel, these refuse.** `find` on
   a missing needle is S0716, `at` past the end is S0715, `to_number` on a
   word is S0610, a backwards `substring` is S0719. The argument, written
   into errors.def's block note: a refusal can LOOSEN into an answer when M12
   makes "nothing" askable, without changing any working program's meaning; a
   `-1` that programs test for is forever. `contains`, `size` and `empty`
   exist precisely so the question can be asked first.
3. **A mutating method's answer is its receiver's new value.** `append`
   `1 6 1 14` and `clear` `1 6 1 15` carry a `mutates` column on their
   Handler row; the machine writes the answer back to the receiver's slot and
   the expression's value is the same answer — one value, two destinations,
   no second contract (`operations_dispatch.cpp`'s file note). §6.4's *"a
   mutating method needs a receiver that names a storage slot"* is enforced
   by the op rather than remembered by install sites: a mutating row reached
   with nowhere to write is S0717.
4. **The written-out spelling is refused by the row itself.** §6.4: *"no
   program may write it."* The compiler cannot enforce that — it does not
   know which rows bind a receiver — so `satellite.variable.string.upper`
   called or read as a path answers S0718, from the one place that does know.
5. **`at(n)` answers a one-character string.** The language has no character
   type and DESIGN §8's table shows no row where one would go.
6. **`replace(a, b)` is every occurrence, left to right, never rescanning
   what it wrote in** — so `replace("a", "aa")` terminates — and an empty `a`
   is refused rather than meaning something surprising.
7. **`trim` strips the raw-area whitespace** — space, tab, CR, LF, the four
   bytes DESIGN §5's table gives no codes of their own.
8. **A method sees codes, not characters-on-a-screen.** A live code
   (`\threads`) is ONE code that render answers at display time, so `size`
   counts it as 1 and `upper` passes it through. Resolving live codes in a
   method would make `size` disagree with what is stored, across the
   render/store boundary satellite_string's header draws.
9. **`to_number` is the literal's rule exactly** — same parse, same S0610
   sentence, no quiet trimming. `trim` is one dot away and asking for it is
   the program's decision.
10. **The number rows count their receiver.** `max(a, b)` is `x.max(y)` with
    the receiver as `a` — DESIGN §6.4's written-out form read literally.
    `power`, `truncate` and `sqrt` refuse naming M15's rounding rule;
    `split` refuses naming M16's list; `modulus` runs and shares S0601 with
    `%`, one rule in one row. `clamp` keeps bignum.hpp's documented
    low-wins-when-backwards rule — its own comment predicted this milestone
    would arrive with the span to refuse at, and the decision taken is that
    a documented deterministic answer beats a refusal added after the fact.
11. **A shift count must fit a machine word.** Not a limit: a count silently
    truncated into `unsigned` would be a wrong ANSWER, and that is the
    difference between a bound and a lie. Everything under the cap is
    memory-bound, per NO_LIMITS.
12. **An interrupt exits 130 from both halves.** The orderly half (statement
    boundary, S0730, drained console) and the escalation half (second SIGINT,
    `_exit` inside the handler) answer the same number, so a script cannot
    tell how hard Ctrl-C was pressed and does not need to.
    `system_facts/interrupt.hpp` owns the number; `machine.hpp`'s `Ending`
    note owns the argument that an interrupt is neither a malformed program
    nor a machine limit. `programs/opening.cpp`'s usage text now says all
    five statuses plus this one.

## 3. What building it found

1. **words.def's paren annotations count two ways, and the fold now tries
   both.** A string row names its WRITTEN arguments — `find(x)` is
   `s.find(needle)` — while a number row names the written-out form, receiver
   included: `abs(a)` is `n.abs()`. The selector-call fold in
   `name_resolver/names.cpp` matched written count only, so every
   receiver-named number method failed to fold (`n.abs()` compiled to a
   refusal) while every string method worked. The fix tries the written
   count first — the surface-true reading — and the written-out count
   second; no type names one word at both counts today, and the comment at
   the fold is where to look the day one does. **WORD_NUMBERS may want a
   sentence about the two conventions; that edit is the author's.**
2. **"Is the receiver NOT a language word" was the wrong test, and the first
   smoke run caught it.** An intermediate segment like the
   `satellite.console` under `display` carries no path of its own, so the
   first cut of `method_receiver()` read every module call as a method call
   and the module road was never taken. The keeper test is positive: a
   method call's receiver IS somewhere — a frame slot, or a global this
   program declared.
3. **The one-hop boundary now has a user-facing surface, and it says what to
   do.** `f().trim()` and `"42".to_number()` both parse and both refuse:
   resolve folds a selector only through a declared name (names.cpp's
   documented boundary, WORD_NUMBERS §1.5), so the refusal names the fix —
   *"name the receiver first."* A literal's type needs no inference and
   folding it is a candidate widening for a later milestone; it was not
   taken here because it is an edit to resolve's stated boundary, and that
   boundary's paragraph says why it is where it is.
4. **`op_method_global` is emitted by nothing today, and saying so is the
   honesty.** A global is created by assignment (`satellite.library.x = 1`)
   and carries no declared type, so no selector can fold through one. The
   arm exists because it is the local arm with one line changed, and the
   day globals are declared with types it is the difference between working
   and a hole; `tests/eval_test` cannot reach it and does not pretend to.
5. **Module-constant reads moved a refusal from compile time to run time,
   and the trade is recorded.** The Member arm used to emit `op_refuse`
   naming M11 for every language path read bare; it now emits `op_dispatch`
   with no arguments, which is what makes `satellite.bool.true` answer. The
   cost: a path nobody has built — `satellite.console.width` until M14 —
   now answers S0721 "a later milestone" at run time instead of a compile
   refusal naming M14. The S0721 sentence is honest and the caret is the
   same; a row that knows its milestone (like `split` → M16, `sqrt` → M15)
   can always be installed to say more.
6. **Interrupt checks live in exactly three arms.** `op_block` between
   statements, `op_while` and `op_for` once per iteration — every statement
   passes through a block and every iteration through its loop's step, so
   these three are v1's "every statement boundary" with nothing double
   checked. The cost is one function-pointer call and one relaxed load per
   boundary, and the `Policy.interrupted == nullptr` default short-circuits
   even that for every machine nobody is listening to.

## 4. The seam that made the interrupt testable

`Policy` gained `bool (*interrupted)()` beside the ceiling and the division
digits — handed in, never read. `programs/built_program.cpp` wires
`interrupt_requested` in for `satl file.satl` AND `satl --call` (both install
the handler and clear the flag first, so a Ctrl-C during a slow compile
belongs to the run and not to a walk that has not started);
`tests/eval_test/interrupted.cpp` hands in a counter and proves the machine's
half — *the walk stops itself at the next statement* — deterministically,
with no fork, no sleep and no signal. The kernel's half (no `SA_RESTART`, the
escalation, delivery) is v1's code ported whole, and §5's transcript is the
end-to-end run.

## 5. How it was checked

**All ten suites pass**; eval_test gained two sections and reporter_test's
row count moved from 70 to 78 with the account beside it.

- `tests/eval_test/scalars.cpp` installs the REAL rows (PLAN M2's rule: a
  registry gets a reader in the milestone that writes it), asserts the
  install count (33), and walks the sixteen and the twelve running number
  methods by answer — including mutation across a `while` loop, which is
  QUAD's `sstream` shape — and the refusals by code: S0713 both ways, S0714,
  S0715, S0716, S0718, S0719, S0610 and S0601 shared, and the two
  milestone-naming rows.
- `tests/eval_test/interrupted.cpp` proves the fourth `Ending`: a `while`
  with no way out ends `Interrupted` with S0730; `for (;;)` likewise; the
  ending is neither `Finished` nor `Stopped` (`at_the_ceiling()` false —
  the exact confusion PLAN's M10 entry named); a flag that never rises costs
  a program nothing; a null listener is the default everywhere else.
- **The real code path**, at a real terminal:

      $ satl loop.satl & kill -INT $!
      looping
      SATELLITE: CTRL+C RECEIVED: QUITTING
      satl: loop.satl:7:11: error S0730: the run stopped here, at the first
      statement boundary after Ctrl-C arrived -- everything before this line
      ran and nothing at or after it did
         7 |         n = n + 1
           |           ^
             in satellite.main
      $ echo $?
      130

  The program's output is ABOVE the caret because the console's four-step
  shutdown runs before the diagnostics print — M10's ordering, doing its job
  for M11's new ending.

- `example/scalars.satl` is the acceptance file: every statement form, both
  module constants, a method from each family, mutation in a loop; fourteen
  lines and exit 0.

## 6. What it left open

1. **The runtime dial was not built, and PLAN §8 expected it here.** M8's
   entry says *"M11 is still where a program can retune the dial at run
   time"* — assignment to `satellite.library.system.division_digits` from
   inside a program. M11's own entry never claimed it, no document says what
   an assignment to a language path MEANS (the Assign arm knows frame slots
   and declared globals), and inventing that meaning mid-milestone seemed
   worse than saying so. **The author decides: a small follow-up here, or
   the sentence in M8's entry moves to a later milestone.**
2. **`satellite.bool` read bare answers S0721 "a later milestone", and no
   later milestone owns it.** A namespace read as a value has no obvious
   answer; if that is its permanent state, the sentence could say so.
3. **Method-on-literal** (`"x".size()`) — the candidate widening §3.3
   records. Costless to a program today (name the receiver), worth deciding
   before M14 hands programs strings they did not write.
4. **The two paren-counting conventions in words.def** (§3.1) — whether
   WORD_NUMBERS records them, and whether new rows should pick one.
5. **`example/bare_main.satl` and `console.satl` still carry M10's shape**;
   nothing here changed them, deliberately — they are M10's acceptance files
   and its milestone note cites them.

## 7. What it cost, measured

`make startup STATIC=full`, 2026-09-03, load 0.93, against M10's baseline —
**one milestone this time, which is §9's rule actually being kept.** Every
delta is inside the noise (widest: `--limits` at −0.023); satl's own share is
0.229 against M10's 0.222 after a new module, an interrupt handler and two
evaluator arms, because none of it runs before an arm is chosen. **The two
new rows are the milestone's**: `satl example/console.satl` at share 0.461
pays the row M10 was owed and upholds its written-first prediction — a whole
run with printer thread and four-step shutdown underruns `--call
frames.satl`'s 0.564 — and `satl example/scalars.satl` at 0.811 is M11's
consumer over 25 cached dispatch sites. `make_support/startup.rows` carries
the full table and both accounts.

**Counted at this landing: 221 C++ files, 35,501 lines over `src/` and
`tests/` (149 files and 24,651 lines of it `src/`), `words.def` at 551,
`errors.def` at 688.** The ten new files over M10 are the five of
`satellite_scalars/`, the two of `system_facts/interrupt`, one evaluator arm
file, and the two new test sections.

## 9. The prototype review this file replaces

Until this landing, `M11.md` held the 2026-08-29 review of `prototype/M9` —
a standalone sketch, never sources, reviewed because *"what a sketch got
right is what M11 will not have to rediscover."* The debt is now collectable,
so: **what it got right** — statement closures over a dispatch table, SIGINT
via a flag without `SA_RESTART` checked on statement boundaries with exit
130, and all sixteen string methods behind one table — is exactly the shape
this tree built, independently and with the numbering the sketch did not
have. **What this tree refused to inherit**: the sketch's `&`, `|` boolean
operators (DESIGN §6.6 deliberately has no logical row — §13's open
question), its bare `true`/`false` literals (the language spells
`satellite.bool.true`, a module constant), and its string ordering
comparisons (`<` orders numbers and nothing else, S0712). The full review
text is in this file's history at `3d7e272` and before.
