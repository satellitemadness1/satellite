# M5 — the error reporter

**Landed 2026-08-30** (`bb5d3ca`), the same day as M4 and M4.5, and against
[DESIGN.md §9](../DESIGN.md), which is one line of specification —
`{ ErrorCode, Span, vector<Note>, vector<FrameRef> }`, *"with rendering in
exactly one place"* — and a page of argument for why it is built **before** the
evaluator rather than retrofitted onto it.

**Verdict: done.** Every clause of PLAN's M5 paragraph has code behind it,
`make` and `make test` are green across **five** suites under both clang and
g++, and three open items that had been carried since M3 are closed. §6 lists
what is left; **§5 is the one a reader should not skip**, because it is the
thing this milestone found that no document had asked about.

---

## 1. What the milestone was

PLAN: *"Codes, spans, a source excerpt with a caret, notes with their own spans,
and 'did you mean' over the trie level that failed. Every milestone after this
reports properly from its first commit. Retrofitting this is exactly how the
first satellite ended up with 200 bespoke message sites."*

DESIGN §9 counts the thing being avoided and the count is worse than the round
number: **199 `fail()` call sites composing 224 distinct string literals**, with
no codes, no call stack and no suggestions. §9 also credits what v1 got right —
it *did* have a source excerpt and a caret — and that credit is the sharpest
part of the specification, because v1 had **three** `format_error`
implementations, one each for parse, resolve and evaluation, and its own header
admits they *"render nothing alike"*. The hard part was never drawing the caret.

**The done-when is `satl --check`.** A file that is fine produces nothing on
either stream and exits 0; a file that is not produces one block per problem on
stderr, nothing on stdout, and exits 1. That is a command a Makefile, an editor
or a pre-commit hook can use without parsing anything, which is what
`--unparse > /dev/null` is a spelling-by-accident of.

## 3. Four things no document settled, decided here

### 3.1 A code's number is a COLUMN, and a word's number is a POSITION

The two registries in this tree now encode their numbers in opposite ways, and
that reads as an inconsistency until the reason is written down —
`errors.def`'s header is where it is.

A word's number is **what a program means**. DESIGN §4.3 freezes registration
order because inserting a row silently renumbers every sibling and every
already-written program with it, so `words.def` makes a number a position and
a duplicate becomes *unrepresentable*.

An error code is **what a person looks up**. It has to survive a row being
deleted, has to leave gaps where a milestone reserved a block, and has to be
assignable out of order. Those are the opposite requirements, so they get the
opposite encoding — and what replaces "unrepresentable" is
`words_invariants.hpp`'s trick pointed at this table instead: the numbers must
**ascend**, which catches an insertion, and `text_of`'s switch catches a
duplicate as `error: duplicate case value` naming both rows.

**The first two digits say who is complaining**, which is what makes a code
worth four digits rather than two: `S01xx` the lexer, `S02xx` the parser,
`S03xx` the cache, `S04xx` the file satl was given, and `S05xx`/`S06xx`/`S07xx`
**reserved** for M6's resolve, M6.5's numbers and the evaluator. A reserved
block costs nothing and stops two milestones reaching for the same number on the
same day; `tests/reporter_test/codes.cpp` asserts the reserved ones are still
empty, which is what makes reserving them worth anything.

### 3.2 The arity is counted from the sentence, and checked at the call site

`errors::make<Code::X>(span, a, b)` is a **template on the code**, so the arity
is a `static_assert`: a site that hands two arguments to a three-hole sentence is
a compile error naming the code.

**This is the check the first satellite could not have had at any price**,
because there the sentence *was* the argument. It is also why the arity is not a
column in `errors.def` — it is the highest `{n}` in the text, computed at
compile time, so there is no second place the same fact lives and no column to
go stale. `holes_are_dense()` is the assert that matters: a sentence rewritten
from `"{1} under {2}"` to `"{2}"` keeps arity 2 and silently ignores whatever the
site passes first, and there is no way to see that by reading either half alone.

### 3.3 A `.satc` diagnostic carries no span

The machinery is right there and deliberately unused. A `.satc` is not a file
the user wrote — `read.cpp`'s own argument — so what they can act on is the file
as a whole, which is what the location line already names. A caret pointing at
byte 412 of a generated file tells somebody to read a file the next sentence
tells them to delete.

### 3.4 A note is a row in the registry, not a string at the call site

This is the half easiest to exempt, and exempting it would put the 224 literals
back at a quarter of the volume and with none of the visibility.
`NOTE_OPENED_HERE` is attached by ten call sites and belongs to none of them;
`NOTE_SATC_IGNORED` was a suffix that four sentences in `read.cpp` each
remembered to append.

**One consequence worth stating**: a note has a code, and the code is printed.
`note S0290:` reads slightly heavier than `note:` and is worth it, because a
note is as lookup-able as an error and a reader should not have to learn which
half of a message they are allowed to search for.

## 4. What building it found

### 4.1 A transposition is one edit, and plain Levenshtein loses `while`

**The single most consequential line in the module.** `wihle` against `while` is
**two** edits under Levenshtein — a delete and an insert — which is over the
threshold for a five-letter word, so the one suggestion a person most often
wants is the one they would never get. Optimal string alignment scores it 1.
That is five extra lines in `suggest.cpp` and it is the difference between
DESIGN §4.6 being a feature and being decoration.

**The threshold is a rule and not a constant**, for the same reason: one edit,
plus one for every four characters. A fixed cap of 2 offers `for` for `if`
— three letters, two edits, and nothing about them alike — and a fixed cap of 1
refuses `argumentz` for `argumentts`.

### 4.2 §9's fourth field is built now precisely because nothing produces one

`FrameRef` has no producer until M7's evaluator. It is carried, drawn, and
rendered in the test with a synthetic frame anyway — and that is the **opposite**
of the call M4 made about a node's extent, on purpose. The difference is that
this is *in* §9's shape and that was not. Building three of §9's four fields and
adding the fourth when the evaluator arrives is exactly the retrofit this
milestone exists to prevent: rendering lives in one place, so a field that
arrives later arrives as an edit to that place, made by somebody thinking about
a stack trace rather than about every other message satl prints.

### 4.3 `gave_up()` answered by counting errors that had already been moved out

`parse()` called `parser.take_errors()` and then asked `parser.gave_up()`, which
answers by comparing `errors_.size()` against the cap — and `take_errors()`
**moves** the vector out. So a parser that had stopped at twenty always said it
had finished, and the note saying the rest of the file was not read was never
pushed. Found by the test that counts them: thirty bad statements came back as
twenty-one errors and no note. One line of ordering.

### 4.4 A tab is expanded to ONE space, and that is a decision

How wide a tab is depends on the terminal the output lands in, which satl cannot
know — so expanding to eight puts the caret under the wrong character on a
terminal set to four, and both are confidently wrong. One space keeps the
caret's column, the character's column and the number in the header the same
number, whatever the file is indented with.

The same paragraph covers two more the first satellite did not handle: a **UTF-8
continuation byte** is not a column, so a caret after an accented letter lands
under the right character; and a **carriage return** is not part of the line,
because left in the excerpt it returns the cursor to column 0 and the caret row
paints over the source it is pointing at.

### 4.5 A length floor is arithmetic wearing a judgement's clothes

An earlier draft asserted that every sentence is at least forty characters, on
the grounds that DESIGN §9's model sentence is fifty-two. It failed on
`{1} was declared here`, which is a perfectly good note, and on
`this did not parse: {1}`, whose fix is in the note beside it.

**No assert can see whether a sentence names a fix.** What replaced it is the
only thing about the wording that IS checkable: every message is rendered after
`satl: <where>: error S0231: `, so it opens lower case and ends without a full
stop. FORMAT/CXX.md §8's warning about `sizeof` arithmetic is the same failure
one register up, and `codes.hpp` now says out loud which of §9's requirements
the asserts do **not** cover.

## 5. What a message registry makes possible that bespoke strings did not

**This is the finding to carry forward.** Moving the parser's 23 message sites
out of it and into 22 rows of one file removes one class of defect and creates
another, and only the first is obvious. *(23 and not 22 because
`PARSE_EXPECTED_DECLARATION` is raised from two places — `top_level()`, where a
program reaches it, and `run()`'s cursor guard.)*

Removed: two sites saying the same thing in two ways, a message nobody can look
up, and a message that cannot be counted.

**Created: a site raising the wrong row.** The sentence renders perfectly, the
build is quiet, the code is a real code, and the message describes a different
problem from the one that happened. Nothing in `codes.hpp` can see it —
`text_of` is a switch over a code, not over a call site — and a test written
against the `Diagnostic` struct would pass.

`tests/reporter_test/parsing.cpp` is what catches it, and it is written the only
way that can: **one assertion of the form "this source produces this code" per
row of `errors.def` the parser owns**, all of them through `parse()` — nineteen
of the twenty-two, because three are not reachable from a program and the file
names which and why rather than leaving them looking forgotten. Two are the
*"no rule may leave the cursor where it found it"* guards in `block()` and
`suit_body()`, which `panic_` suppresses whenever a real rule has already
reported, so reaching one means a defect in the parser rather than a shape a
file can have; the third needs `words::Words::define()` to refuse a name
`find()` has just called free. All three stay, because a guard that fires is
worth a sentence rather than a crash.

That is the check to extend when M6 and M7 take their blocks, and it is the
reason this suite links the parser and the lexer rather than testing the
reporter against diagnostics it wrote itself.

## 6. What is left open

1. **One `Source`, not a map.** A Span says where in *a* file, and `satellite.include`
   at M21 makes a program more than one file. v1 grew a `SourceMap` and a file
   id in every span for exactly that; it is not built now because nothing can
   produce a second file, and `report.hpp` names M21 as the milestone that has
   to make the call. This is the same reasoning M4 used about a node's extent
   and is recorded so it does not have to be rediscovered.
2. **A node still has one token and not an extent**, so a caret underlines the
   anchor token and never a whole expression. M4.md §6 item 5 predicted M5 would
   want it; **M5 did not**, because the anchor is the token the message is about
   in all 24 sites — `a + ` points at the `+`. Left open with the answer now
   attached: whoever wants it should have a message that reads worse without it.
3. **A very long line is printed whole.** The caret is clamped to the line, so
   nothing is unbounded, but a 5,000-character line is 5,000 characters of
   output. A window around the span is the fix and no milestone owns it.
4. **The command line has no codes and that is a boundary, not a gap.**
   `errors.def`'s S04xx block says where the line is: a code and a span are for
   something inside a *file*, and `satl --frobnicate` has neither. `usage_error`
   and `not_yet` in `main.cpp` keep their own words.
5. **`satl --words` does not render through the reporter**, and
   `satellite_words/dump.cpp` now says why: a path typed on a command line is
   not a place inside a file, so a Span whose offsets index an *argument* would
   mean something different from every other span in the tree. What the two
   share is the **suggester**, which is the part that is actually one fact.
6. **The caret's clamp is bounded twice and only one of them is load-bearing.**
   A mutation removing the clamp on the span's END was caught by **nothing** —
   `columns_between` stops at the end of the text on its own. The clamp on the
   START is the one v1 hard-won and it is still the one that matters. Kept, and
   recorded here rather than deleted, because the next person to read that line
   should know which half is doing the work.
7. **`main.cpp` is 378 lines** and is past `unparse.cpp`'s 341 as the largest
   file in the tree. M5 moved two helpers and one arm out to
   `programs/check_command.cpp` and still added net lines, because it added two
   commands. The seam is real and is named rather than taken: `main()` is a
   dispatch over fourteen arms, and the four that take a **file** are one
   subject. M4.md §6 item 6 made the same call about `unparse.cpp` at 341, and
   M3 about `lexer.cpp` at 304.

8. **A failed top-level declaration cascades, and the reporter made it visible
   rather than causing it.** `satl --check example/class_test.satl` prints ten
   blocks: one real — line 4's `my_superclass():`, which M4.md §6 item 1 names —
   and **nine repeats of S0204** as `run()` meets each line of the spacesuit body
   at the top level and says a file holds four forms. The rule that stops this
   inside a statement is `panic_`, one error per synchronisation, and it does
   its job; what has no equivalent is a **declaration** that fails, because
   `synchronise()` recovers to the end of a line and a declaration is many
   lines. DESIGN §9's own warning is the description of it — *"a user reading
   twelve messages about one missing brace fixes the wrong thing first"*.
   **This is M4's recovery policy and not the reporter's**, and it was there
   before today; what changed is that ten blocks with carets are harder to
   overlook than ten one-line messages were. The fix is a `synchronise()` that
   skips to the next line beginning `satellite.` at column 0 when the failure
   was a top-level one, and it belongs to whoever next has a reason to care —
   most likely M6, which will be the second pass to want recovery.

## 7. What the test proves, and the mutations that prove the test

`tests/reporter_test/` is **132 check sites in five sections** — the registry,
the rendering, the suggester, the lexer's one error, and the parser's twenty-two,
of which §5 says which three a program cannot produce.

Every mutation below was made in an isolated copy of the tree, compiled, run
under `stdbuf -o0`, and reverted.

| mutation | caught by |
|---|---|
| the unclosed-bracket note not attached | 5 checks |
| a note drawn at the error's span instead of its own | 4 checks |
| a UTF-8 continuation byte counted as a column | 2 checks |
| the transposition arm removed from the edit distance | 1 check |
| the suggester searching the whole language instead of one level | 1 check |
| a tab left unexpanded in the excerpt | 1 check |
| the empty-spelling guard removed from the suggester | 1 check — **and 0 before this milestone added one for it**, §7.1 |
| the caret's END no longer clamped to the line | **0 checks**, and §6 item 6 says why that is the right answer |

### 7.1 The mutation that found a missing check

Removing the guard that skips a bare row's empty spelling was caught by
**nothing** on its first run. `words.def`'s 38 bare shapes and 6 argument rows
have an empty spelling by design and are never walked to by name — and
`satellite.container`'s empty child is declared **before** `list`. Without the
guard, `ls` matches the empty spelling at the same distance as `list`, wins on
being first, and then fails the threshold as a zero-length candidate: **the
suggestion is lost rather than made wrong**, which is precisely the regression a
suite that only asks for good answers cannot see. The check is
`suggest(CONTAINER, "ls") == "list"`, and it is in `suggesting.cpp` now.
