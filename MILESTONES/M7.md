# M7 — resolve: names to integer frame slots

**Landed 2026-08-31** (`e76443b`).

DESIGN §7 is the specification, [PLAN.md](../PLAN.md) §8's M7 entry is the
milestone and its done-when, and `src/name_resolver/` is what turned up. This is
a **review and not a plan** — what was decided on the way, what building it
found, what it left open, and which mutations prove its test.

`satl --resolve <file>` is the consumer. Six sources over three headers, one new
test of **114 check sites in six sections**, and one new acceptance program.

---

## 1. What the milestone was

DESIGN §7 calls scope *"the most important decision in the language, and the
first satellite's best engineering,"* and §7.1 is the receipt rather than the
claim. With one global registry keyed by `<capsule>.<variable>`, a capsule has
**exactly one slot per local for the whole program**:

- a recursive `fact` returns **1 for every input** — 1, 2, 3, 5 and 10 all yield
  1, because the base case's write is the last one standing;
- eight threads running a capsule with **no recursion and no shared state**
  produced **1585 wrong results out of 1600**;
- and it cannot be reframed as deliberate capsule-static semantics, because
  **parameters are locals too** and `arguments` would be a program-wide static.

§7.2's fix is per-call frames and integer slot indices decided **before anything
runs**, and it is 7.1× faster besides — 160 ms against 1131 for 200k iterations
of `fact(15)`. This milestone decides the indices. Nothing executes yet; M9
compiles the tree to closures and M10 runs one.

**The side table is PLAN §2.2's decision and not this milestone's convenience.**
`ast.hpp` has held the space since M4: *"`Name::slot`, which in the first
satellite is a `mutable int` on a `shared_ptr<const Expr>` held off by a comment
reading `resolve() must finish, on one thread, before any evaluation begins`,
becomes a side table indexed by node index — so the race is structurally
impossible instead of documented. M7 builds that side table."* It is built and
nothing in this milestone writes to the tree.

## 3. What was decided on the way

### 3.1 The trie walk already existed, and a second one was not written

DESIGN §6.3 says *"the trie walk that turns a path into a `PathId` happens once,
after parsing, in M7's resolve pass"*, and this milestone set out to write it —
**and it was already there.** `satellite_cache/paths.cpp`'s `language_path()`
flattens a postfix chain because §6.2 makes Member and Call peers, collapses
aliases first, and slots a call by **arity** rather than by the spelling of its
argument list. M4.5 wrote it to decide what a `.satc` may substitute.

That file opens **"THIS IS NOT RESOLVE AND MUST NOT BECOME IT"**, and it is right
about what it warns against: a version taking a *receiver* argument would be
resolve, and the `.satc` it wrote would name a handler, which SATC §7 forbids.
**Reading it is not that.** A second copy would be a second place a path's
identity is decided, and the two would disagree the day a row grows an argument
list — which is exactly the class of defect `paths.cpp` already records two of.

**What M7 added to it is one thing: where the walk stopped.** That function's own
comment has said since M4.5 that a path the numbering cannot account for is
*"M7's to refuse with M5's did-you-mean over the node the segment failed under"*,
and it could not say **which** node that was. `PathMatch` now carries `under` and
`at`, filled on the one arm that fails, and the cache ignores both.

### 3.2 `satellite.main` can be declared twice and only resolve can see it

`Parser::define_name()` reports **S0242** for a second capsule of the user's own,
because `words::Words::define()` refuses to allocate one name twice. But
`capsule_decl`'s reserved arm **looks a name up** — `words_.find(SATELLITE,
"main")` — and the numbering has nothing to say about a name it did not
allocate. So a file with two `satellite.main`s **parses clean and has two entry
points.**

Pass 1 is the only place that can notice, so **S0514** is a row this milestone
added beyond its done-when, with **S0590** attached to the first declaration. The
second capsule gets no frame, so `satl --resolve` does not print a file with two
entry points as though it had them.

### 3.3 DESIGN §7.7's open question, answered — and it is a rule and not a spelling

§7.7 asks: *"Which spellings, exactly, and what happens to the seventh? Declaring
a parameter named `argv` gets a plain list with no properties, silently. Under §9
that silence is wrong — the language should say so."*

**It is said, and only where somebody plainly meant the object.** The condition
for refusing is that `errors::suggest()` over `satellite.library.main`'s children
and aliases comes back with one of the six. `argv` is one edit from `arg` and is
refused; `input_lines` is nowhere near any of them and is an ordinary list, which
is exactly what §7.7 says the language does — *"it does not introduce
`arguments`, it recognises the name the user chose."*

**A rule and not a seventh alias.** Adding `argv` to `words.def` would make it
work, and that is an edit to the numbering — WORD_NUMBERS.md is the authority and
it is the author's decision, not a milestone's to take in passing.

### 3.4 Only `satellite.main` gets the arguments object

The M6 draft recognises the six spellings **in every capsule**. This resolver
recognises them in `satellite.main` and nowhere else, and that is a decision
rather than a narrowing: §7.7 puts the object at
`satellite.library.main.arguments` and describes it as *"the language handing the
PROGRAM everything it knows about the machine it woke up on."* A capsule of the
user's own with a parameter called `args` is holding whatever its **caller**
passed, and giving it the machine's answers instead would be DESIGN §1.1's
*"behind their back"* with the wrong value in the variable.

### 3.5 The fold reads the numbering, so M19 gets it for free

PLAN's M7 bullet says *"M19 is waiting on this: whether `satellite.file.open`'s
four mode words fold decides whether its bad-mode message is M5's suggester or a
runtime check."* The answer is **the suggester**, and no edit to any source file
is needed on the day M19's rows land.

The fold is not a table of special cases. **A word takes options when the rows
beside it are spelled `<word>_<something>`** — `sort` has `sort_down` and
`sort_up`, so a literal first argument to it names one of them; `contains` has no
such sibling, so `contains("ok")` is an ordinary call with a string in it. The
legal options in **S0524**'s sentence are those siblings with the prefix
stripped, so `words.def` gaining `open_read_append` makes
`satellite.file.open("read_appnd")` answerable here with nothing else changed.

### 3.6 Three sentinels and not six

The M6 draft defines `SLOT_GLOBAL`, `SLOT_CAPSULE`, `SLOT_METHOD`, `SLOT_SUIT`,
`SLOT_FIELD` and `SLOT_ARGUMENTS`. Three of those are spacesuits' and are M26's.
The fourth, `SLOT_ARGUMENTS`, **is never assigned by that draft either**:
`arguments` is a parameter, so it takes a real slot like every other parameter,
and the flag saying which one it is rides beside the slot.

A sentinel with no producer is a case every later reader has to rule out. M5
carries `FrameRef` with no producer for a reason it argues at length — it is *in*
DESIGN §9's shape, and building three of four fields is the retrofit that
milestone existed to prevent — and this is not that reason.

### 3.7 `main.cpp`'s seam, which M6 named and declined

MILESTONES/M6.md §6.1: *"the arms that DUMP a registry (`--words`, `--errors`,
`--limits`) and the arms that read a FILE (`--tokens`, `--unparse`, `--satc`,
`--check`) are two subjects, and splitting them is a reshaping of M2 through M5's
arms rather than of this milestone's."* It was right to decline and it was also
counting: `main.cpp` was **427 lines**, 127 over PLAN §3's target, and M7 adds a
fourteenth arm to the same switch.

Taken here. `programs/dump_commands.cpp` and `programs/file_commands.cpp`, and
**every comment moved unchanged** — each was written by the milestone that added
the arm, including M5's two corrections to them, and rewriting them while moving
them would have thrown four milestones' reasons away in a commit about line
count. `main.cpp` is **297 lines** and is the dispatch it was meant to be.

What the two subjects *are* is now written down once, in `dump_commands.hpp`: a
registry dump takes no operand or a key into itself, answers out of tables
compiled into the binary, opens nothing, and cannot fail about the user's
program; a file arm takes a path, reads a file that may not exist, and has a
status about what was in it.

### 3.8 SATC.md §4's reading order is a function now

`satl --resolve` needs the same three steps `--satc` does, for a different reason
— it wants the tree and the numbers the file already carried. A second copy of
*which check runs first* is the thing `read.cpp`'s own header says the module
exists to have exactly one of, so `read_program()` came out of `satc_command()`
and both call it. M10 will be the third caller and will want neither of their
outputs.

## 4. What building it found

### 4.1 A diagnostic cannot be drawn into a `.satc`, and this is the first pass that could

A `.satc` is written from a tree that **parsed** — `cache_command.cpp` refuses to
cache anything else — and **resolve is the first pass that can find something
wrong in a tree that parsed.** So a program with an unknown name in it is cached
on its first run and read back on its second, and the tree that comes back has
spans into the `.satc`'s **words**: no comments, blank lines where the writer put
them, and line 6 of that is not line 6 of the file the user wrote.

Measured on `example/hello_world.satl`: the same `satellite.console.display` is
**line 7 of the source and line 5 of the cache.**

A caret drawn from those spans lands on the wrong line of the right file, which
is worse than no caret. **So a warm run that finds a problem is thrown away and
taken again from the source**, and says so on stderr. The cost lands only on a
program that is already broken — and a broken program is one somebody is editing,
which invalidates the `.satc` on the next save anyway. errors.def's S03xx block
makes the same call about the same file: *"a caret pointing at byte 412 of a
generated file tells somebody to read a file that the next sentence tells them to
delete."*

The **dump** takes the weaker step, because a table can be qualified where a
caret cannot: on a warm run its line column says `the lines are the `.satc`'s,
which is what was read`.

### 4.2 §7.3's third pass is "top-level statements" and this grammar has none

DESIGN §7.3 orders the passes as *every capsule name, every spacesuit name, top
level statements, then each body*. DESIGN §6's `top_level` is include, capsule,
spacesuit and global — and the parser's **S0204** says so in the words a user
reads: *"a statement at the top of a file is not an unfinished feature, it is a
program with no capsule to run."*

So what pass 3 actually resolves is the two forms that can carry an expression
outside a body: a global's initialiser and an include's argument. **The pass
keeps its place, because §7.3's ORDER is what matters** — a global read by a
capsule body has to be numbered before pass 4.

**And the M6 draft's step 6 had to go with it.** That resolver answers
`SLOT_GLOBAL` for any unknown name met outside a capsule, which is right for the
grammar it was written against and wrong for this one: an unknown name in a
global's initialiser is unknown. `satellite.library.total = missing` is **S0511**
here and a silent global there.

### 4.3 A keyword the parser consumed is syntax, and resolves to nothing

The done-when says *every path in the file*, and a `.satc` numbers more paths
than resolve does: `#1.2` for `satellite.capsule`, `#1.13.1` for
`satellite.statement.if`, and `satellite.protected` and `satellite.public` inside
a suit. **None of them is resolved and none of them should be.**

`unnumber()` and the writer are a **text substitution over words**; they number
those because they are words. What resolve produces is an identity something can
dispatch on, and nothing dispatches on `satellite.statement.if` — DESIGN §6.1
puts that decision at **parse time**, on segment 1, and the parser has already
made it. A number recorded here that no consumer reads is the thing §3.6 refuses
one paragraph up.

**So the clause is narrower than it was written**: every path a *name or a type*
in the file resolves to. PLAN §8's entry says so.

### 4.4 The `.satc` skip keys on where the words END

Both offsets identify a substitution; only one lines up with a node. A chain's
**root** is the same token for `satellite.time.now()` and for the
`.some_function()` wrapped around it, so keying on where the substitution began
would hand the outer node the inner one's number. Every node that names a path is
anchored at the path's **last segment** — `ast.hpp`'s *"the token that NAMES the
node"* — so the end of the substituted words belongs to exactly one node,
whichever node that turns out to be.

**And the argument list is not part of it.** A row may keep its parentheses when
the words are written back — `input()` is `1 5 2` and the number says its own
brackets — and those characters belong to no node's anchor.

### 4.5 The three unbounded tree walkers, and only one of them is now bounded

`resolve.hpp`'s depth guard fires at 2000 and holds. Two other walkers in this
tree have none, and both can be made to segfault. Measured on this machine,
`ulimit -s` 8192, one expression nested N deep:

| N | `--check` | `--unparse` | `--satc` | `--resolve` |
|---|---|---|---|---|
| 2100 | ok | ok | ok | **S0501, refused** |
| 18000 | ok | ok | ok | S0501 |
| 19000 | ok | **segfault** | ok | S0501 |
| 20000 | ok | segfault | **segfault** | S0501 |

The parser survives all of them. `abstract_syntax_tree/unparse.cpp` and
`satellite_cache/write_expressions.cpp` do not. **This is not M7's to fix** —
they are M4's and M4.5's printers, the fix touches two other milestones' modules
and their tests, and the structural version of it is a bound in the *parser*, so
that no such tree can exist for any consumer. §6 carries it as an open item.

What M7 can say is that resolve is the one walker in the tree that cannot be made
to do this, and that its bound is **not** DESIGN §7.5's — §7.5 bounds a program
that is *running*, derives its ceiling from `RLIMIT_STACK`, and is M9's, which
`system_facts/facts.hpp` already says in its own words.

### 4.6 Four passes do not produce errors in source order

Pass 1 sees a capsule declared twice on line 14 and pass 4 sees a parameter
declared twice on line 3, so the order problems are **found** in is the order of
the passes and not of the program. The lexer and the parser get source order for
free by walking forward once; this pass has to ask for it. One `stable_sort` at
the end of `run()`, rather than a rule every site has to keep — and stable, so
two problems on one line stay in the order they were found, which is the order
somebody would fix them in.

## 5. The clause that is counted and not timed, and why the draft's version was wrong

`SCRATCH.md/M7_START.md` offered a draft done-when whose last clause read: *"and
resolve **skips a path the `.satc` already numbered**, measured — a warm hit
beats `--unparse` on hello_world."*

**That comparison cannot be won or lost, because the two commands do not do the
same work.** `--unparse` does not resolve anything, so it is not doing the work
the skip saves. What MILESTONES/M4.5.md §5 actually measured is that a warm hit
*reads a larger file, runs the substitution back, and then lexes and parses
exactly as `--unparse` does* — strictly more work, and the skip does not change
any of it.

**And the honest comparison — warm `--resolve` against cold `--resolve` — is
under the clock's noise at this size.** §5's own table is what says so: a warm hit
and `--unparse` differ by 0.03 ms on a 273-byte program, and the walk is a
fraction of that.

So the clause is **counted**. `satl --resolve` prints how many paths it walked
and how many it took from the file, and `tests/resolve_test/cache.cpp` asserts
both. On `example/frames.satl`: **28 walked cold, 14 walked and 14 taken warm.**
On `example/advanced.satl`: **11 cold, 3 and 8 warm.**

**A count is also the only thing that can catch the skip disappearing.** A
resolver that stopped reading the marks would still produce every correct number,
because the walk is the fallback and the fallback works. §7 is the mutation that
proves that is not a hypothetical.

## 6. What is left open

1. **`sort("up")` has no row to fold to, and that is the numbering's to answer.**
   WORD_NUMBERS §2.2 assigns `sort()` `1 4 2 3` as *"ascending, no key"* and
   `sort_up(key)` `1 4 2 7`, and there is **no `sort_up()`** — because `sort()`
   already is it. So `my_list.sort("up")` gets **S0523** naming `sort_up(key)`,
   which is accurate and is not what somebody wanted. Two fixes exist and both
   are the author's: an alias row spelling `sort_up()` onto `1 4 2 3`, or a rule
   that a fold may land on the bare word it was spelled from. This milestone
   refused to pick, because either is a decision about the numbering.
2. **`unparse.cpp` and `write_expressions.cpp` can be made to segfault** — §4.5
   has the measurements. The structural fix is a nesting bound in the **parser**,
   so that no consumer can be handed a tree it cannot walk; that is one place
   instead of three, and it is a new S02xx row and a change to what the parser
   accepts.
3. **A statement form is never skipped from the `.satc`.**
   `satellite.include(satellite)` is an Include node anchored at the **reserved
   word** rather than at `include`, so the mark's offset belongs to no node's
   anchor. It is derivable — the parser advances `satellite`, `.`, `include`, so
   the word is at `token + 2` — and it was left alone because a node reaching
   into the token stream by a fixed offset is a rule the grammar can break
   silently. Two paths per program.
4. **No arity check on a call.** Resolve knows every frame's parameter count and
   could refuse `factorial(1, 2)` statically. It is not in the done-when and it
   needs two decisions DESIGN has not taken: what a variadic call shape is
   (WORD_NUMBERS §4 has the variadic split open), and what happens when a call
   goes through a variable. M9's `FrameRef` is where a call gets a shape.
5. **No type checking, deliberately.** This pass asks whether a name has
   somewhere to live and whether a path is a path. `satellite.variable.number x =
   "a string"` is DESIGN §8's value model and is M9's, and generic arity —
   `map<x>` with one argument — is the same. The M6 draft checks both here and
   had to invent the rules to do it, including which types may be a map's key.
6. **One hop, and no further.** A selector resolves when the receiver is a name
   whose declaration this pass just read: `my_list.size` is `1 4 2 2`,
   `f().size` is not, because what `f()` returns is M9's. WORD_NUMBERS §1.5
   describes the general case and this is the part of it available without a
   value model.
7. **Spacesuits are M26 and pass 2 is a hole with a name.** The M6 draft's
   `resolver_suits.cpp` — 248 lines of inheritance links, cycle breaking,
   flattened field layout, method tables and access checking — is 40% of that
   draft and every line of it is a decision about what a spacesuit **is**.

## 7. What the test proves, and the mutations that prove the test

`tests/resolve_test/` is **114 check sites in six sections**. Every row of
`errors.def`'s S05xx block is reached from a real program through `resolve()`,
which is the rule `tests/reporter_test/parsing.cpp` established and SESSION.md
§5.20 is the reason for: **a site that raises a neighbouring code renders
perfectly and no assert can see it.**

Eight mutations were run. **Seven were caught immediately; the eighth and a
ninth were not, and both were real gaps.**

| mutation | caught by |
|---|---|
| §7.4: reuse the slot on a redeclaration | 2 — including `frames.satl`'s two `counter` rows |
| the **chain** half of the `.satc` skip disabled | 2 |
| the **type** half of the `.satc` skip disabled | 1 |
| the depth bound raised past the C++ stack | 2 (and the process no longer segfaults only because the test's fixture is 2200 deep) |
| §7.7 recognised in every capsule (the M6 draft's rule) | 2 |
| WORD_NUMBERS §1.5's fold removed | 6 |
| the initialiser resolved **after** the name enters scope | 1 — `number x = x` |
| a bad path accepted in silence, **Member arm only** | **0, then 2** |

### 7.1 The two the mutations found

**The eighth walked straight through.** Deleting the refusal from `member()` left
every assertion green, because every fixture in `paths.cpp` happened to end in a
**call** and was therefore refused from `call()`'s arm instead. DESIGN §6.2 makes
Member and Call peers and a path is asked about at whichever node ends it, so
there are two sites and only one was covered. `satellite.consle.width` — a chain
with no call on it — is the fixture that closes it.

**And strengthening `section_cache` found a defect in the code, not the test.**
The first version asserted the **totals**: `from_cache > 0`, `walked < cold`, and
the two adding up. Disabling half the skip walked through all three, because the
other half still moved every number in the right direction. Asserting the origin
**per path** — one chain, one type, one call shape — is what catches either half
alone.

Doing that failed immediately, and not on the mutation: **`unnumber()`'s
`word_length()` had its ternary inverted.** Written as `arity > 0 && !absorber ?
whole : whole - args.size()`, it returned the **full** length for exactly the
rows `path_source()` shortens, so every call shape's mark landed 16 characters
past the word it belonged to and matched no node.

**The effect was silent, one-sided and correct.**
`satellite.console.display` skipped and `satellite.console.input(prompt, target)`
did not, and **every number in every program was still right**, because the walk
is the fallback. `example/advanced.satl` went from *3 walked and 8 taken* to *8
walked and 3 taken* the moment it was fixed. Nothing but a per-path assertion
could have seen it, and the totals version of the test would have shipped it.

### 7.2 The one the numbering caught, before any of this ran

Adding **S0514** between S0512 and S0513 failed the build, on
`codes.hpp`'s `numbers_ascend()` static_assert, naming the line. That is the
check errors.def describes as *"what replaces `a number is a position` as the
safety net"*, doing exactly that on its first real insertion.

## 8. What this closed elsewhere, and what it did not

- **`errors.def`'s S05xx reservation was honoured end to end.** M5 reserved the
  block, M6 landed in between and took S08xx rather than the next free number,
  and M7 took S05xx **with nothing moving to make room** — no row renumbered, no
  block split. `tests/reporter_test/codes.cpp`'s reserved-blocks loop lost one
  number from it and that is the entire edit. The file has argued for reservation
  since M5; this is the first time it happened.
- **`words_runtime.hpp`'s `find()` was two milestones stale.** It said *"DESIGN
  §2's reservation rule is decided at M7's resolve"*; M4 decided it, in the
  function above, and reports **S0241**. What M7 actually decides is the one case
  left — a **local** called `satellite`, which the parser accepts because
  `satellite` is a legal `primary` and only a scope can refuse. **S0513**.
- **MILESTONES/M4.5.md §5's carried clause is closed.** It was written in three
  places on purpose; all three now point at something built.
- **PLAN §9's rule ran itself.** `make startup` took M7's measurement, diffed it
  against M6's baseline, and reported no regression — the first milestone this
  has been true of. satl's own share is **0.179 ms against M6's 0.168**, and the
  0.011 ms is six new translation units in the image the loader maps, not the
  pass: the resolver does not run unless `--resolve` asks for it, so `--version`
  cannot be paying for it. `make_support/040-sources.mk` has the table.
- **What it did not close** is `example/class_test.satl` and
  `example/gui_example.satl`, which still do not parse. Both constructs are the
  files' rather than the parser's (MILESTONES/M4.md §6) and neither is resolve's.
