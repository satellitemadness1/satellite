# M10 — the console, and the first program that runs

**Landed 2026-09-02** (`PENDING`).

[PLAN.md](../PLAN.md) §8's M10 entry is the specification and it was rewritten
by the author on the morning of the day this was built — `3d7e272`, "the printer
owns its thread, and the block is the first step of the shutdown", a
documentation-only commit that settled two things before a line of code existed.
[DESIGN.md](../DESIGN.md) §10.1 is the console, §3 is what `satellite` means as
a value, and §8's type table has had a row for it since the document was
written. This is a **review and not a plan** — what was decided on the way, what
building it found, what it left open, and which mutations prove its test.

**One new module, four new files of `src/`, four of `tests/`.**
`satellite_console/` is the queue, the printer thread and the four-step
shutdown; `programs/run_command.*` is `satl file.satl`; `programs/built_program.*`
is the four passes, moved out of `evaluate_commands.cpp` when the third arm
needed them. **And satellite executes:**

    $ satl first.satl
    Hello, World!
    $ echo $?
    0

---

## 1. What the milestone was

**Three things, and none of them is hello world.**

1. **The console.** DESIGN §10.1: whole strings into a locked queue, one printer
   thread out, a `drain()` barrier. It is the first thread in this tree that
   belongs to a program rather than to the machine.
2. **`satellite.main` and `satellite.return`.** Where a program starts, and the
   three shapes it can end with — `return()` `1 15 0`, `return(satellite)`
   `1 15 1`, `return(value)` `1 15 2`. The middle one needed `satellite` to be a
   value, which is a fifth arm on M9's variant.
3. **`satl file.satl`.** The arm this binary has been pointing at since M1, and
   the reason `programs/opening.cpp` has carried a paragraph apologising for
   itself for ten milestones.

**Its done-when was going to be prose, and the author closed that on the day.**
§8's M10 entry had said since it was written that *"`example/` holds no bare-main
program, so this milestone has no acceptance file yet; writing one is the
author's"* — and two arrived on 2026-09-02: `example/console.satl`, which prints
`hello!` and exits 0, and `example/bare_main.satl`, which prints nothing and
exits 0. **The second is not a lesser copy of the first.** A program that prints
nothing still takes the four-step shutdown, and a barrier that waited on a
printer nobody started would hang every one of them; `satl --compile` says the
difference in one line — `0 call sites with an inline cache` against 1.

**What a file cannot show is inside the console**, so `tests/console_test` takes
the four claims that have no surface: a line stays atomic across eight threads,
nothing queued is lost, `drain()` means the bytes reached the descriptor, and the
row is found by its number. Four files, twenty-two check sites, and §5 below is
the mutation pass that says whether they hold anything.

## 2. What the author settled before it was built

**Both were settled on 2026-09-02, in `3d7e272`, and both were corrections
rather than choices.** Recording them here because a milestone whose shape was
decided the same morning it was built is one where nobody can later tell which
half was the plan.

**THE PRINTER CREATES ITS OWN THREAD.** Six places in the documents said it was
M6's pool's first tenant. The author: *"the plan was always that the printer
would create its own thread."* The rule that replaces it is one line in
`machine_limits/pool.hpp` — **that pool takes work that FINISHES**. `run_over()`
is a range, a split and a join; a printer waits on a queue for the life of the
run, so a resident tenant would hold a worker forever, `wanted()` and `parked()`
would go on counting it, and `satl --limits` would go on reporting a thread that
is never coming back. It was a category error and not a scheduling one.

**THE BARRIER IS A PREFIX OF THE SHUTDOWN.** The author: *"the block is similar
to a shutdown -- combine shutdown with the block."* Four steps — drain, flush,
stop, join. `satellite.console.input` takes step 1 and carries on (M14);
`satellite.return` from `satellite.main` takes all four. **What that buys is that
the barrier is not speculative three milestones before anything reads input**:
the same wait is on the exit path of every program that prints, so M10 has a
consumer for it on the day it is written.

Both are in the code as written. `console.cpp` includes no `pool.hpp`, and
`shutdown()` is four numbered steps with `drain()` as the first, public on its
own for M14.

## 3. What was decided on the way

### 3.1 `satellite` is a fifth arm, and it cost no bytes

DESIGN §8's type table has thirteen rows and the last is **`satellite` | the
runtime singleton | `satellite.return(satellite)`**. M9 built four arms and its
header says why: *"an arm with no producer is a case every later reader has to
rule out ... so the rest arrive with the milestone that can build one."* M10 is
that milestone for this one, so `Runtime` was appended — at the END of the list,
which is v1's append-only rule kept — and `sizeof(Value)` did not move. An empty
struct in a variant whose widest arm is 32 bytes is free, and the `static_assert`
that would have caught a mistake did not fire.

**Which is why `satellite.return(satellite)` needed no case of its own.** The
three return shapes are resolve's numbering and what separates them is what the
ARGUMENT is; `compile_expressions.cpp`'s `NodeKind::Satellite` arm emits a
constant, and the statement half never learns there was anything special about
it. A compiler that special-cased the middle shape would be deciding a path's
meaning in two places.

**And it is not `Nothing`.** Two empty structs in one variant look like waste
until a program can tell them apart: a capsule that answered `satellite` said it
succeeded, and one that answered nothing said nothing. `type_name` calls it "the
satellite runtime" so that S0710's sentence reads, and `text_of` renders it as
the word the program wrote.

### 3.2 What a program answers is not its exit status

**The decision this milestone had to take and no document had.** The C shape —
`main` returns a number, the process exits with it — is wrong here for three
reasons, and the first is sufficient:

1. **The numbers are already spoken for.** `programs/opening.hpp` says its four
   statuses "are assigned by what a failure IS and not by the order they were
   invented in". A program answering 2 would be reported as *"the command line
   did not name something satl can do"* — exactly the disagreement that enum
   exists to prevent, arriving from a direction it cannot see.
2. **The language already has a success signal and it is not numeric.** DESIGN
   §3: `satellite.return(satellite)` is *"return the runtime (that is,
   success)"*.
3. **A satellite number is exact and unbounded; an exit status is eight bits.**
   Truncating one into the other is the silent conversion §1.1 refuses.

So the **ending** decides it: 0 finished, 4 a ceiling, 1 the program was wrong.
`run_command.cpp`'s `status_of()` is three lines under a page of that argument,
and §6 below carries it as the open item the author can overrule.

### 3.3 A file with no `satellite.main` is S0402, in the S04xx block

`--call` answers a missing capsule with a plain sentence, and this is
deliberately not that. **A capsule name on a command line is the user's word and
has no row; `satellite.main` is the language's**, it is where every program
starts, and errors.def is where a sentence somebody may have to look up belongs.

**It went in S04xx — "the file satl was given" — and not in the evaluator's
block.** The evaluator is not complaining: a file with no `main` parses,
resolves and compiles perfectly, and every capsule in it is callable. What has
gone wrong is one level out, which is exactly what that block's note describes:
*"the command line was well formed and named a file, and the file is where it
stopped."*

**It carries no span, and it is the first row where that is the interesting
part.** S0401 has none because the file never opened. This one has none because
what is wrong with the file is something that is NOT IN IT — and pointing at
line 1, or at the last capsule, would be the reporter inventing a place.

### 3.4 A `main` with a parameter gets a caret and a milestone, not an argument count

Every program in `example/` declares DESIGN §3's
`satellite.container.list<satellite.variable.string> arguments`. Calling `main`
with no arguments would have raised S0722 — *"`satellite.main` takes 1 argument
and was given 0"* — which is true, useless, and names nobody: a person reading it
goes looking for the caller. S0720 is the row for a program that is RIGHT and
arrived early, so the run arm raises it with the caret under the word
`arguments` and the milestone that will bind it, and **exits 3 rather than 1**
because the file is not malformed.

    satl: example/hello_world.satl:5:86: error S0720: `satellite.main`'s
    parameter parses and does not run yet -- PLAN.md §8 builds the containers
    at M16 and hello world at M17, and DESIGN §3 is why an empty list is still
    a list
       5 | satellite.capsule satellite.main(satellite.container.list<...> arguments)
         |                                                                 ^^^^^^^^^

### 3.5 The flush is when the queue runs dry, and it happens under the lock

DESIGN §10.1 asks for a flush because *"glibc buffers fully to a pipe or a file
and output can sit unwritten indefinitely"*. Two shapes were available: flush
every line, or flush at the end of the run. **Neither is right** — the first puts
a syscall in the most-called path in the language, and the second means
`satl prog.satl | head` sees nothing while the program computes.

So the printer flushes **when it has written its batch and the queue is empty**.
Under load the queue is never empty and it never runs; the moment the program
stops printing, the bytes are out. And it happens **inside the critical section
that signals the barrier**, which is what makes `drain()`'s promise "written AND
flushed" rather than "handed to stdio" — a waiter cannot be woken before the
flush, because the wake is after it in the same locked region.

### 3.6 The four passes moved to a file of their own

`evaluate_commands.cpp` held `Built`, `build()` and the policy read in an
anonymous namespace with one consumer. `satl file.satl` is the third, and three
copies of twenty lines would be three places the ORDER of the passes is decided.
`programs/built_program.hpp` is the split, on the seam `programs/source_file.hpp`
already named before this file existed: *"getting the bytes is what M3's
`--tokens`, M4's parser, M4.5's `.satc` reader and **M10's runner** all need the
same answer to."*

## 4. What building it found

### 4.1 The un-newlined form has no spelling, and the grammar is why

PLAN §8's M10 entry gives this milestone *"`display`'s un-newlined form, which
lives under `1 5 1`"*, and the M14 entry names v1's version by its C++ symbols:
`named_arg_misuse()` is the message for `display(text, end="")` and
`display_with_end()` begins at line 205.

**That spelling is not writable in this language.** DESIGN §6's grammar reads
`args := expression { "," expression }` — there are no named arguments anywhere
in it, and no positional form for this is specified in any document. So the
capability is built where the queue is, `Console::write()` takes a string and
appends nothing, and **`tests/console_test` is its only caller**. M14's
`satellite.console.input(prompt)` `1 5 3` is the first real one, and whoever
gives it a language surface decides the spelling. PLAN §8 now says so in both
entries.

### 4.2 Three sites said "1 arguments", and nothing had ever read one

S0722 is *"`{1}` takes {2} and was given {3}"*, and all three raisers built `{2}`
by hand as `std::to_string(n) + " arguments"`. It was invisible while the only
producers were a capsule call and a test's own handler row. **M10 installs the
first language row with an arity, so the first person to write
`display("a", "b")` is the first person to read the sentence.** `eval::arity_text`
is one function and three call sites now, which is errors.def's own argument —
a message is a row somebody maintains, not a literal at a call site.

### 4.3 A guard in `drain()` was dead, and a mutation test is what said so

`drain()` opened with `if (!started_) return;`, written for a deadlock where a
console nothing had started waited on a condition variable nobody would signal.
**The mutation that deletes it changes no fixture's answer**, and the reason is
that the wait predicate — an empty queue and no batch in flight — is already true
in exactly that case, so `wait` does not wait. The guard was defending against a
state that cannot happen (`push()` starts the printer, so there is no way to have
work queued and no thread) and it made the real reason harder to see. Deleted,
with the argument in its place.

### 4.4 A live code and a config setting disagree on purpose, and M10 is where it can be seen

`SCRATCH.md/PORTING.md` §3 has asked since 2026-08-27 what happens when
`satellite_string`'s live code 97 (`\threads`) and `satellite_config.ini`'s
`THREAD_COUNT` say different numbers: *"something has to say which one a program
sees."* **A program had no way to print a live code until there was a console**,
so the question could be asked and not demonstrated. Measured, with
`THREAD_COUNT=4` in a config beside the binary:

    $ satl --limits
      THREAD_COUNT      4           the file, .../satellite_config.ini:1
    $ satl live.satl
      threads=24 cwd=/home/madness/code/cxx/satellite

**That is correct and it is specified.** DESIGN §7.7: *"They must not be allowed
to disagree. Whatever the configuration finally says, it is a SETTING and the
machine is a FACT, and a program that asks `arguments.machine.threads` is asking
what the machine has, not what the config was told."* Code 97 is the machine;
`THREAD_COUNT` is how much of it satl may use. Two facts, two names.

**The answer predates the demonstration by two days and the question outlived it
by three**, which is the shape worth recording: §7.7 settled it on 2026-08-31 and
`PORTING.md` §3 went on asking, because nothing could run. It is struck now, and
that file is spent — `SCRATCH.md/README.md`'s row says so.

### 4.5 `example/satellite_config.ini`'s `max_depth` comment is a milestone out of date

The commented-out line reads `# max_depth=2000     M9 -- how deep a program may
recurse (DESIGN §7.5)`. M9 settled `max_depth` as a **memory ceiling in bytes**,
so `2000` is now both the wrong kind of number and one the reader would refuse —
a bare number with no unit raises S0805. Corrected at this milestone; it is
noted here rather than in M9's file because M9 is where it went stale and this is
where it was found. The same pass corrected the line above it, which said "the
other three are stored and nothing reads them yet" — true on 2026-08-27, and
false twice over since M8 and M9.

## 5. How it was checked

**`tests/console_test`, a suite of its own and not six more sections in
`eval_test`.** A binary that starts a printer thread and writes to descriptor 1
has to take that descriptor away and give it back around every fixture, and
mixing that with a suite whose other sections print nothing is how one failing
section makes another look broken.

**It redirects its own stdout, which is the only honest way.** The claims are
about bytes reaching a file descriptor, so a fake sink would be a test of the
queue with the half that can fail removed — glibc's buffering IS what §10.1's
flush exists for. `capture()` dup2s a temporary in `/tmp` over fd 1, runs a
fixture, shuts the console down and puts the descriptor back. That is
`satc_test/writing.cpp`'s *"it touches a disk, once, in /tmp, and that is on
purpose"* for the file writer, one module over.

**The mutations, and one of them does not fail.** Each was applied to
`console.cpp`, the suite rebuilt and run:

| mutation | what happens |
| --- | --- |
| the printer never flushes | **caught** — the barrier fixture fails: bytes are in stdio and not on the fd |
| `display` queues the text and the newline separately | **caught** — eight threads interleave inside a line, and the count is wrong too |
| the printer is detached rather than joined | **caught** — the suite hangs and the run does not complete |
| `drain()` waits only for an empty queue, ignoring a batch in flight | **NOT CAUGHT** |
| the `!started_` guard is removed from `drain()` | **not caught, and it was right not to** — §4.3 |

**The fourth is a line no test holds, and saying so is the point of running the
pass.** `drain()` waits for `queue_.empty() && !writing_`; the second half closes
the window where the printer has swapped the queue out and not yet written it.
Dropping it still passes at 2,000 queued lines and at 50,000, because **the
printer is never behind** — an `fwrite` to a file in `/tmp` is a memcpy into
stdio's buffer, and the producer, which allocates a string per line, is the
slower of the two. What would force it is a sink that BLOCKS, and M14's
`pty.fork()` fixture is where one arrives. The flag stays, because the window is
real; the fixture says in its own comment that it does not close it.

**And the suite is run twenty times before it is believed.** Two of its five
fixtures are threaded, and a threaded test that passes once has established
nothing.

**The other nine suites all pass — under clang, and the g++ half of the habit is
OWED.** Every suite ran clean under the tree's default clang, from a `make clean`.
The g++ cross-check was started twice on 2026-09-02 and completed zero times,
both times because a second `make` was running in the same tree — once mine
against mine, once mine against the author's, and the second collision is the
one that settled the rule: **this tree builds in-tree, so there is one `make` at
a time, whoever runs it**. The check is unverified rather than failed — the
farthest it got was `Error 127`, a test binary deleted out from under the run
list by the other make's `clean` — and it is the first thing to run on a quiet
tree, before the startup row.

**And two of the nine had to be edited rather than merely re-run**, which is
the milestone deleting its own predecessors' honesty:

- `tests/reporter_test/codes.cpp` counts the rows of `errors.def`. It went 69 →
  70 and **the count assertion is what stopped the build**, which is exactly the
  job it was written for.
- `tests/eval_test/compiling.cpp` asserted that `satellite` used as a value
  refuses with M10's number in it. It now asserts the ANSWER. **A refusal that
  names a milestone is a test that milestone deletes**, and that is the only
  thing keeping the "what parses and does not run yet" list honest.

## 6. What it left open

1. **The exit-status decision (§3.2) is the author's to overrule in one line.**
   Named here the way M6's `_exit(2)`-versus-`_exit(4)` argument was, and settled
   the same way if it is settled differently.
2. **The un-newlined form's spelling (§4.1)** belongs to whoever gives it a
   caller. M14 is the candidate.
3. **The `writing_` window is untested (§5).** Not a defect and not a gap in the
   code — a line no fixture in this suite can force.
4. **M6's pool still has no tenant, and that is a finding rather than a gap.**
   `MILESTONES/M6.md` §8 carried the question forward: *"M10 is the first
   milestone that can test that justification, and its printer thread is the
   first tenant; if the pool is still doing nothing after M10, §4.5.1.2 is a
   decision that should be re-taken with a number rather than defended."* **The
   premise was false**, so the test does not happen here — the first real batch
   is `satellite.include` of a second file at M25. The question is not answered
   by M10 and is not failed by it either, and this sentence is what M10 owes it
   so that nobody reads the pool's silence as the evidence M6 asked for.
5. **The watchdog cannot reach the queue.** `fflush` before `_exit` reaches what
   the printer has already written, and this milestone puts a queue above stdio.
   Draining there is exactly what a watchdog must never do, so **lines queued and
   not yet written are lost when it fires**. `watchdog.cpp` says so where somebody
   would otherwise add the drain; PLAN §8's M22 entry is where it is revisited.
6. **Ctrl-C has no ending to be reported as**, and PLAN §8 already gives that to
   M11: `Stopped` means a ceiling and carries exit 4, so an interrupt without a
   fourth `Ending` would be reported as a memory limit. M10 has no interrupt to
   end and adds nothing here on purpose.

## 7. What it cost, measured

**`make startup`, 2026-09-02, load 0.67, STATIC=full.** `make_support/startup.rows`
carries the table and `040-sources.mk` the account.

**satl's own share is 0.222 ms against M8's 0.239** — and the baseline was M8's,
because **M8.5 and M9 both landed without running this target**. So the deltas
cover three milestones, and every one is negative or inside the noise.

**The honest reading is a bound and not a result.** The machine was quieter than
it was on 2026-08-31 (load 0.67 against 0.88), and no claim is made that three
milestones made satl faster. What the table establishes is that an explicit
control stack, a value model, an evaluator and a console cost nothing this
measurement can see.

**The one positive claim is a negative, and it is about the console.** M10 adds a
module that starts a THREAD, which is the kind of thing already on this table —
§4.5.1.2's pool builder is 0.14 ms of it. It does not appear, because
`Console::the()` is a function-local static and the printer is made inside
`start_held()`, reached from `run_command.cpp` and from the queue and from
nowhere `satl --version` can get to. **The bare `satl` row is where it would show
if it did** — that row runs no arm at all, and M7's and M8's entries in
`040-sources.mk` are the worked examples of a cost paid before a command is
chosen turning up in exactly that place. That row went down.

**And the table still has no row for running a program**, which is the one
measurement this milestone owes and could not take. It had no file to point at
while `example/` held none that would run; it has two now, so `startup.rows`
gains `satl example/console.satl` the next time the harness runs on a tree
nobody else is building in. That is the only thing here that is unmeasured
rather than measured.
