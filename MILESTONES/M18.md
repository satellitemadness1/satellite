# M18 — `satellite.help`, and the trie answering for itself

**Landed 2026-09-08** (`HASH`).

[PLAN.md](../PLAN.md) §8's M18 entry is the specification. Its demand is one
sentence: *"`satl` runs a program whose whole body is `satellite.help` and the
output names exactly the paths that are built when it runs."*

This is a **review and not a plan**: what was decided on the way, what building
it found, and what it left open.

    $ satl help.satl
      satellite                                             1

      The root of the language, and the only word that is not under another
      one. Every path in satellite begins here, which is why its number is `1`
      and why every other number starts with a 1.

      On its own it names nothing you can call. Asking help about it is how you
      get the list of modules underneath, and that list is the language as it is
      built today rather than as it is planned.

          satellite.help(satellite)

      what is underneath, and every one of these is built:

    	satellite.include     Brings a body of words into the program.

    	satellite.capsule     Declares a capsule, which is what this language calls a function.

    	...

      14 of them -- ask about any by its path.

    $ cat network.satl
    satellite.help(satellite.network)

    $ satl network.satl
    satl: network.satl:5:19: error S1101: `satellite.network` is a path
          satellite has a number for and nothing built behind it yet, so there
          is nothing to tell you about it -- `satellite.help()` lists what is
          built

**The text was written before the machinery and that is why this note is short
on prose and long on mechanism.** `HELP.md` — 264 entries, one per node, every
worked line executed — was finished on 2026-09-07 and is unchanged in substance
by this milestone. What landed here is everything that makes the language able
to say it.

---

## 1. What the milestone was

- **The `built()` predicate over four kinds**, three stated and one derived,
  and the correction DESIGN §4.6 needed before help could be written at all.
  §2.1.
- **The first unevaluated argument in the language.** `satellite.help(x)`'s
  argument is a path or a name and is never run — which is a language decision
  and not an implementation one, and PLAN's account of which line carries it
  turned out to be half right. §2.2.
- **The walk**, which is one walk at three depths and has no root case. §2.3.
- **The entries as data**, generated from `help_lines/` in the same run that
  writes the document, so the two cannot disagree. §2.4.
- **A test that sweeps all 264 nodes** rather than sampling, because the
  done-when's own check passed by accident before the milestone started. §3.

**Four files under `src/satellite_help/`, one generated `.def`, four under
`tests/help_test/`, and edits to nine files that already existed.** No new word
numbers: `1 19`, `1 19 0` and `1 19 1` were assigned on 2026-08-28 when M2
transcribed the numbering, eleven days before anything answered to them.

## 2. The decisions

### 2.1 `handlers[path_id]` is not what "built" means, and hello world is the proof

**PLAN's own fix was wrong and PLAN says so.** DESIGN §4.6 said *"help cannot
drift from what exists — the trie **is** what exists"*, and §8's M18 entry
corrected it to *"help prints a node when `handlers[path_id]` is non-null"*
with the argument that **"the same table that decides whether a call runs
decides whether help mentions it."**

**Of the seven paths hello world is written in, exactly one is a row in that
table.** *(PLAN's entry says six; the `.satc` dump in M17.md has seven, because
the parameter's type is two of them — `satellite.container.list` and
`satellite.variable.string`.)* `satellite.console.display` `1 5 1` is a handler;
`satellite`,
`satellite.include(satellite)`, `satellite.capsule`, `satellite.main` and
`satellite.return(satellite)` are recognised by the parser and the resolver and
are never dispatched. A help built on the handler table alone prints one word of
the language's own first program and is silent about the other five. PLAN found
this on 2026-09-07, before any of it was built, and the author settled the
answer the same day: a node is built when it has a **handler** row, an
**assigner** row, or is a **front-end word**.

**The fourth kind is derived and must not be listed.** `satellite.console` `1 5`
has no row of any kind and is plainly built, because nine words under it are. So
`built()` is three claims plus one backward pass over the registry —
`src/satellite_help/built.cpp`, and the pass is single because a parent is
declared before its children, which is the same property `words_numbering.hpp`
reads forwards.

**The front-end set is data, in `words.def`'s fourth list, 27 rows.** PLAN asked
for that and the reason is worth repeating: a set inferred from which spellings
`parser_types.cpp` compares against moves the first time somebody refactors a
comparison, silently, and the only symptom is a help text that has started
lying.

**And a word that parses is not thereby built, which is where the list nearly
went wrong.** Every type name parses: `satellite.variable.window x` is accepted
today and the name simply holds nothing. So "does the front end have a case for
it" is the wrong test. The six type names in the list are **the six
`satellite_value/value.hpp` has an arm for** — string, time, number, bool, float,
variant — plus the list and the map, which M16 gave bodies. `satellite.file`,
`satellite.variable.window` and `satellite.include(spaceship)` are absent, and
each was checked by running a program that used it.

**`built()` is computed fresh on every ask and never cached.** The handler table
is filled by each module's `install_handlers()` at the top of a run, so a set
remembered once would be right or wrong depending on whether the first ask
happened before or after the installs — a defect visible only in whichever
program asked first. `help_test`'s first fixture clears both tables and asks
again, so the sentence is checked rather than written.

### 2.2 The argument is not evaluated, and nothing said so until the day before

***`satellite.help(satellite.console)` CANNOT BE AN ORDINARY CALL.*** A bare
language path read as a value compiles to `op_dispatch` and refuses at run time,
so the argument dies before help is entered — **and it refuses identically for a
module that IS built**. Measured 2026-09-07:

    satl: error S0721: `satellite.console` is a path satellite has a number
          for and nothing behind yet -- a later milestone

**So the done-when's second self-verifying check passed by accident, through the
wrong mechanism, and gave the same answer to the central question help exists to
answer.** That is worse than a check that fails.

**The mechanism is a new arm and a line the compiler does not run.**
`words.def` gains a fifth list, `SAT_TOPIC`, one row: `satellite.help(x)`
`1 19 1`, argument 0. `Compiler::topic()` reads what resolve already decided
about the node and folds it to a **constant string holding the canonical path
text**; the `Call` case skips `visit_reversed` for that argument.

***AND THE LOAD IS SHARED BETWEEN THOSE TWO, WHICH PLAN DOES NOT SAY AND A
MUTATION FOUND.*** PLAN names `visit_reversed(n.b)` as the load-bearing line. It
is not, on its own: **`topic()` folds the path itself and never looks at the
stack**, so a compiler that visited the argument anyway still ANSWERS correctly
and leaves the argument's `op_dispatch` unreferenced in the arena — exactly as
M14's misused place arguments are left. Restoring `visit_reversed` was expected
to turn S1101 back into S0721 and **every clause in `help_test` passed**.

**What the skip actually owns is the compiler's operand stack.** An op that was
pushed and never taken stays there, and the next expression to ask for a result
gets it — so `display(help(x))` would hand `display` the argument's op instead of
help's answer. The suite had no nested help call, so it caught nothing;
`walking.cpp` fixture 8 is that call, added because of this, and it is now the
one clause the mutation fails.

**Three reasons the fold is text and not a number.** The refusals help raises
quote the path, so the text is needed anyway; `satl --compile` prints a legible
constant instead of an integer nobody can read back; and a `Value` holding a
`PathId` would be a number that is not a number, which `value.hpp`'s rule about
arms with no producer exists to keep out. The compiled form of a whole help call
is **one constant and one dispatch**:

    2     constant      0 0 0 0           line 5
    3     dispatch      209 1 0 0         line 5

**Resolve had to be taught the same thing, and this is what building it found.**
Two cases reached resolve before the compiler could see them:

- **A bare word.** `satellite.help(random)` was refused by resolve with S0511,
  *"nothing called `random` is in scope here"* — which answers a question nobody
  asked, because a bare word here is a topic somebody left the `satellite.` off.
  `Act::Topic` carries the argument through the resolver's work stack and holds
  exactly that one refusal back, so the compiler can raise the sentence the
  author settled on 2026-09-07: **S1102**, *"there is no variable with the name
  `random` — did you mean `satellite.random`?"*
- **A global.** `satellite.help(satellite.library.n)` got S1103, *"`n` is
  neither [a path nor the name of a variable]"* — and `n` **is** the name of a
  variable, which is the one thing a refusal must not get wrong. Found by
  probing the shapes after the milestone was otherwise finished. A global is
  written `satellite.library.n = 0` and there is no typed form (S0204 refuses
  one), so resolve has no declared type to hand over and help would have to run
  the program to answer. **S1104** says that instead.
- **A word whose every shape takes arguments.** `satellite.variable.string.find`
  is `1 6 1 3` written `find(x)`, and resolve's walk is strict about that on
  purpose — `find` alone is not an expression. **It is a topic**, and it is the
  spelling every listing help prints names it by, so a help that could not
  answer it would print lines nobody could type back in. `words_walk.hpp` gains
  `word_named()`, the looser lookup `satl --words` has always used, with exactly
  one caller and a comment saying nothing else may use it.

**What was NOT loosened: `satellite.help(satellite.consle)` still stops at
`consle` and still says "did you mean `console`?".** The escape is narrowed to
the segment the topic node itself named, which is the same `found.at == node`
guard the arm above it uses for M9's globals.

### 2.3 One walk at three depths, and the root is not a special case

PLAN: *"Bare `satellite.help` and `satellite.help()` start at the root;
`satellite.help(x)` starts at `x`'s node."* That is literal here — there is one
function, `answer_for(built, id)`, and the topics a bare ask prints are the built
**children of `satellite`**, which is the same clause that prints display and
input under `satellite.console`. **`help_test` asserts all three print the same
bytes**, so the day the root becomes a special case the claim stops being true
out loud.

**A node is answered for together with the shapes beside it, and the grouping is
authored rather than derived.** Every entry in `help_lines/` carries the `>` line
it is brought up by, and `satellite.help(satellite.console.input)` heads
`input()`, `input(prompt)` and `input(prompt, target)` — three sibling nodes and
one word. PLAN says the same of `satellite.main`, which answers for `1 3` and
`1 3 0` at once. The head is stored as **the node the query walks to**, so
grouping is an integer compare and `help_text.hpp` can assert at compile time
that every head is its own head — which is what makes the groups a partition and
no entry unreachable. **183 groups over 264 nodes.**

**A derived rule was checked against the document before the authored one was
chosen.** Truncating each path at its first `(` reproduces the author's `>` lines
for **255 of 264** entries; the nine exceptions are `satellite.variable.file`'s
seven children and `satellite.variable.thread`'s two, both wholly unbuilt blocks
the author grouped under their parent. Since help never prints an unbuilt group,
either rule would behave identically today — the authored one was taken because
it cannot diverge tomorrow.

**Built, and offered, are not the same question.** `satellite.returns` `1 21`
parses, works, and answers in full when asked about — and it is optional, no file
under `example/` uses it, and the author's instruction is that it is not how a
capsule is written here. It is **built and unlisted**: a second column on
`SAT_BUILT`, one row, and the default is `SAT_OFFERED` so that a word added and
forgotten shows up rather than disappearing.

### 2.4 The entries are generated twice from one source

**`HELP.md` and `src/satellite_help/help.def` come out of one run of
`help_lines/gen.py`.** A hand-maintained C++ copy of 264 entries would be the
second document DESIGN §4.6 exists to remove, with a compiler in front of it.

**`help_text.hpp` asserts the join at compile time**: one row per node, in
`words.def` order, every head its own head. A word appended to the registry with
no entry written for it is a **build error naming the node**, not a blank page
somebody finds in six months.

**`help_lines/words_def.py` parses the registry to get each node's identifier**,
which `nodes.tsv` does not carry — and the parse is checked against `nodes.tsv`,
which a binary measured, before either is used. They agree on all 264 paths and
numbers or the generator stops.

**And `topics.py` stopped reconstructing the listing and started asking the
interpreter.** It used to walk `nodes.tsv` plus a hand-written `FRONT_END` set
and assemble what help *would* print — a second implementation of this
milestone's whole subject. It disagreed with the first on the day help was built:
the real walk names **14** topics and it named 13, because help now names itself.
It runs `satellite.help()` and refuses if `./satl` is older than `help.def`.

**90KB of string literals, and the binary went from 3,890,576 to 3,973,760
bytes** — 81KB on a static build, which is the text plus nothing. The alternative
was reading a document at run time, and a help that can be asked on a machine
where the document is missing or edited is v1's defect with an extra failure mode
bolted on.

## 3. The test, and why it is a sweep

`tests/help_test/` is the fourteenth suite. It redirects its own stdout for
`console_test`'s reason — help's answer is bytes reaching descriptor 1 through
the printer thread — and compiles and runs real programs rather than calling
handlers, so the trie walk, the compiler arm that declines to compile the
argument, the array index and the arity check are all in the path.

**The done-when's second check is swept over all 183 groups and asserts the
CODE.** Every built group answers; every unbuilt group refuses; and the refusal
must be **S1101 and never S0721**, which is the code that would mean the argument
had been evaluated after all. **118 answer and 65 refuse at M18.** One example
would have passed before this milestone existed.

**The first check is a comparison and not a restatement.** Every non-null entry
of `handlers[]` is built — 109 rows, help's three included. Every non-null entry
of `Assigners` is built — the four dials, which is the kind a help built on
`handlers[]` alone would have missed. And **nothing is built for no reason**: for
each of the 144 built nodes, one of the four kinds is found or the fixture fails.

**And the predicate is asked once before anything is installed**, because
`built()` reads the tables live rather than remembering an answer — a set
computed once would be right or wrong depending on which program in a process
asked first, which is a defect that appears in one program and not the next.

**Four error codes, not three, and the fourth is the milestone's own late
finding.** S1101 unbuilt, S1102 a bare word, S1103 anything else, and **S1104 a
global** — added after the other three, because probing the shapes turned up a
sentence that told somebody `n` was not the name of a variable while they were
looking at the line declaring it. `errors.def` went 101 rows → 105.

**What proves it, in mutations.** Each was applied to a **copy** of the tree —
never the working one — and the suite re-run:

    MUTATION                                       RESULT
    remove SAT_BUILT(RETURN_SATELLITE)             1 clause  hello world's own words
    remove SAT_BUILT(MAIN) and MAIN_0              2 clauses the front-end kind, by name
    remove the topic arm from call()              194 clauses the milestone, gone
    let resolve refuse a bare topic word            1 clause  S1102 became S0511
    drop the is_unlisted filter                     1 clause  returns is offered
    delete a row from help.def                     build fails, static_assert
    point an entry's head at a non-head            build fails, static_assert
    restore visit_reversed for the topic argument   0 clauses -- SEE BELOW

**Two of these were wrong when they were written, and both are worth keeping in
the table rather than quietly replaced.**

***Removing `SAT_BUILT(MAIN)` alone changes nothing, and that is the predicate
being right.*** `satellite.main()` `1 3 0` is a front-end row too, so `1 3` stays
built through the derived arm — a namespace is vouched for by what is under it,
and `main` has something under it. The mutation that bites is a **leaf**, and
`satellite.return(satellite)` `1 15 1` is one.

***Restoring `visit_reversed` for the topic argument is NOT CAUGHT, and PLAN's
account of that line is what was wrong.*** Every clause passes with it back in.
What makes the argument a path is `call()`'s topic arm, which folds the path
itself and never reads the results stack; a visited argument simply compiles to
an op nothing references and never runs. The leftover result it pushes sits
**below** the answer, and no construct in the compiler takes more results than
it pushed, so nothing ever reads it. **The guard that would see it is a floor
check on `results_` in `compile_tree()`** — "every case answers exactly one op"
is `compile_expressions.cpp`'s own opening contract and nothing enforces it. That
belongs to whoever owns that file; it is recorded here because a mutation
disproved a sentence in PLAN and the disproof should not be lost.

`walking.cpp`'s fixture 8 — a help call inside another expression — was added
while chasing that mutation on a theory that turned out to be wrong. **It is kept
and its comment says so**, because a help call in expression position is worth a
fixture and a clause whose stated purpose is false is worse than no clause.

## 4. What it left open

**`satl --words` is still unmarked, and that is a decision.** Marking each row
with whether it is built would put `eval::Handlers` behind `satellite_words` —
and `words.hpp`'s claim is that the numbering "can be read by a test, a future
`.satc` reader or a disassembler without dragging the interpreter in behind it",
which `words_test` relies on by linking no objects at all. The mark would have to
arrive as a predicate passed in by `programs/dump_commands.cpp`. It is worth
doing; the question `--words` answers is what the registry SAYS, and
`satellite.help` is now the command that answers what the language DOES.
**`dump.cpp`'s closing paragraph was corrected here** — it had said "there is no
handler table yet" and "there is no evaluator yet" since M2, which stopped being
true at M9 and M10 and went on printing until this milestone.

**`--call` installs no help, for the same reason it installs no console.** Help's
whole answer is printed, so a help row installed where `display` is not would
reach a console that arm never started. It refuses there with S0721 exactly as
`display` does, and `built()` correctly reports help unbuilt in that process —
the predicate is a property of the RUN and not of the build, which is why it is
computed fresh.

**The seven v1 topic pages are still undecided**, exactly as PLAN leaves them:
`arguments`, `random`, `fast`, `normal`, `ultra`, `random.ultra`, `wide`. None is
a path with a number. PLAN says whether they survive is open and that their text
"must not be a second document"; nothing here forecloses either answer.

**`satellite.analyze` `1 16` still has no milestone anywhere**, and help now says
so out loud rather than by omission — asking about it refuses with S1101 and
names the command that lists what is built.

**`compile_expressions.cpp` is 640 lines**, up from 510. The line rule is "try to
build for 300" and this file was over it before this milestone; the growth is one
new function and its argument. A split at a real seam — the shapes a call can
take, against the rows that declare a parameter is not an expression — is
available and was not taken mid-milestone, which is the rule's own advice.

## 5. The done-when, read carefully

PLAN's sentence is *"the output names exactly the paths that are built when it
runs — everything through M16 and M17, in build order, and no others."*

**What `satellite.help` prints is the 14 built topics, not all 144 built paths**,
and the difference is the author's, settled on 2026-09-07 when the text was
written: `HELP.md`'s first section is *"the topics that are built, one to a line,
each indented one tab and separated by a blank line"*, and `1 19 0`'s own entry
says *"Everything, from the root down: the topics that are built, one to a
line."* That entry is the later document and it is the one the author reviewed.

**The property the done-when is actually about is kept in full, and is kept by
the test rather than by the printout**: nothing help names is unbuilt, nothing
built is unreachable, and the same unedited program will print a different and
equally correct language at M19 — `satellite.file` joins the topics the day
`1 8 1` gets a row, with no edit here.
