
--------------------------------------------------------------------------------
SATELLITE 004: arguments
--------------------------------------------------------------------------------

arguments is the special variable that controls the interpreter: the settings
satl starts with, the words it was given on the command line, and what it can
read about the machine it runs on. It is filled from four places:

1) the author's rows, compiled into satl (satellite/config/satellite_config.hpp)
   -- arguments.version, arguments.threads_startup_per_core, arguments.infinity
   and more.
2) ~/.satl/config.ini, your own file: one "key = value" a line, # for comments.
   A row can be set for one machine by its name without "arguments." --
   directory.default, float.whole, float.decimal and display.buffer are the
   rows read from this file today; any other number row there is not read.
   The switches live here too (access = true), and "features = b..." is what
   satl really reads: satl --rebuild writes it from the switches. At its top,
   first_start and the machine's facts satl keeps (point 4). No config.ini is
   only a notice (S010), and the run carries on.
3) the command line, numbered as it was typed: satl prog.satl one two gives
   arguments.argument1 = satl (satl itself), argument2 = prog.satl, argument3
   = one, argument4 = two, and arguments.length = 4, every one counted. arg3,
   args3 and arguments3 are argument3 too, and arguments.program is the file
   again. satl --debug prints every argument, these first.
4) the machine. What changes -- free and used memory, the process, the
   session -- is read fresh each time a program asks. What does not -- the
   processor's name and cores, and the system's name and version -- is read
   once, on the first start, and kept in config.ini under first_start = false
   with the machine's name: believed on that machine only, and read again after
   satl --rebuild. satl --config [most] measures once how many threads this
   machine can hold and keeps the count in ~/.satl/machine.conf; until then
   arguments.threads answers the lowest of the thread limits the system states.

satellite.main hands a program all of it as ONE variable, when main asks for it
by declaring it -- satellite.main() with nothing between its brackets asks for
nothing:

    satellite.capsule satellite.main(satellite.variable.arguments args)

The name is yours: arguments, args, anything. Each row is read by its name
after the variable's, with no brackets -- args.username, args.memory.total,
args.argument3, args.float.decimal. A row satl gathered when it started is
that row; a row only a library answers, like memory.used and memory.free, is
read fresh each time, so it is what the machine is using now.
satellite.console.display(args) shows every row there is (57 on one machine). A
name that is not a row is refused where it is read: "args.usernme is not one of
the arguments". The older spelling,
satellite.container.list<satellite.variable.string> arguments, is the same
variable.

What the processor can run is two rows: args.cpu.architecture is haswell when
it runs everything Haswell brought (the x86-64-v3 set: AVX, AVX2, FMA, BMI1,
BMI2 ...) and baseline when it does not, and args.cpu.features is one list of
every instruction set the processor and the kernel both allow --
args.cpu.features.contains("avx2") asks for one.

A row is written the same way, when its name is the program's own:
args.some_var = 5 adds it, a second args.some_var = 6 changes it, and
satellite.console.display(args) shows it after satl's rows. A row can hold a
list and change it: args.l = satellite.container.list(), then args.l.append(5)
and args.l[1]. A row satl holds -- username, memory.total, argument3,
infinity -- is read and never written, and a line writing one is refused before
the program runs. access is the one setting among them:
args.access = satellite.bool.false turns it off in ~/.satl/config.ini.

The same facts are words of the language too, read by their full name with no
brackets: satellite.library.arguments.cores,
satellite.library.arguments.memory.used and the rest, in any capsule. access is
the one a program can also write. (satellite.library.main.arguments, where
they lived until 2026-10-03, still answers.)

example (run as: satl prog.satl one two -- the comments are one machine's):

satellite.include(satellite)

satellite.capsule satellite.main(satellite.variable.arguments args)
{
    satellite.console.display(args.username) // madness
    satellite.console.display(args.argument3) // one
    satellite.console.display(args.length) // 4
    satellite.console.display(args.float.decimal) // 128
    satellite.console.display(args.memory.used > 0) // true
    satellite.console.display(args.cpu.architecture) // haswell
    satellite.console.display(args.cpu.features.contains("avx2")) // true
    args.some_var = 5
    args.some_var = args.some_var + 1
    satellite.console.display(args.some_var) // 6
    satellite.console.display(satellite.library.arguments.machine.pointer_bits) // 64

    satellite.return(satellite)
}

satl --debug prog.satl one two prints, among its other lines, every argument --
the command line first:

[satellite] arguments.argument1 = satl (machine_code: 0 success)
[satellite] arguments.argument2 = prog.satl (machine_code: 0 success)
[satellite] arguments.argument3 = one (machine_code: 0 success)
[satellite] arguments.argument4 = two (machine_code: 0 success)
[satellite] arguments.length = 4 (machine_code: 0 success)
