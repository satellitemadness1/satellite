
--------------------------------------------------------------------------------
SATELLITE 004: arguments
--------------------------------------------------------------------------------

arguments is the special variable that controls the interpreter: the settings
satl starts with, the words it was given on the command line, and what it can
read about the machine it runs on. It is filled from four places:

1) the author's rows, compiled into satl (satellite/config/satellite_config.hpp)
   -- arguments.version, arguments.threads_startup_per_core, arguments.infinity
   and more.
2) ~/.satl/config.ini, your own file: one "key = value" a line, # for comments.
   Every SETTING is read from it by its name without "arguments." --
   missing = false, magic = 9, float.decimal = 10, directory.default = ~/code
   -- and a line typed at the prompt saves one there (below). The settings are
   access, missing, startup_display, magic, directory.default, log_path,
   object_bytes_max, file_size_max_bytes, infinity, infinity_display,
   infinity.counter, float.whole, float.decimal, display.buffer,
   scroll.vertical and scroll.horizontal. A number
   that is not one stops satl as it starts, by name; a true/false row reads
   anything but false as true. The warm threads (threads_startup_per_core,
   threads_max) stay the author's rows: saved, one line could make every start
   ask for a million threads. The feature switches live here
   too (access = true), and "features = b..." is what satl really reads for
   them: satl --rebuild writes it from the switches, and until it runs every
   start says S011. At its top, first_start and the machine's facts satl keeps
   (point 4). No config.ini is only a notice (S010), and the run carries on.
3) the command line, numbered as it was typed: satl prog.satl one two gives
   arguments.argument1 = satl (satl itself), argument2 = prog.satl, argument3
   = one, argument4 = two, and arguments.length = 4, every one counted. arg3,
   args3 and arguments3 are argument3 too, and arguments.program is the file
   again. satl --debug prints every argument, these first.
4) the machine. What changes -- free and used memory, the process, the
   session -- is read fresh each time a program asks. What does not -- the
   processor's name and cores, and the system's name and version -- is read
   once, on the first start, and kept in config.ini under first_start = false
   with the machine's name: believed on that machine only, and read again after
   satl --rebuild. satl --config [most] measures once how many threads this
   machine can hold and keeps the count in ~/.satl/machine.conf; until then
   arguments.threads answers the lowest of the thread limits the system states.

satellite.main hands a program all of it as ONE variable, when main asks for it
by declaring it -- satellite.main() with nothing between its brackets asks for
nothing:

    satellite.capsule satellite.main(satellite.variable.arguments args)

The name is yours: arguments, args, anything. Each row is read by its name
after the variable's, with no brackets -- args.username, args.memory.total,
args.argument3, args.float.decimal. A row satl gathered when it started is
that row; a row only a library answers, like memory.used and memory.free, is
read fresh each time, so it is what the machine is using now.
satellite.console.display(args) shows every row there is (57 on one machine). A
name that is not a row is refused where it is read: "args.usernme is not one of
the arguments". The older spelling,
satellite.container.list<satellite.variable.string> arguments, is the same
variable.

What the processor can run is two rows: args.cpu.architecture is haswell when
it runs everything Haswell brought (the x86-64-v3 set: AVX, AVX2, FMA, BMI1,
BMI2 ...) and baseline when it does not, and args.cpu.features is one list of
every instruction set the processor and the kernel both allow --
args.cpu.features.contains("avx2") asks for one.

A row is written the same way, when its name is the program's own:
args.some_var = 5 adds it, a second args.some_var = 6 changes it, and
satellite.console.display(args) shows it after satl's rows. args.some_var(6)
is the same line as args.some_var = 6. A row can hold a list and change it:
args.l = satellite.container.list(), then args.l.append(5) and args.l[1]. A
fact satl holds -- username, memory.total, argument3, version -- is read and
never written, and a line writing one is refused before the program runs.

A SETTING IS CHANGED BY A LINE, and WHERE the line is says how long it lasts:

    typed at the prompt     arguments.infinity(256)   saved in config.ini --
                                                      every run after reads it
    in a file               arguments.infinity(256)   this run only; config.ini
                                                      is not touched

arguments.infinity = 256 is the same line as arguments.infinity(256), with the
same rule. A switch takes true or
false (bare, or satellite.bool.false), a count a whole number (infinity,
infinity_display, infinity.counter, float.whole, float.decimal and
display.buffer at least 1), and directory.default and log_path a folder or a
path in quotes. A setting satl reads as it starts -- startup_display,
directory.default, display.buffer -- is read before any file is, so a line in
a file is refused for it: it is
changed at the prompt, for every run after. A file run from
the prompt (interpret file.satl) is a satl of its own, so what that file
changes for its run never reaches the prompt.

THE BARE NAME arguments reads them anywhere: in any capsule, and at the
prompt, arguments.missing, arguments.username and the rest are the run's own
rows, and arguments.infinity(64) changes one. So nothing else may be named
arguments -- no variable, object, parameter or satellite.namespace -- except
satellite.main's parameter, which is the arguments. A name of the program's
own is main's: it is written on main's arguments, not on the bare name.

A bare true or false is taken by every write to the arguments: args.access =
false is args.access = satellite.bool.false, args.access(false) is the same,
args.my_flag = true is a row of your own, and satellite.library.arguments.access
= false works too. There the bare word is the value, always -- a variable a
program named false is read as (false), in brackets.

arguments.missing is the switch a program writes for itself, at the top of its
own file and outside every capsule, where satellite.library.span = 25 would
stand (the example below has it under satellite.include(satellite)):

arguments.missing(false)

-- or arguments.missing = false, the same line. Any setting a file may change
is written there the same way, for that run: arguments.float.decimal(10).

It is true unless the program says false, and it is what turns off what satl
says a program is missing -- a forgotten .open(), a forgotten return, Hello,
World! for a blank file. Those reports are being built after it, so today it is
only the row. satellite.library.arguments.missing = false is the same line. It
is written once, true or false and nothing else, before anything is said about
the program; a file the program includes keeps its own switch for when it runs
by itself, and a file that never runs by itself -- one with no
satellite.include(satellite) -- cannot have one. Inside a capsule it is
refused: it holds for the whole run, and some of what it turns off is said
before satellite.main begins. Typed at the prompt, arguments.missing(false) is
saved for every run. Read it back as args.missing, or arguments.missing
anywhere.

The same facts are words of the language too, read by their full name with no
brackets: satellite.library.arguments.cores,
satellite.library.arguments.memory.used and the rest, in any capsule. access is
the one setting among those words, written by the same rule as every
setting. (satellite.library.main.arguments, where they lived until 2026-10-03,
still answers.)

example (run as: satl prog.satl one two -- the comments are one machine's):

satellite.include(satellite)

satellite.capsule satellite.main(satellite.variable.arguments args)
{
    satellite.console.display(args.username) // madness
    satellite.console.display(args.argument3) // one
    satellite.console.display(args.length) // 4
    satellite.console.display(args.float.decimal) // 128
    satellite.console.display(args.memory.used > 0) // true
    satellite.console.display(args.cpu.architecture) // haswell
    satellite.console.display(args.cpu.features.contains("avx2")) // true
    args.some_var = 5
    args.some_var = args.some_var + 1
    satellite.console.display(args.some_var) // 6
    satellite.console.display(satellite.library.arguments.machine.pointer_bits) // 64

    satellite.return(satellite)
}

example, a program that turns the switch off and reads it back:

satellite.include(satellite)
arguments.missing = false

satellite.capsule satellite.main(satellite.variable.arguments args)
{
    satellite.console.display(args.missing) // false
    args.my_flag = true
    satellite.console.display(args.my_flag) // true

    satellite.return(satellite)
}

example, settings changed for one run -- at the top, in main, and by the bare
name in a capsule of its own -- and config.ini is not touched:

satellite.include(satellite)
arguments.float.decimal(10)

satellite.capsule wider()
{
    arguments.infinity(64)
    satellite.console.display(arguments.missing) // true
}

satellite.capsule satellite.main(satellite.variable.arguments args)
{
    satellite.console.display(1.0 / 3.0) // 0.3333333333
    args.float.decimal(3)
    satellite.console.display(1.0 / 3.0) // 0.333
    wider()
    satellite.console.display(args.infinity) // 64

    satellite.return(satellite)
}

satl --debug prog.satl one two prints, among its other lines, every argument --
the command line first:

[satellite] arguments.argument1 = satl (machine_code: 0 success)
[satellite] arguments.argument2 = prog.satl (machine_code: 0 success)
[satellite] arguments.argument3 = one (machine_code: 0 success)
[satellite] arguments.argument4 = two (machine_code: 0 success)
[satellite] arguments.length = 4 (machine_code: 0 success)
