# M4.5 — the `.satc` cache

**Landed 2026-08-30** (`e9df46a`), the same day as M4 and against
[SATC.md](../SATC.md), which had been written five days before anything could
implement it. Three things in that specification turned out to be wrong when the
code was written, and **all three are corrected there rather than recorded only
here** — §1's location, §1.1's spelling of a path, and §5's thread. §3 below is
the argument for each.

**Verdict: done.** Every clause of PLAN's M4.5 paragraph has code behind it,
`make` and `make test` are green across four suites **under both clang and g++**, and
`satl --satc <file>` runs the whole of SATC §4 — reads the cache when it hits,
walks and writes when it misses, prints the `.satc` either way and says on
stderr which happened. §6 lists what is left open, and **§5 is the one a reader
should not skip**: the cache does not pay for itself until M7.

---

## 1. What the milestone was

PLAN: *"check for a `.satc` before walking a source, read it when its three
header lines match, and write a fresh one afterwards on its own thread."* And
the reason it sits between the parser and the error reporter:

- **After M4**, because it serialises a parsed program and there is nothing to
  serialise before the parser exists.
- **Before M5**, because *"a malformed `.satc` is the first thing in the
  language that has to say something to a user in plain words."* That sentence
  is now written, in `src/satellite_cache/read.cpp`, in the shape DESIGN §9 asks
  for — a full sentence naming the fix, and no code, because codes are M5's to
  design with all of them in view.

**The done-when is a fixpoint one step longer than M4's.** M4's was *print, parse,
print, identical*; this one is **write a program, read the file back, write
that, and the two files are identical** — over both fixtures and all four
acceptance programs. It is one step longer because there are two printers and a
substitution between them.

**And a fixpoint alone proves nothing about meaning**, which is worth saying
because it is exactly the trap this module's own first defect sat in.
`satellite.console.input(">>>", target)` written as `display` reads back
perfectly and writes out identically. What catches that is
`tests/satc_test/examples.cpp` checking every number in every acceptance program
back through the trie. The two checks are complementary and neither is enough:
one says the numbers are the right ones, the other says nothing was lost
carrying them.

## 3. Three things SATC.md did not settle, decided here

### 3.1 Every `.satc` lives in `$HOME/.satl/cache`

§6's first bullet asked and listed three answers. **Beside the source cannot be
the only one** — a program run out of `/usr/share` or a read-only checkout would
never get a cache at all — and **both is the one the bullet itself rules out**:
*"two places to look and a rule about which wins."*

What one directory costs is a name collision, and it is paid in the file name
rather than discovered later: `<stem>.<16 hex of the source's ABSOLUTE path>.satc`.
The absolute path and not the one that was typed, because `satl hello.satl`,
`satl ./hello.satl` and `satl ~/code/hello.satl` are one source, and hashing what
the user typed would give it three cache files — two of them written on every run
and read on none.

**And the header is still checked after that.** The digest makes a collision
unlikely; §2's `source <name> <mtime> <size>` line is what makes one *harmless*.
A reader that opened the wrong file finds a name that does not match and treats
it as a miss, which is the same answer it gives a stale one.

### 3.2 A path is written `#1.5.1` and not `1.5.1`

**Found by writing the thing.** `satellite.console` is `1 5`, which closes up to
`1.5`, which is also the float one-and-a-half — and
`example/super_advanced.satl` already puts a float and a path within three lines
of each other.

It happens to be decidable today, because all 24 two-segment paths are namespaces
and a namespace is never a value. That is a property of the numbering that
**nothing enforces**, and WORD_NUMBERS §3 lets a numbering grow. One character
settles it permanently instead.

`#` rather than any other character, because **no satellite program can contain
one**: the lexer gives it back as `Punct(#)` and the parser has no rule that
accepts it. So a `#` in a file is proof that the file is a `.satc` and not a
source, which is the property worth having a marker for at all. The alternative
— leaving the file as §1.1 wrote it and having the reader disambiguate by
grammar position — was rejected because it makes the format un-lexable without
the numbering in hand.

### 3.3 The write thread is joined, not detached

§5 says *"the run does not wait for the write"*, and that is about **where** the
wait goes rather than whether there is one. `satl hello_world.satl` finishes in
under a millisecond, so a detached writer is a thread the process exits out from
under: the first run pays for the walk, writes nothing, and the second run pays
for it again, forever. Joining in a destructor puts the wait after the program
instead of in front of it, which is what §5 actually asks for.

## 4. What building it found

**A miss must cost exactly one walk and nothing else, and the obvious reader
breaks that.** Parsing a `.satc` allocates every user name in it (WORD_NUMBERS
§3, *"the next number free when the name is first met"*). A reader that parsed
straight into the caller's numbering and then discovered the file was malformed
would leave `fact` and `helper` already defined — and the caller's fall back to
the source would meet them a second time and report **the user's own program as
declaring a name twice**. `read_text()` parses into a local numbering and hands
it over only on a hit. `tests/satc_test/reading.cpp` checks it, and the mutation
that removes it is caught.

**A `.satc` that does not parse is malformed; a source that does not is the
user's.** Nobody typed the cache file — the writer produced it from a tree that
had already parsed — so a parse error in one is evidence about the machine (a
truncated write, a damaged disk, an edit by hand) and never about the program.
That is why the note ends *"nothing is wrong with your program."*

**A stale file must say nothing, and that is as much a requirement as the note
is.** Appending a word to the language moves the digest, which invalidates every
cached program on the machine at once. A note on each would be a hundred lines of
output about a cache doing exactly its job. Both stale checks in the suite assert
`note.empty()`.

**The suite's output is block-buffered, so a mutation that CRASHES looks like a
mutation nothing caught.** Removing the path mark makes a fixture unbuildable and
aborts the binary, and every `FAIL` printed before the abort was lost in the
buffer — the first run of that mutation reported "caught by 0 checks", which is
the most misleading answer a mutation can give. Re-run under `stdbuf -o0` it is
**38**. Worth knowing about before the next milestone mutates something.

## 5. What a cache hit saves today: the walk, and not the numbering

**This is the finding to carry forward and it is written in three places on
purpose** — here, SATC §4.1, and PLAN's M4.5 paragraph — because it is otherwise
discovered by whoever wonders why the cache is not faster.

The tree a reader hands back has **nowhere to put the `PathId`s the file already
carries**. `ast.hpp` reserves the side table indexed by node for M7 and forbids
M4 to put a mutable field on a node, so the honest M4.5 reader produces the TREE
and M7's resolve still numbers every path in it. That is exactly what PLAN asks
M4.5 for — read, check, write and refuse, and no more — and it means
**M7's resolve has to learn to skip a path the `.satc` has already numbered**
before the cache pays for itself.

Measured on this machine, and the numbers say the same thing:

| | |
|---|---|
| `satl --version` (the floor) | 1.61 ms |
| `satl --unparse example/hello_world.satl` | 1.71 ms |
| `satl --satc example/hello_world.satl`, cache warm | 1.74 ms |
| the same, cache cold — walk, write, `fsync`, join | ≈ 3.2 ms |

**A warm hit is not faster than `--unparse`, and on a 273-byte program that is
the expected answer rather than a defect.** The warm path reads a 425-byte
`.satc` instead of a 273-byte source, runs the substitution back over it, and
then lexes and parses exactly as `--unparse` does — so it does strictly more work
until M7 lets it do less. And a cold run costs about 1.5 ms over the floor, of
which the walk is roughly 0.1 ms: **the `fsync` dominates the thing it is
caching.** That is the right trade for a cache that must never leave a truncated
file, and it is why the write is on a thread.

**These numbers are comparable to each other and NOT to M4's.** They were taken
at load ≈ 2.8 through a shell-loop harness whose own overhead puts `--version` at
1.61 ms against the 0.62 ms MILESTONES/M4.md §7 records for the same command on
a quiet machine. What is being read here is the shape of the four, not their
absolute values.

## 6. What is left open

1. **M7 must learn to skip a path the file has already numbered** — §5. Until it
   does, the cache saves a walk and adds a substitution.
2. **`satellite.include` of a spaceship is still SATC §6's open bullet.** A
   program's meaning then depends on files it did not name in its own header, and
   neither answer — a header line per included file, or an included program
   invalidating the cache wholesale — is chosen. Nothing in this milestone
   forecloses either.
3. **Nothing prunes the cache directory.** Every source ever run leaves a file
   and a numbering change orphans all of them. That is a `satl --clear-cache` or
   a size ceiling, and it is nobody's milestone.
4. **`src/abstract_syntax_tree/` and `src/parser/` still have no rows in
   LAYOUT.md**, only a paragraph. M4.5 added rows for its own module and did not
   close that gap, because those files are M4's to describe.
5. ~~**The exit status is still M5's**~~ — **CLOSED 2026-08-30 BY M5**, and
   this was the third of the three arms. `EXIT_MALFORMED = 1`; `programs/
   opening.hpp` carries why it is 1 and why no arm was allowed to invent it.
   §4's plain-words note is now an `errors::Diagnostic` too — the four sentences
   are `errors.def`'s S03xx block, and the fifth that all four used to append is
   a **note** they attach instead. *(Original: "this is the third command to need
   the code that is missing. EXIT_USAGE is the only non-zero code and its own
   definition is 'the command line did not name something satl can do', which a
   malformed program is not.")*
6. **The `.satc` is lossy and the format says so in only one place.** §5.1's
   alias collapse means the file cannot say whether the source wrote `hex` or
   `hexadecimal`, or which of six spellings of `arguments` was used. Harmless for
   a cache; it does mean a `.satc` is never a substitute for its source, and
   §1.1 invites exactly that mistake by making the file pleasant to read.

## 7. What the test proves, and the mutations that prove the test

`tests/satc_test/` is **87 check sites in six sections**. Six rather than four
because M4.5 finished what M4.5 started: `reading.cpp` is §4's order and the
fixpoint, `writing.cpp` is §5's write on a real disk in `/tmp`.

Every mutation below was made, compiled, run, and reverted.

| mutation | caught by |
|---|---|
| the path mark not written | **38 checks**, and the binary aborts |
| the arity guard removed — *the `display` defect*, **both** guards | 7 checks |
| the absorber preference reversed | 5 checks |
| declarations emitted in reverse order | 5 checks |
| the source header line no longer compared | **9 checks** |
| `path_source` keeps the row's argument list | 3 checks |
| the alias's call looked for after its FIRST word | 1 check |
| the caller's numbering handed over before the parse is checked | 1 check |
| string literals scanned for the path mark | 1 check |
| a segment of `0` treated as the end of a number | 1 check |
| the temporary left behind on a successful write | 1 check |
| the write thread detached instead of joined | 1 check |

**The `display` mutation has to be made twice, and that is the same finding
MILESTONES/M4.md §8 records one milestone earlier.** The defect is guarded in two
places — `consider()` refuses a row with no argument list, and the child loop is
skipped when there is no call — and disabling either alone changes nothing. Both
together reproduce it. That is defence worth knowing about, and it was invisible
until a mutation went looking for it.
