[PLAN.md](../PLAN.md) §8's M22 entry is the specification: *"the prompt, the
prompt's Ctrl-C — the byte `0x03`, because raw mode turns ISIG off and the

## 0. Why this milestone ran out of order

**It was built before M18, at the author's direction, and the reason is a rule
this tree already has.** M18 is `satellite.help`, and the author's account of
what help should do includes asking about a variable *after the program that
declared it has finished* — which needs the program's names and types kept
somewhere, and needs somewhere to type the question. There was nowhere: the
prompt was M22 and unbuilt, and `satl-term` closed a tab when its interpreter
finished.

**A store built at M18 would have had its only reader at M22**, and PLAN §8's M2
entry forbids exactly that — a registry needs a consumer in the milestone that
writes it, *"which the first satellite did not have for three commits, and four
defects accumulated in that window"* ([words.def](../src/satellite_words/words.def)
says it in its own header). The author's answer was to move the prompt in front
of it. **PLAN §8's build order is unchanged and this note is the record that it
was departed from**, the same shape M18's own entry already carries: *"if help
is wanted during M11 and M16, this is the one that can move, and it moves
without consequence."* The one that moved was the other one.

## 2. The decisions

### 2.1 A typed line is not a program

**S0204 is the whole problem in one sentence** — *"a file holds
`satellite.include`, `satellite.capsule`, `satellite.spacesuit` and
`satellite.library.<name>`"* — and `satellite.console.display("hi")` is none of
them. Measured before anything was written:

    $ satl toplevel.satl
    satl: toplevel.satl:1:1: error S0204: a file holds satellite.include, ...
       1 | satellite.console.display("top level")
         | ^^^^^^^^^

So the session **wraps** what was typed. The author proposed the hello-world
skeleton and it was tested rather than assumed; it works, and two things came
off it:

**The wrapper takes no parameter and writes no return.**
`satellite.capsule satellite.main()` is what `example/scalars.satl` declares and
it runs, so the empty `satellite.container.list<satellite.variable.string>
arguments` that DESIGN §3 writes is not needed — and declaring it would hand
every typed line an empty list nothing reads, which is M20's parameter borrowed
early for no purpose. `satellite.return(satellite)` is likewise optional: a
capsule that falls off its end has finished.

**A top-level form is kept; a statement is not.** Every line rebuilds the whole
program from the forms typed so far, so **a capsule declared at the prompt is
still there on the next line** — which is most of what a person wants a prompt
for, and it costs nothing because a declaration has no side effects to re-run.
A local declared inside `main` goes when its line does. §6 has what that costs.

### 2.2 Where a line goes is decided by the language's own lexer

`block.cpp` counts `{` and `}` **tokens**, not characters, so a brace inside a
string is not a brace and a brace inside a comment is not either. The
alternative — a character scan — is a second implementation of what a string
literal is, what an escape is and where a comment ends, three rules DESIGN §5
already fixes. It would disagree with the language the first time either moved.

The same pass answers **where** the line goes, by asking segment 1 the question
the parser already asks (DESIGN §6.1's dispatch on segment 1).

### 2.3 The owed body was measured, not designed

See §3.1. It is the one piece of this milestone that was got wrong first.

### 2.4 A diagnostic says the line the person typed

The wrapper puts lines **above** the body, so a mistake on what the user sees as
line 1 is on line 4 of the text the passes are given. Every diagnostic carries
its own line (`errors::Span::line`), so the session subtracts and renders
afterwards — which needs `build_source()` not to have printed already, and that
is why it grew a `report` parameter.

**The count is counted and not assumed.** The first version subtracted a
constant three, which is right only while no top-level form has been kept: each
form adds its own lines between the include and the capsule, so the error would
drift by exactly as much as the user had declared, and **the drift would grow**
— the worst shape for a wrong number, because it looks right at first.

### 2.5 Ctrl-C is two mechanisms, side by side

DESIGN §10.2 says the key means two things and this is the milestone where both
exist at once. **While a line is being read** the terminal is raw, ISIG is off,
and Ctrl-C arrives as the byte `0x03` — no signal is raised at all, and the
prompt abandons the line. **While a line is running** the terminal is cooked
again and the SIGINT M11 built stops the walk at the next statement boundary.

**Raw mode is entered per line rather than per session**, which is what makes
that true: the `RawMode` object lives inside `read()`, so a satellite program
that asks for input (M14) finds the terminal in the state every other run of it
finds. The prompt does not leak its mode into the program it launches.

**And this is the only registrar of the emergency exit hook.** M6 built
`set_emergency_exit_hook()` and deliberately registered nothing, *"because until
there is a prompt nothing has put the terminal into raw mode"* — PLAN M22 says
so in as many words. `_exit()` runs no `atexit` handler by definition, so
without the hook a memory ceiling struck while the prompt was reading would
leave a terminal with no echo and no line editing, from the one code path whose
whole job is to fail safely.

### 2.6 The window narrowing, and where it departs from PLAN

PLAN §8 says the clean-exit arm in `on_child_exited` *"is marked as M1.5's and
this milestone removes it rather than discovering it."* **That sentence was
written before tabs existed.** `TERM.md` now has *"a tab closes when its
interpreter is finished with"*, and `Open…` runs a file in a tab — so removing
the arm would leave every finished program sitting in a tab the user has to
dismiss by hand.

**So the arm stays and the prompt opts out of it**: `hold_always ||
file.empty()`, and `child.cpp` already adds `--repl` in exactly the
`file.empty()` case. PLAN's own reason for closing — *"the child runs for
milliseconds and a window that outlived every one of them would only ever be a
window nobody asked to keep"* — is still exactly true of a file and is no longer
true of a prompt. **The letter was departed from and the argument was kept.**

`hold_forced` is new and is what keeps `--hold` alive: `terminal_run` recomputes
the policy when `Open…` starts a file in a tab that was a prompt a moment ago,
and with nowhere to keep the command-line flag that recomputation would quietly
drop it.

### 2.7 `help` is refused rather than recognised

The author asked for a bare `help` to answer *"did you mean
`satellite.help()`?"* rather than doing anything, and the same for `help()` and
`help(x)`. **That is DESIGN §1's generating rule held to.** A bare word belongs
to the user, so the prompt recognising one is a cost paid only where it buys
something — leaving a session is a thing a person must be able to do before they
know any of the language, which is why `exit` and `quit` are recognised; asking
for help is not, because there is a path for it and pointing at the path is
better than making the language own a second bare identifier. §7.7's `arguments`
is the first and should stay the only one.

**It fires only when nothing declares `help`.** A program that declares a name
called `help` means that name. The check runs before any lookup today because
there is nothing to look up in — the day the prompt keeps declarations, this has
to move behind them, and `prompt.cpp` says so where it is written.

### 2.8 The prompt writes the brace, and the body arrives indented

**The author's ask, and it is one sentence with two halves**: a head line should
not make somebody type a `{` the prompt already knows is coming, and the body
should not make them type tabs. So `satellite.capsule f()` and every
`satellite.statement.*` head now print their own `{` — **onto the screen and
into the entry**, because a brace that is in the program but not on the terminal
is a program the user cannot read back — and the body is prompted four spaces in,
which is what every file under `example/` is written in.

**The closing brace dedents live, and that is what changed `LineReader`'s
signature.** A `}` belongs to the block it ends rather than to the body inside
it, so its line sits where the head sat — but the user types it as the first
character of an already-indented line, and **the prompt was printed before that
character existed**. `read()` therefore takes a *function* of what has been typed
instead of a string, recomputed on every redraw, so the line moves left the
instant the brace appears. A fixed string cannot express it.

**A `{` typed on the line after the prompt wrote one is swallowed**, one line's
grace and no more. It is the user's habit meeting the prompt's help, and opening
a second block there would be silently wrong.

`owed_body` left the loop with this. The brace is written the moment the head is
accepted, so there is no longer a state in which one is owed.

### 2.9 What a line declares survives it

**The author asked twice — locals should persist, and running a file should
leave its variables behind to be used. They are one mechanism.**

**In, through the wrapper's parameter list.** A variable the session holds is
written into `satellite.capsule satellite.main(...)`'s signature and its value
handed to `Machine::call`. **Nothing is re-run to restore it**, and that is the
whole reason for choosing this over replaying the declarations: replaying
`satellite.variable.string s = satellite.console.input("name? ")` to get `s` back
would ask the question again on every line. A value travels as a value.

**Out, through the frame — and this is the milestone's one change to the
evaluator.** `Machine::unwind()` copies the **outermost** frame's slots before it
gives the storage back, and `last_frame()` hands them over. Six lines. Only the
outermost, so a program of a million frames copies nothing until the last of them
returns; and a copy rather than a promise not to resize, because the Machine
outlives the call and `--call` runs a second capsule through the same one.
`resolve::Frame` beside it says which name each slot is.

**So a file's variables survive it without rewriting the user's file**, which was
the alternative and would have been text surgery on somebody else's program.

**A redeclaration is still a redeclaration.** Once the session holds `n`,
`satellite.variable.number n = 9` is declaring a name that exists and says so;
`n = 9` is the assignment. That falls out of the parameter list rather than being
a rule anybody wrote, which is the argument for building it this way round.
§7.7's `arguments` is skipped, a slot whose type did not resolve is dropped
rather than guessed at, and **a line that refused keeps nothing** — its later
slots were never assigned.

### 2.10 `satellite.system.persist`, and the two numbers it took

**The author asked for it to be switchable and displayed**, and for the number to
be whatever was next free under `satellite.system`. That node's children run 1
through 6, so it is **7** — and **two rows rather than one**, because §1.3 says
the arity is the identity and *the same parent already carries the same pair*:
`threshold()` `1 22 5` and `threshold(n)` `1 22 6`. So `persist()` `1 22 7`
answers what the setting is and `persist(x)` `1 22 8` sets it.
WORD_NUMBERS §2.7 is the assignment.

**It is the first child of `satellite.system` that anything implements.** Thirty
numbered paths have sat under that node since the 2026-08-28 transcription and no
milestone reached one.

**Off does not throw away what is already held**, it stops the next line adding
to it — which is the reading that lets a program turn it off around one line and
back on afterwards.

**The banner says `satellite.bool.true` and not `true`, and that correction is
worth the space.** The author drew the line as `satellite.system.persist(true)`.
`true` is not a word in this language: DESIGN §6.1's module constants are
`satellite.bool.true` `1 17 2` and `satellite.bool.false` `1 17 1`, and a bare
`true` is a name the **user** owns — typing the short form answers S0511,
`nothing called `true` is in scope here`, which was measured. A banner that
showed it would have been teaching a command that does not run, in the one
week whose whole subject has been not making claims like that.

**And the memory line under it is deliberately blank**, at the author's
instruction: *"if it's not built yet just put a line there that says
`arguments.memory.available = ` and leave it blank for now, so that we remember
to put it there later."* Two things about it are for M20. The **number** exists
today — `system_facts::mem_available_bytes()` is built and M6 reads it — so what
is missing is the path, not the fact. And **DESIGN §7.7 spells free memory
`arguments.memory`**, with `arguments.memory.total` beside it; there is no
`.available` in that table. The line therefore reserves a spelling §7.7 has not
agreed to, and M20 has to settle which of the two names it is before a value
goes in.

## 3. What building it found

### 3.1 The brace is on its own line, and the prompt was running headers alone

**Found by driving it, not by reading it.** Typed at the prompt:

    satellite.statement.for (satellite.variable.number i = 0; i < 5; i = i + 1)
    {
        total = total + i
    }

and the answer was `nothing called `i` is in scope here`. The header line
**contains no brace at all** — this language writes `{` on its own line, and
every example in the tree does — so a prompt counting only braces read the
header as a finished entry and ran a `for` with no body. The failure then
arrived one line later, pointing at the loop variable, which is as far from the
cause as a diagnostic can land.

The fix is a flag and not a heuristic: `satellite.statement` has **exactly four
children** in `words.def` — `if` `1 13 1`, `for` `1 13 2`, `while` `1 13 3`,
`else` `1 13 4` — and every one takes a body, so the test is the segment rather
than a list of spellings that could fall behind. `capsule` and `spacesuit` join
it; `include` and `library` deliberately do not, or the prompt would sit waiting
for a block after `satellite.include(satellite)`.

### 3.2 Two clauses that passed against a mutant, which is the reason to mutate

`tests/prompt_test` was mutation-tested the way `MILESTONES/M17.md` §3.4 asks,
and it caught the suite twice before it caught the code.

**Version one** asserted that `0`, `1` and `2` were on the screen after a
three-round loop. Every one of those characters is in the loop header the user
had just typed, which the prompt echoes — so the clause passed against a build
with `opens_body` forced to `false`, while six other clauses went red.

**Version two** counted a literal `"TICK"` and needed four. It also passed,
and the reason is the prompt's own redraw: **a line is repainted on every
keystroke**, so the echo alone holds the word several times before the line is
even accepted. A test reading a raw pty stream is reading every intermediate
paint, not the screen.

**Version three** displays `i + 1000` and looks for `1001` and `1002`, which can
only have been printed *by* the loop — the source says `1000`. It fails under
the mutant. Three mutations were run in the end and all three are caught:
`opens_body` forced false (7 clauses), the line rebase removed (1 clause), and
Ctrl-C made to accept the line instead of abandoning it (2 clauses, one of them
through the pty).

### 3.3 One line, two statements, and the prompt could not tell them apart

**`satellite.library.counter = 5` DECLARES a global at the top of a file and
ASSIGNS to one inside a capsule, and both are legal** — measured, in a file, both
in one program. The block scanner routes on segment 1, so it sent every such line
to the top level, and the second mention of a name became a **redeclaration**:

    madness, ...: satellite.library.counter = 5
    madness, ...: satellite.library.counter = 9
    error S0291: counter was declared here

So a global made at the prompt could never be changed. **The scanner cannot fix
this** — the two spellings are identical and what separates them is *where the
line sits*, which is exactly what the scanner is being asked to decide. What can
fix it is the thing that remembers: `block.cpp` now reads the global's **name**
out of the line, and `session.cpp` keeps the ones it has declared, so **the first
mention declares and every later one assigns**. It is remembered only after the
line builds, or a rejected declaration would make the next mention an assignment
to something that does not exist.

**Its value still resets every line**, because the kept declaration is re-run
when the program is rebuilt — §6.1's consequence, not a separate defect. Within
one entry the assignment does exactly what it says.

### 3.4 The clause that proved nothing, again, for a third reason

The test written for §3.3 put the assignment **inside an `if` block**, so the
entry began with `satellite.statement` and the scanner never saw a library line
at all. It passed with the fix disabled. **That is three clauses in one milestone
that were green against a mutant** — §3.2's two and this one — and the shape is
the same every time: the clause exercised something *near* the change rather than
the change. What the fix decides is where a **bare** `satellite.library.<name>`
line goes, so only a bare line can test it.

### 3.5 LAYOUT's node count had been stale for three milestones

Assigning `persist` meant checking what the count became, and the count was
already wrong before it moved. `satl --words` answers **264 nodes, 9 aliases**;
`LAYOUT.md`'s row for `words.def` said **254**, which was last true at M7. M8
appended `digits`, M12 the variant's four, M16 two `search(pattern)` rows and
this milestone two more — **four milestones, none of which updated the one line
in the tree that states the number as a current fact.**

`PLAN.md`'s three mentions of 254 are **left alone**, and the difference is what
kind of sentence they are: they sit inside M2's own account (*"§2.2's 219 numbers
do not include the bare shape..."*, *"216 numbered rows + 38 bare shapes = 254"*)
and are measurements of that day, the same way this directory's startup tables
are. A dated measurement that still says what it measured is correct; a row
describing a file as it is now is not, and only the second kind was changed.

**What would have caught it is what caught the row counts here** —
`tests/words_test` checks §2.2's 229 rows and 226 numbers against the file and
went red the moment two more arrived, which is how the counts in `words.def`'s
own header and in three test comments got corrected. Nothing checks LAYOUT.

### 3.6 `make console_test` has never worked

Noticed only because `prompt_test` was added beside it and the two were
compared: `console_test` is in `TESTNAMES` and in the run list, but has no alias
rule and is not in `TESTALIASES` — so `make console_test`, which is what fingers
type, fails. **Left for the author**: it is one line and it belongs to whoever
owns that suite. Recorded here rather than fixed, because a milestone quietly
tidying another's build file is how a change gets attributed to the wrong work.

### 3.7 `not_yet()` lost its last caller here

`programs/main.cpp`'s `not_yet()` had one caller — `--repl` — and this milestone
took it. The function now has none, which `-Wall` says out loud. **It is marked
`[[maybe_unused]]` rather than deleted**: its own comment is an argument for
keeping it (*"the next arm to arrive with a file behind it will want it"*, and
M24's windows and M25's second file are both such arms), and the
counter-argument is this tree's rule about code nothing reaches —
`satellite_console/console.cpp` removed a guard *"against an impossible state"*
for exactly that reason. **Deleting an argument somebody wrote down is not a
warning fix**, so it is §6's and not this milestone's.

## 5. Startup

`make startup`, 2026-09-07, load 0.42, both sides `STATIC=full` so the ms column
is comparable as well as the share:

    command                                           ms   share     was   delta
    ---------------------------------------------------------------------------
    int main(){return 0;}                          0.547      --      --      --
    satl                                           0.866   0.319   0.338  -0.019
    satl --version                                 0.869   0.322   0.340  -0.018
    satl --words                                   1.020   0.473   0.481  -0.008
    satl --tokens example/class_test.satl          1.269   0.722   0.698  +0.024
    satl --limits                                  1.587   1.040   1.026  +0.014
    satl --resolve example/hello_world.satl        1.000   0.453   0.429  +0.024
    satl --call example/frames.satl factorial 10   1.217   0.670   0.655  +0.015
    satl example/scalars.satl                      1.475   0.928   0.900  +0.028
    satl example/hello_world.satl                  1.155   0.608   0.589  +0.019

**Nothing regressed**, and the reason is worth stating rather than being pleased
about: **nine objects joined the binary and none of them is on the startup
path.** Nothing under `satellite_prompt/` runs until `--repl` is the first
argument — no constructor, no table, no thread — so the cost of the prompt to a
program that does not use it is the linker's, and the linker's cost is in the
binary's size (3.84 MB to 3.87 MB) rather than in its clock. `satl` and
`satl --version`, the two rows that do nothing but say what they are, both came
out **faster** than the M17 baseline.

**The stored rows were left as they are.** Every delta is between -0.019 and
+0.028 ms on figures around 1 ms, which is inside what two afternoons at
different load produce; re-baselining on that would replace a good comparison
point with a noisier one and buy nothing. The claim this milestone is answerable
for is *nothing regressed*, and the M17 baseline is what supports it.

**`--repl` is not a row and cannot be one.** Every command in this table exits
on its own; the prompt waits for a person. Timing it would need a script that
types `exit`, which measures the harness rather than the startup.

## 6. What is left open

1. ***CLOSED THE SAME DAY — §2.9 IS WHAT REPLACED IT.*** This entry said there
   was no session state, that `satellite.variable.number n = 6` ran and `n` was
   gone by the next prompt, and that it was the first thing a user would hit. The
   author read it and asked for it to be fixed, so it was. **The paragraph is
   kept rather than deleted** because it is what the milestone shipped for the
   length of an afternoon, and a note that quietly rewrites what was true is a
   note nobody can date.
   **A capsule IS kept** (§2.1), which covers most of what a prompt is for, but
   the first thing many people type is a variable. Making declarations persist
   is not one change but three decisions nothing has taken: what re-declaring a
   name means, what happens to a line that fails after declaring, and how a
   session frame relates to DESIGN §7.2's `satellite.library`. **Named here
   rather than filed**, because it is the first thing a user will hit.
2. ***ALSO CLOSED THE SAME DAY.*** This said the store M18 needs was not built
   and that building it here would be the no-consumer mistake in the other
   direction. **§2.9 built it without meaning to**: making a line's variables
   survive it IS the store, and `Session::kept()` is the reader's door — name,
   type as the node its declaration ends at, and value, for a typed line's
   locals and a run file's alike. The no-consumer worry does not apply to what
   actually happened, because the thing that keeps the variables is also the
   thing that uses them: the next line does. PLAN §8's M18 entry now says so.
3. **History is in memory only.** It lasts a session and no longer. A file needs
   a path in the user's home, and `~/.satl` is the INSTALL directory, so user
   data does not belong in it — inventing a second dotfile is a decision for the
   author rather than a detail of this milestone.
4. **`run <file>` takes no arguments after the file.** `satl <file> [args]`
   does, and drops them with a line on stderr (M17 §6.3) until M20. The prompt's
   `run` should grow the same shape when `arguments` does.
5. **`not_yet()` has no caller.** §3.7 — keep or delete, the author's call.
6. **`make console_test` has no alias.** §3.6.
7. **`satl -i <file>` is not built, and it is the one thing the author asked for
   that this milestone did not reach.** The ask was that reaching
   `satellite.return(satellite)` should leave you at a prompt with the program's
   variables — and **the hard half of that is done**: `run <file>` at the prompt
   already keeps them (§2.9), so what is missing is the command-line arm and
   `satl-term` passing it. **It must not be the default for `satl <file>`**, and
   that is measured rather than cautious: 17 rows of `make_support/startup.rows`
   and both pty harnesses run `satl` to completion, and every one of them would
   hang forever. The author settled it — *"it is only the default if the user is
   using the terminal"* — which is the same split `python -i` makes and puts the
   decision in `satl-term`, the one binary that knows there is a person there.

8. **The prompt has no completion and no `:` commands.** v1's REPL had `:vars`
   and `:history`; the M11 prototype had `:cancel`. None is here, and whether
   the prompt should have a command language of its own at all is undecided —
   it is the same "a bare word is the user's" question §2.7 answers for `help`.
