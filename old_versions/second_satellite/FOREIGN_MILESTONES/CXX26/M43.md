# CXX26/M43 — composing concurrent work

**C++26 papers:** P2300 (`std::execution`, senders/receivers), P2530 (hazard
pointers), P2545 (RCU). In the working draft; not in a published standard at the
time of writing.

**Answer: satellite milestone M43 — and it must not be started before
[M40](../SATELLITE/M40-locks-and-atomics.md).**

## What C++ is doing

```cpp
auto work = just(42) | then([](int x){ return x * 2; }) | on(pool.scheduler());
auto [result] = sync_wait(work).value();
```

A grammar for describing concurrent work before running it, so the scheduler
decides where and when.

## What satellite has

`satellite.thread.new(f(x))`, `.start()`, `.join()`. Raw threads and nothing
above them. A program that wants 23 workers writes the split, the shards, the
start loop and the join loop by hand — `infinity_data_main.satl` does exactly
that, four loops and about sixty lines, and every threaded program will rewrite
them.

**There is also a pool already** (`machine_limits/pool.cpp`, "24 threads, 11
parked just now and still warming") which programs cannot reach. So the
scheduler half of P2300 exists and has no door.

## Why M40 comes first

**Composition makes sharing easier, and sharing is the unguarded part.** Senders
hand values between threads by design; satellite's containers are copy-on-write
and safe, but a spacesuit's fields are not, and nothing checks. Shipping a
pleasant way to pass work between threads on top of that would multiply the one
real hazard rather than help with it.

M40 decides whether a shared spacesuit is locked, refused, or the programmer's
problem. That answer changes what a sender is allowed to carry, so it has to
come first.

## What it must not break

DESIGN §7.2's frame-per-call, and the measurement behind it —
`example/threads.satl` §3: eight threads, 200 activations each, 1600 results,
1600 right. Any scheduling that reuses a frame across tasks puts that at risk,
and it is the property that made threads correct on the first try.
