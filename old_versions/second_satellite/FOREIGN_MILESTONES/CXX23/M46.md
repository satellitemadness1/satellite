# CXX23/M46 — `std::mutex`, `std::lock_guard`

**Standard:** C++23 §32.6 (mutual exclusion), §32.6.5 (`lock_guard`).
**Answer: [M40](../SATELLITE/) — and this is the most serious gap in the folder.**

## C++

```cpp
std::mutex m;
{ std::lock_guard<std::mutex> held(m); shared.push_back(x); }
```

## satellite

**There is no lock.** Verified 2026-09-12: no `mutex`, no `atomic` and no
`lock_guard` anywhere under `src/satellite_containers/`, and none in the
refcounting.

## Why this is worse than a missing feature

**Satellite already ships threads.** M23 built `satellite.thread.new`,
`start()` and `join()`, and `example/threads.satl` proves eight threads get 1600
correct results. So a reader has every reason to believe sharing is safe, and
nothing tells them otherwise:

- two threads appending to one `list` is a **corrupted list, not a slow one**
- two threads touching one spacesuit's refcount race on a non-atomic counter
- `satellite.library.n = satellite.library.n + 1` is read-add-write, which
  `example/threads.satl` §4 says out loud is not atomic — and that file asserts
  only that every thread saw the same variable, deliberately not the total

**The language's own honesty is doing the work a type system should.** The M23
notes are explicit that this is "a data race in the PROGRAM and not in the
language", which is a defensible position — but it is stated in a milestone
document, not at the point where somebody writes the bug.

## What a program does today instead

**One container per thread, shared by nothing.** `infinity_data_main.satl` gives
each of its 23 workers its own `earth_shard`, and the threads share exactly one
object — an `infinity_data` they only ever read. That is the discipline the
language cannot currently enforce, applied by hand and commented at the site.

## What M40 should bring

Least: `satellite.variable.mutex` with `lock()`/`unlock()` and a scope form.
Better, and more satellite: **make the containers refuse**. A list that knows it
is reachable from two threads and stops, rather than corrupting, matches
DESIGN §9.1's "report and answer false" far better than a lock the programmer
must remember to take.
