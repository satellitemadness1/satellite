satellite.statement.else -- the other branch of an if

  satellite.statement.if (n > 5) { satellite.console.display("big") }
  satellite.statement.else       { satellite.console.display("small") }

  The else block runs exactly when the if's condition was false. There
  is no truthiness in reach of that sentence: the condition must BE a
  bool, and satellite.statement.if (n) on a number is refused at run
  time with

      condition must be a satellite.variable.bool, got
      satellite.variable.number

  before either branch runs.

  TWO SPELLINGS are accepted and they are the same statement:

      satellite.statement.else        bare
      satellite.statement.else()      an empty pair of parentheses

  The parens carry nothing and the parser drops them. They are accepted
  because every other statement form is written with them, so reaching
  for them here is a mistake made once per program, not once per career.

  ONLY AN EMPTY PAIR. satellite.statement.else(n > 1) is REFUSED with

      expected '{' to open a block

  and the caret on the '('. That is not a spelling the parser lacks. An
  else has no condition to take -- it IS the case where the if's
  condition was false, and a second condition is a second if. Write the
  chain instead.

  A BRACE BLOCK, NEVER ONE STATEMENT. There is no one-statement else to
  borrow from C, so

      satellite.statement.else satellite.console.display("small")

  gets that same "expected '{' to open a block", with the caret on the
  word where the block should have started. An if is the one thing that
  may stand where the block goes; an else followed by a while or a for
  is refused the same way.

  THE CHAIN is an else whose branch is another if, spelled out in full:

      satellite.statement.if (n < 0) { ... }
      satellite.statement.else satellite.statement.if (n == 0) { ... }
      satellite.statement.else { ... }

  The if after the else needs its whole path. satellite.statement.else
  if (n == 0) is an else followed by a bare word and gets that same
  "expected '{' to open a block". The if may sit on the line after the
  else, and satellite.statement.else() satellite.statement.if (...) is
  accepted too. A chain runs to any number of arms; the last else is
  optional, and a chain that ends without one runs nothing when no arm
  matches.

  THERE IS NO elif, and reaching for one is not a parse error, which is
  what makes it worth naming here. satellite.statement.elif (n == 0)
  ends the if without an else and is left to fail on its own at run
  time, with the one message on this page that is not the others:

      no such module function: satellite.statement.elif

  NO DANGLING ELSE, and no rule needed to break one. Every branch is a
  brace block -- there is no one-statement form for an else to be
  swallowed by -- so an else always follows a '}', and that '}' says
  which if it belongs to:

      satellite.statement.if (a == 1)
      {
          satellite.statement.if (b == 1) { }
          satellite.statement.else { }   // the INNER if's
      }

  Move that else below the outer '}' and it is the outer if's, with no
  second reading available. Run at a = 1 and b = 0, the shape above
  takes its else and the moved-down shape takes nothing.

  Blank lines and // comments may sit between the '}' and the else
  without detaching it. A statement in between does detach it, and what
  is left over is the next case.

  AN ELSE THAT MATCHES NOTHING is not a parse error. It falls through to
  an expression statement and fails where it stands, at run time:

      satellite.statement.else is a module path, not a value

  which is also what a second else on one if gets, and an else written
  after a while or a for. No statement but if takes one. AT RUN TIME is
  the whole of it: an orphan else inside a capsule nothing calls is
  never reached, so the program prints nothing about it and exits 0.

  satellite.help(if)  the condition, the block, the whole picture.
  A topic answers bare or quoted. The dotted language path is not a
  value, so satellite.help(satellite.statement.else) is refused with
  "is a module path, not a value" rather than answered.
