# Session state — 2026-08-23/24

Written so this survives a `/clear`. Everything below is in the working tree,
built clean with clang 24 at `-O2`, and **none of it has been through the test

## What landed

**`make` installs what it built** (Makefile)
- `make` at the project root builds, then runs the existing `install` target at
  the prefix that build used. Icons are recopied from `dist/icons` every run.
- Default prefix now follows who runs make: `/usr/local` as root, `$HOME/.local`
  otherwise — the rule `install.sh` already used. One prefix per invocation: a
  sub-make at a *different* prefix flip-flops `.libdir-stamp` and never reaches a
  fixed point (measured).
- Fires only when: CURDIR is the Makefile's own directory, `DESTDIR` is empty,
  `MAKELEVEL` is 0, `SATELLITE_AUTOINSTALL` is not 0, **and** `prefix` was not
  named on the command line. That last guard auto-protects every packager,
  including rpm/Nix/PKGBUILD which no edit in this tree can reach.
- Never runs sudo. Unwritable prefix → prints the refusal and exits 0. Nothing in
  the path can fail the build.
- `debian/rules` (MAKEVARS) and `install.sh` (both build invocations) pass
  `SATELLITE_AUTOINSTALL=0` explicitly. Without those two, `dpkg-buildpackage`
  installs into the build machine's live `/usr` and `sudo ./install.sh` dies
  before its own install runs.
- `install:` is now GUI-tolerant (`$(GUI_TARGET)`, `[ -f satl-term ]` guards) so
  `make` still works on a machine without gtk.
- `install-report` prints where things went, checks PATH **precedence** (not
  membership) with `command -v` + `-ef`, and warns when a later-precedence icon
  directory holds different artwork.

**GTK icon precedence — verified, and it constrains the above.** GTK4 4.16.7
resolves an icon to the **last** base directory in its search path that has it,
not the first (`[A,B]→B`, `[B,A]→A`, reproduced twice independently). So the
root-owned `/usr/local/share/icons` outranks `~/.local/share/icons`. `make`
cannot fix that without sudo; it reports it instead. To make the user install the
only one: `sudo ./install.sh --uninstall --prefix /usr/local`.

**Build flags**
- `OPT ?= -O2`, and `CXXFLAGS = -std=c++20 -Wall -Wextra $(OPT)`. `make OPT=-O3`
  works; `make CXXFLAGS=-O3` was the trap (replaces the variable whole, drops
  `-std=c++20`, dies on `atomic<shared_ptr>` being C++20).
- `.cxxflags-stamp` mirrors `.libdir-stamp`: `$(OBJS)` depend on it, so changing
  `OPT` **or `CXX`** rebuilds. Verified 0 / 43 / 0 compiles.
- `LLVM_BIN` now `$(HOME)/opt/clang-24/bin`. It was `$(HOME)/.local/llvm/bin`,
  which does not exist — so every build for some time silently used GCC 17 via
  the `c++` fallback. **DESIGN/README attribute their benchmark tables to clang;
  those numbers were most likely GCC's.** Remeasuring is outstanding.
- `-march=native` deliberately NOT added: `debian/rules` drives this Makefile and
  the package must run on machines that are not this one.

**`make clean`** also removes `example/website/gtk_window`, `pcg_test/pcg_test`,
`speed_test/cxx_speed`, and now recurses into `example/website` (which had a
clean target the root never called). It does **not** uninstall; `make uninstall`
does, and now follows the same prefix rule.

**Language additions** (all in `src/evaluator/`)
- `satellite.directory.list([dir])` — sorted, dotfiles in, `.`/`..` out, names
  only (so `satellite.file.open(l[i])` still works). Sorted in satellite's own
  string order (lowercase, uppercase, digits, punctuation) so `l[i] < l[i+1]`
  holds in-language. Failure is **loud** with three distinct messages, because an
  empty list is already the true answer for an empty directory.
- `.lines()` on a list, and it is what the REPL echoes a list with. Columns:
  `name | type | permissions | size | lines | date`. Every cell that does not
  apply says `- -`. Type: dir/exe/compressed/ascii/text/binary/special, from a
  ~130-entry text-suffix table and 34 archive suffixes, plus byte sniffing.
  `root_only` replaces the bits when a file is root-owned with nothing for group
  or other. An unreadable file reports type and lines as `- -` (it used to claim
  "ascii, 0 lines", which was a silent lie). Date is `statx` **birth** time,
  falling back to mtime where the filesystem never recorded one.
- `exit()`, `quit()`, `satellite.return`, `satellite.return(satellite)` all end a
  REPL session; `satellite.return(3)` exits with status 3.
- `satellite.directory()` (and `.console()`, `.time()`, `.file()`, `.system()`,
  `.random()`) print that module's commands. **Parenthesised form only** — making
  bare `satellite.directory` a value broke `satellite.directory.list()`, which the
  evaluator then read as a string with `.list()` called on it.
- `satellite.analyze(path)` — `src/evaluator/analyze.cpp`. Lexes the file rather
  than scanning text, so `satellite.spacesuit` in a comment or a string does not
  count (grep says 2, analyze says 0). Reports include/main/return, spacesuits,
  statements, variables (container = 2).
- `satellite.system.home()`.
- `satellite.system.memory.{used,free,total,swap,main}([unit])`,
  `.swap.used()`, `.frequency()`, `.bit()`,
  `.this.{used,free,available}([unit])`. Units are strings `"b" "kb" "mb" "gb"
  "tb"`, default mb — a bare `tb` would be a name the user owns (§1). Every
  conversion is exact because 1024 is a power of two.
  - `.main()` is this process's resident set, read fresh from `/proc/self/statm`.
  - `.this.*` is the running **thread's stack** (`pthread_getattr_np`), because
    Linux accounts an address space per process — heap-per-thread would be the
    same number for every thread.
  - `.frequency()` and `.bit()` read SMBIOS type 17, which is `0400 root`, so
    they answer **0** for anyone but root. **That code path is untested** — it is
    written to the spec offsets (total width 0x08, data width 0x0A, speed 0x15).
    `.bit()` returns TOTAL width (72 with ECC, 64 without).

**Registry** (`format.def`): words 87 analyze, 88 system, 89 home, 90 memory,
91 used, 92 free, 93 total, 94 swap, 95 frequency, 96 bit, 97 this,
98 available. `main` reuses word 4 — the space is flat. Paths added for analyze,
system.home and the five memory quantities (variadic, for the optional unit).
`format_test.cpp` tripwires updated: registry ends at 98, 99 unassigned, 27
paths, 7 variadic.

1. **The test suite has never been run against any of this.** `.lines()` becoming
   the default list echo *will* have broken `eval_test`'s `[1, 2, 3]`-style
   expectations. `format_test`'s counters were updated by hand and only
   syntax-checked.
2. **15 commits are unpushed**, including the whole of satellite.random, maps,
   spaceships/includes, the format registry, and the pcg-cpp vendoring. That is
   why pcg-cpp "is not on the GitHub page" — `origin/main` is ten commits behind.
   Remote: `git@github.com:satellitemadness1/satellite.git`.
3. **DESIGN.md has no entry for any of this.** Guidance gathered: the make change
   belongs as a `###` subsection inside §9 (after "Finding the installed library",
   ~line 1128), not a new `## N.`; `satellite.directory`/`.analyze`/`.system`
   would be a new `## 19.` covering the module rather than a `.list` footnote.
   Also `DESIGN.md:16` "Last updated" needs the date, and §17's "One path in the
   table has more than one shape" is now false (there are seven).
4. **Licensing.** `pcg-cpp-0.98` is Apache-2.0 and is compiled into `satl`
   (header-only, via `random.o`). The top-level `LICENSE` says MIT only, and that
   is what `make install` ships as the copyright file — so the tarball route
   understates the terms. `debian/copyright:11-14` already records this as a known
   gap. Either add a third-party section to `LICENSE`, or install
   `pcg-cpp-0.98/LICENSE.txt` into `share/doc/satellite/`.
5. **Five-segment paths.** `satellite.system.memory.swap.used()` and
   `.memory.this.*()` are five segments; `SAT_PATH` holds four. They work in the
   tree walker (which reads a path, not the table) but §17 cannot encode them.
   Either the unit grows a fifth word, or they become `swap_used()` etc.
6. `-O2` vs `-O3` never measured. `make compare` / `make python` exist for it, and
   the tables need remeasuring anyway because of the GCC/clang mix-up.
7. `.lines()` decorates only names that resolve from the current directory, so
   `satellite.directory.list("/etc")` echoes a table of `- -`. Fixing it properly
   means the listing carrying its directory — a new value type, not a plain list
   of strings. Decide before the ncurses column work.
8. `used("tb")` prints the exact `0.0066326670348644256591796875`. There is no
   rounding-to-decimals in the language (`.round()` goes to a whole number). A
   `.round(places)` would give the short `0.030 tb` form.

## The download bundle (added after the first draft of this file)

`make` at the project root now also writes **`enterprise_download/`** — `satl`,
`satl-term`, `install.sh` — and **`satellite_rhel.tar.xz`** beside it (outside the
folder, so unpacking recreates the directory rather than scattering three files).
Both are gitignored and both are removed by `make clean`. The tar is built with
`--sort=name --owner=root:0 --group=root:0 --mtime=@0` so two builds of the same
binaries produce a byte-identical archive and a published checksum means
something.

`satl.tar.xz` in the project root is NOT this — it is an old ad-hoc archive
holding a single file, the `satl` binary. Untracked. Probably delete it.

**Two things about that bundle are not finished:**

1. **`install.sh` in the bundle does not work.** It requires a Makefile beside it
   (`install.sh:207`) and drives `make install`, so from the download folder it
   exits with "no Makefile beside ./install.sh". A user who downloads, unpacks and
   runs it installs nothing. Fix is either a bundle mode in install.sh (copy a
   staged tree directly, no make) or shipping the data tree — the icons, mime
   packet, .desktop, man pages, examples, LICENSE — alongside the binaries. Right
   now the folder contains only the three files that were asked for.
2. The bundle is EL-only by construction: an AlmaLinux 10 build links EL 10's
   libstdc++. A Debian bundle has to be built on Debian.

**Regression found and fixed while adding it:** defining `bundle:` above `all:`
made bundle the DEFAULT GOAL, so plain `make` built the bundle and silently
skipped the install — fresh binaries, no install, exit 0, no error. The rule now
sits below `all`, and `.DEFAULT_GOAL := all` is set so it cannot recur.

## In flight

**Reimplementing pcg32_k16384 in-tree**, to drop the vendored Apache-2.0 code and
make `LICENSE` accurate as plain MIT. Legally fine: copyright covers pcg-cpp's
expression, not the PCG algorithm; the rule is write it from the algorithm, do
not transliterate their header.

The hard part is NOT plain pcg32 (a 64-bit LCG plus the XSH-RR output function,
~15 lines). It is the **extension**: `pcg32_k16384` is
`pcg_engines::ext_setseq_xsh_rr_64_32<14,16,true>` — a 16384-word extension table
with its own advance rule, seeded across every word from kernel entropy. Getting
it subtly wrong invalidates §18's tier claims. Note DESIGN.md:3190 already records
that pcg-cpp's own `discard()` is **wrong** for extended generators.

Plan: derive a bit-level spec from the algorithm (reading the vendored header for
understanding only, never copying it), implement independently, then validate
**bit-exactly against the vendored reference for identical seeds** — the reference
is in the tree, so this test is available and is the strongest one there is.
**The derived spec is saved in `plans/pcg_k16384_spec.md`** — algorithm at bit
level, seeding chain, and the drop-in surface. Two findings from it that change
the story:

- **"seeded from kernel entropy" is false as built.** `std::random_device` on
  libstdc++/x86 uses the RDRAND instruction, not the kernel pool. DESIGN §18 says
  kernel entropy; the code does not do that. The recommended replacement is
  `getrandom(2)` in a loop (256-byte rule), `/dev/urandom` only on ENOSYS, never
  `std::random_device` — which would make §18's sentence true for the first time.
- **The seeding path can throw and nothing under `src/` catches it.**

The seed draw is 16392 words / 65568 bytes. Cost is paid per satellite.random
call, and getrandom is measured 12.4x cheaper than what it replaces.

Still outstanding: the bit-exactness test. The fourth subagent was implementing
the spec and diffing 10000 outputs against the real pcg32_k16384 when the session
ended. Re-run that before trusting the algorithm section.
