# CXX23/M9 — references, pointers, `new`, `delete`

**Standard:** C++23 §9.3.4.3 (references), §7.6.2.8 (`new`), §7.6.2.9 (`delete`).
**Answer: satellite says it — by not having the question.**

## C++

```cpp
Thing *p = new Thing();
Thing &r = *p;
p->method();
delete p;
```

## satellite

```
thing t          // constructs it
t.call_method()  // and `t` is already a reference
```

## Why there is nothing to translate

**A spacesuit IS a reference** — DESIGN §7.4, and the §12 "Decided" list. Passing
one to a capsule passes the handle, not a copy, so there is no address-of
operator, no pointer type, and `satellite.pointer<T>` is not a path. A program
that wants to hand out a reference to itself is told its own handle from
outside, because there is no `this` either.

**Nothing is freed by hand.** Refcounting releases a spacesuit when the last
handle goes. DESIGN §12 accepts the cost openly: a cycle is never freed, and
`infinity_data_main.satl` has one on purpose — the store holds its own handle so
`pointer()` can answer, and that object leaks for the life of a run that was
never going to release it anyway.

## The one thing a C++ reader must unlearn

**Containers do NOT follow this rule.** A `satellite.container.list` passed to a
capsule is **copied**; a spacesuit is not. Measured 2026-09-12: a capsule that
appends five items to a list parameter leaves the caller's list holding zero,
with no diagnostic. To have a capsule or a thread fill a container, wrap it in a
spacesuit and write through a `call_` verb — which is what `earth_shard` in
`infinity_data_main.satl` exists to do.
