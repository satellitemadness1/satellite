# CXX26/M42 — contracts

**C++26 paper:** P2900 (`pre`, `post`, `contract_assert`). Voted into the
working draft; not in a published standard at the time of writing.

**Answer: satellite milestone M42 — and it is more natural here than in C++.**

## What C++ is doing

```cpp
int divide(int a, int b)
    pre (b != 0)
    post (r: r * b == a)
{ return a / b; }
```

## Why satellite wants this more than C++ does

**Satellite is a language built on refusing well.** ERROR_HANDLING.md §3 states
the rule the whole error system is held to:

> A REFUSAL MUST NAME WHAT WOULD HAVE MADE IT NOT HAPPEN.

The interpreter obeys it. **A program cannot.** A capsule that requires a
positive count has no way to say so — it either checks by hand and displays
something, or does the wrong thing quietly:

```
satellite.capsule populate_world_shard(world_shard shard, ..., satellite.variable.number count, ...)
{
    // `count` must not be negative. There is nowhere to write that but here,
    // in a comment, where nothing enforces it and no refusal will quote it.
}
```

That comment is from real code. **The requirement is written down in the one
place the language cannot read.**

## What M42 should bring

```
satellite.capsule divide(satellite.variable.number a, satellite.variable.number b)
    satellite.requires(b != 0)
    satellite.returns(satellite.variable.number)
{ ... }
```

and on failure, a refusal that quotes the condition:

```
satl: error S0735: `divide` requires `b != 0`, and b was 0
      the requirement is declared at divide.satl:4
```

**That message satisfies §3 by construction** — it names what would have made it
not happen, because the author wrote that sentence themselves.

## Why this is small here

The machinery exists. `m.refuse()` takes a diagnostic; a contract is a condition
evaluated at entry and a refusal carrying its source text. No new types, no new
numbering beyond one path and one error code.

**What C++ spent years arguing about does not apply.** Most of P2900's
difficulty is *what happens when a contract fails* — terminate, throw, ignore,
or a build-mode matrix. Satellite has one answer already and it is the right
one: **the run stops and says why.** There is no exception to leak, no mode to
choose, and no undefined behaviour to fall into.

## What it must not break

The rule that a refusal is not catchable ([M33](../SATELLITE/M33-catching-a-refusal.md)).
If contracts ship before M33 they are simply "stop and say why", which is
correct. If M33 ships first, a contract failure must decide whether it is
catchable — and the honest answer is **no**: a broken precondition is a bug in
the caller, not a condition to recover from.
