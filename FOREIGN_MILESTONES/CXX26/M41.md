# CXX26/M41 — reflection

**C++26 paper:** P2996 (`^^` the reflection operator, splicing, `std::meta`).
Voted into the working draft; not in a published standard at the time of writing.

**Answer: satellite milestone M41 — and satellite is better placed for this than
C++ is.**

## What C++ is doing

```cpp
constexpr auto r = ^^MyClass;
for (constexpr auto m : std::meta::nonstatic_data_members_of(r))
    std::print("{}\n", std::meta::identifier_of(m));
```

Forty years of C++ resisted this. The feature is large because the language has
no registry of its own contents — reflection has to be *invented* on top of the
type system.

## Why satellite is the opposite case

**Satellite already has the registry. It just cannot be read from inside a
program.**

Every path in the language is a number — DESIGN §4's generating rule — and the
interpreter walks that numbering constantly:

- `satl --words satellite.system.memory` lists a node's children and their numbers
- `satl --resolve <file>` prints every name, its type and its slot
- `satl --arms` prints which handler groups each entry point installed

**All three of those are reflection.** They are performed by the tooling, over
data that exists at run time, and a satellite program can reach none of it.

## What M41 should bring

A `satellite.words` path — the registry, as a value:

```
satellite.container.list<satellite.variable.string> kids = satellite.words.children("satellite.system.memory")
satellite.variable.number n = satellite.words.number("satellite.thread.new")
satellite.variable.bool  here = satellite.words.installed("satellite.thread.new")
```

**`installed()` is the one with a bug behind it.** On 2026-09-12
`satellite.thread.new` was built, numbered, and missing from the prompt's
handler table, and the refusal blamed a milestone that had already landed
(ERROR_HANDLING.md §1). A program that could ask *"is this actually installed
here?"* could have answered that in one line — and `--arms` was written to
answer it from outside because nothing could answer it from within.

## What it would cost

Less than any other milestone in this folder. The data is `constexpr` in
`words.def`, the walk exists in `satellite_words/`, and `--words` already
renders it. What is missing is handlers exposing it as values.

**The scope decision is whether reflection covers the PROGRAM as well as the
LANGUAGE** — can a capsule list a spacesuit's fields, or only the language's
built-in paths? The second is nearly free. The first needs the resolver's
per-program names to outlive resolution, and `words_runtime.hpp` warns in
capitals that a user's `PathId` is valid inside one run only.

Ship the language half first. It is the half that would have caught the bug.

## What it must not break

The numbering's frozen registration order (DESIGN §4.3). Reflection makes the
numbers *visible to programs*, which turns "the order is frozen" from an
implementation promise into an observable one — so it must ship with the
numbering already stable, not before.
