NOTES

[1] SELF-CONTAINED, AND WHY include/ IS HERE.
    A satellite.cxx block is compiled at RUN time, so the headers and the core
    .so have to exist then -- not just when satellite was built. Earlier builds
    baked absolute paths to the repository's source and build trees into
    libsatellite_core.so, which meant this folder only worked while the rest of
    the repository sat where it was. These binaries were configured with
    SATELLITE_RUNTIME_INCLUDE_DIR and SATELLITE_RUNTIME_CORE_LIB pointing inside
    this folder, and linked with RPATH=$ORIGIN.

    Verified by hiding the repository's build/ and include/ directories and
    running the bundle: check and run both still work, compiling cold.

    THE ONE CATCH: those two paths are absolute, so they point at
    .ship/001 AT ITS CURRENT LOCATION. Moving bin/ alone is fine ($ORIGIN
    handles the library), but moving the whole 001 folder elsewhere breaks
    satellite.cxx until the binaries are rebuilt with the new paths. Version
    001 has no way to relocate them without a rebuild.

[2] REQUIREMENTS.
    Linux x86-64. g++ must be on PATH at run time for satellite.cxx -- the
    bridge shells out to literally `g++ -O2 -std=c++20 -shared -fPIC`, and 001
    exposes no flag or environment variable to choose a different compiler.
    A writable home directory for the block cache at ~/.satellite/cache
    (falls back to $TMPDIR then /tmp; safe to delete, blocks recompile).

    No LD_LIBRARY_PATH is needed. The binaries were built with GCC 17.0.0
    (experimental) but require only GLIBCXX_3.4.31, which the system
    libstdc++ (14.3.1) provides -- confirmed by running with LD_LIBRARY_PATH
    unset and PATH reduced to /usr/bin:/bin.

[3] THESE BINARIES ARE A SNAPSHOT OF UNCOMMITTED WORK.
    They were built from the working tree as of 2026-08-03, which is AHEAD of
    the last commit (d8e34fa) and contains uncommitted changes to
    container.hpp, types.hpp and container.cpp, plus two untracked new files,
    capsule.hpp and capsule.cpp, that are compiled into this .so.

    capsule.cpp compiles and links, but its test (tests/test_capsule.cpp) has
    not been written yet -- the repository's own CMakeLists.txt refers to that
    file, so THE REPOSITORY DOES NOT CURRENTLY CONFIGURE. These binaries were
    produced from a frozen copy of the tree with that one dangling test target
    removed. Nothing in the CLI reaches the capsule code yet, so its being
    untested does not affect anything verify.sh exercises -- but it is in the
    .so, and it has not been tested.

    The headers in include/ are byte-identical to the ones this .so was
    compiled from, so there is no header/binary mismatch.

[4] NOT EXERCISED BY verify.sh.
    satellite.machine (synthetic keyboard via /dev/uinput) needs permission on
    that device, which is root-only by default, so verify.sh does not touch it.
    It is compiled into the .so and covered by the repository's test_machine,
    which runs in recording mode.
    satellite-gui (the GTK4 console) is NOT shipped in this folder.

[5] WHAT 001 STILL CANNOT DO.
    There is no parser and no virtual machine. A .satl file cannot be executed.
    `satellite run` executes the satellite.cxx blocks in a file and nothing
    else: satellite.console.display produces tokens and no output,
    satellite.capsule defines nothing, satellite.include loads nothing. That is
    the whole of it, and README.md says so first rather than last.
